## R-3 — 三个点呼上报弹窗无防连点（重复上报）

**问题（已核实）**：`Features/Home/HomeStubs.swift` 三个 Sheet 的 `submit()` 提交时无「提交中禁用」守卫，慢网下连点会重复 POST、产生重复申请：
- `HealthSheet.submit()` @2131（体調報告，POST `/rollcall/reports` kind=health）
- `AbsenceSheet.submit()` @2221（欠席申請，kind=absence）
- `OtherSheet.submit()` @2301（その他，kind=other）

三处都是 `PrimaryButton(enabled: !xxx.isEmpty){ submit() }` → `submit()` 里直接开 `Task` 调 `RollCallReportsAPI.create`，全程无 in-flight 状态。

**现成正确范本（同文件）**：`RenewStudentNoSheet` @2349 已做对——`@State private var submitting = false` + `canSubmit` 含 `!submitting` + 按钮 title `submitting ? "送信中…" : "更新する"` + `submit()` 内 `submitting = true`、Task 结束复位。

**改成**：三个 Sheet 各加 `@State private var submitting`，照 `RenewStudentNoSheet` 的范本：
- `PrimaryButton` 的 `enabled` 追加 `&& !submitting`，title 在 `submitting` 时显「送信中…」。
- `submit()` 的 `#else`（生产版）分支：进 `Task` 前置 `submitting = true`，成功/失败/切账号各路径都要复位 `submitting = false`（用 `defer` 或每个 await 后手动复位，注意 `@MainActor`）。
- `#if DEMO` 分支是同步 `closeSheet`，本身不会重入，但按钮 `enabled` 统一加 `!submitting` 无妨。

**占用文件**：仅 `HomeStubs.swift`（只动这三个 struct，别碰 `simulate()` 签到逻辑——那块归 R-1）。

## R-4 — 登录锁定 iOS 与后端两套口径

**问题（已核实，含后端真值）**：
1. **iOS 本地是假锁定**：`AuthStubs.swift` 的 `LockoutView` @1796 + `AppStore` 的 `loginFailCount` / `currentLockoutSeconds` 是纯内存计数，杀 app 重开即清零；「永久ロック」只显示「永久」无任何出口。
2. **后端真锁没接**：`tryLogin()` @1762 只 `catch APIError.unauthorized`（401→走本地 lockout），**没特判后端真锁状态码**。主会话已 grep 后端 `app/routers/auth.py` 核实真值：
   - 学生登录被锁 → 后端返 **`HTTP 423 LOCKED`**，body 带现成日语 message「アカウントロック中（残り約 X 分）」（`auth.py:86-89`）
   - 账号停用（非 active）→ 后端返 **`HTTP 403 FORBIDDEN`**（`auth.py:114`）
   - 这俩现在掉进 `tryLogin` 最后的 `catch { app.showToast(error.localizedDescription) }`，被 `APIClient.swift:115` 包成 `APIError.server(statusCode, msg)`，显示成笼统服务器错误，丢掉了后端给的日语锁定文案。

**接手会话开工先核实 2 件**（写代码前）：
- 后端 423 的 body 结构：`auth.py:86-89` 的 `detail` 到底是 `{"message": "..."}` 还是别的 → 决定 iOS 从哪个键取文案。
- `APIClient.swift:111-115`：`APIError.server(_, msg)` 的 `msg` 是怎么从 body 解析出来的、能不能拿到那条日语 message。

**改成**：
- `tryLogin()` 加分支：`catch APIError.server(423, let msg)` → 显示后端真锁文案（含剩余分钟），**以后端为锁定真值**，不再用本地写死的 30/60/300 秒假倒计时；`catch APIError.server(403, _)` → 显示「アカウントが無効です。寮監にご連絡ください」。
- 本地 `loginFailCount` 连续失败计数可保留作纯 UX 提示，但「是否锁定 / 锁多久」真值来自后端 423。`LockoutView` 倒计时若保留，秒数应取后端剩余分钟而非本地写死值。
- 若 `APIError` 没有便于 match 状态码的形态，可能需在 `APIClient.swift` 调整 error case（注意所有调用点）。

**占用文件**：`AuthStubs.swift` + 可能 `APIClient.swift` + 可能 `AppStore.swift`（动 loginFail 相关时）。⚠️ `AppStore.swift` 是多会话热点核心文件，动前看协作板。

## R-5 — 体調報告履歴整页显示假病历

**问题（已核实）**：`Features/MyPage/MyPageStubs.swift` 的 `MyHealthView` @1840 整页 `ForEach(SEED.health)` 渲染，无 `#if DEMO`、无后端拉取 → 生产学生打开「体調報告履歴」看到假人发烧记录当自己的健康史。

**数据源（已核实，纯 iOS 侧可补）**：
- 后端**已有** `GET /rollcall/reports/mine`（`app/routers/rollcall.py:818`，返回 `list[RollCallReportOut]` 本人体调报告）。
- iOS `RollCallReportsAPI`（`Foundation/Network/Endpoints/RollCallAPI.swift:78`）**只有 `create`、缺 list** → 这就是缺口，补 iOS 即可，不用动后端。

**改成**：
1. `RollCallReportsAPI` 加 `static func listMine() async throws -> [RollCallReportOut]` 接 `GET /rollcall/reports/mine`（`RollCallReportOut` 字段照 `schemas.py` 的 `RollCallReportOut` 定义对齐，缺对应 iOS 模型就建）。注意只列 kind=health 的（或前端过滤），跟「体調報告履歴」语义对齐——核实后端是否支持按 kind 过滤，不支持就 iOS 端 filter。
2. `MyHealthView` 改双轨：`#if DEMO` 读 `SEED.health`（保留演示效果）；`#else` 用 `@State` + `.task` 拉 `listMine()`，配齐**三态**（加载中转圈 / 失败可重试 / 真空态），照同文件已接后端的写法（如 `rollcallStatusCard` 生产分支 @437 / 行事予定卡 `loadedEvents`）。
3. 底线：**生产版绝不显 `SEED.health`**——哪怕接口暂时拉不通，也显空态/报错，不显假病历。

**占用文件**：`MyPageStubs.swift`（`MyHealthView`）+ `RollCallAPI.swift`（加 list 方法 + 可能加 `RollCallReportOut` 模型）。
