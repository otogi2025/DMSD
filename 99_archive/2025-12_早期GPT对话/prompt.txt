**1) 系统总体（你这套最终想要的形态）**
场景：宿舍早晚点呼。固定时间、固定教室、固定座位。老师需要确认到场与健康、发布要事；学生需要“进房间→碰一下→回座位坐好”。
结果：
*   学生：打开 App → 在老师视线范围内用 iPhone 碰教室唯一 NFC 点位 → 立即完成签到 → 回自己固定座位。
*   老师 iPad：显示真实座位布局的座位表；学生成功签到后对应座位亮起；点座位可看该生详情（扣分/历史/健康申告/扫除提交等）。
*   服务器（校内/宿舍内网）：保存全量记录、自动扣分与处分判断、提供导出与审计、支持扫除照片审核与加减分规则。
*   扫除：必须 App 内相机拍，App 自动加水印证明“今天/本场次/本区域拍摄”，上传后老师逐张审核评分。
*   规则：迟到 -0.5，缺席 -1；月度≥4 触发下月罚扫，≥8 禁足；可设置“扫除表现抵扣”但带上限；连续多月超标报警。
*   点呼后“回宿舍不去上课”这种无法自动识别的行为，由老师现场观察后在 iPad 手动把绿色改成迟到，并留下原因与审计。
**2) 终端与模块拆分（技术组件）**
**2.1 学生 iOS App**
*   登录/会话：账号密码或学校 SSO（任选），拿到 access_token
*   设备绑定（单账号单设备）
*   NFC 读取（Core NFC）：只允许在点呼页面前台读取，确保“必须打开 App 才能签”
*   本机生物识别（FaceID/TouchID）作为签到前确认门槛
*   扫除拍照：仅 App 内相机；拍完本地生成水印图后上传
*   健康申告：结构化选项+可选短备注
*   WebSocket/SSE 非必需（学生端主要是请求/响应）
**2.2 老师 iPad 管理端（iPad App 或 Web 管理台）**
*   开始/结束点呼（打开/关闭时间窗）
*   真实座位布局视图（和纸质座位表一样的排列）
*   座位状态实时更新（亮起/未到/迟到/缺席/异常）
*   点座位看详情（健康、扣分、历史、扫除）
*   手动改判（迟到/缺席/撤销/补签），强制填原因
*   扫除审核与评分
*   规则配置与报表导出
**2.3 校内/宿舍服务器（内网）**
*   API 服务（REST/JSON）
*   实时推送（WebSocket 或 SSE）
*   数据库（PostgreSQL/MySQL）
*   文件存储（本地 NAS/对象存储 MinIO）
*   日志/审计/备份
*   可选：TTS 服务、广播控制服务
**2.4 教室 NFC 点位（一个）**
两种实现等级：
*   普通 NFC Tag：只提供固定 NDEF/URL 或固定 ID（可被复制，但配合服务器挑战与老师监督可用）
*   安全 NFC Tag（SDM/SUN 类动态认证）：每次 tap 产生动态数据，服务器验证真伪与防重放（复制上一次读到的数据无效）
**3) “碰一碰签到”最关键：从头到尾完整技术链路（你要的重点）**
下面是必须存在的一条闭环：
NFC 只证明“你碰到了教室点位”；账号+设备密钥证明“是这个学生的这台设备发起”；服务器时间窗证明“是这一场点呼有效时间内”。
**3.1 点呼开场：老师控制时间窗（防提前刷）**
1.  老师 iPad 点“开始点呼”
2.  服务器创建：  
    *   session_id（例如 2025-12-19 morning dorm-A）
    *   window_start / window_end（例如 08:47:00–08:50:00）
    *   session_token（短期有效、仅本场可用）
3.    
4.  服务器向老师 iPad 推送当前座位表初始状态（全灰）
关键：是否迟到/是否有效，一律用服务器时间。手机时间只用于显示倒计时。
**3.2 学生签到：碰一下即完成**
学生必须在 App 的“点呼页”操作（保证“必须打开 App”）。
1.  App 检查当前是否存在进行中的 session_id（拉取或收到推送）
2.  App 要求 FaceID/TouchID 确认（只本机验证，不上传生物数据）
3.  学生把手机贴近教室 NFC 点位
4.  iPhone 读取到 tag_payload：  
    *   普通 tag：可能是固定 URL / 固定 NDEF 文本 / 固定 ID
    *   安全 tag：包含动态字段（计数器/随机量/认证值等）
5.    
6.  App 立即向服务器提交“签到申请”
**3.3 服务器判定：三道验证（缺一不可）**
服务器对每次签到事件做以下校验：
校验 A：场次与时间窗
*   session_id 是否存在且处于进行中
*   当前服务器时间是否在 [window_start, window_end] 内
*   不在则拒绝（或记录为迟到/无效，看规则）
校验 B：设备绑定与请求不可伪造
*   user_id 是否绑定了 device_id
*   设备签名验签通过才允许写入  
    *   服务器先下发一次性 challenge（或每次提交都带 nonce）
    *   App 用设备私钥签名：challenge + session_id + hash(tag_payload) + timestamp
    *   服务器用该设备公钥验签
*     
*   目的：防抓包改包、别人知道你学号也伪造不了
校验 C：点位真实性与防复制（按你的预算选择）
*   普通 tag：只能校验“tag 内容是否属于这个教室点位”（白名单），无法阻止复制
*   安全 tag：服务器用点位密钥验证动态认证值；并检查计数器/随机量是否重放  
    *   目的：复制上一次读到的数据无效；伪造点位难度大幅上升
*     
**3.4 写库与实时点亮座位**
通过校验后：
1.  写入 attendance_event
2.  更新该学生座位 seat_status = present 或 late
3.  通过 WebSocket/SSE 推送给老师 iPad：seat_id 亮起、状态颜色变化
4.  iPad 上座位表实时刷新，老师无需逐个点名核对
**4) “一个账号一台设备 + 密钥配对服务器”的具体做法（你点名要的细节）**
**4.1 绑定时生成密钥**
*   设备首次绑定时生成一对密钥：  
    *   私钥：保存在 iOS Keychain / Secure Enclave（优先 Secure Enclave）
    *   公钥：上传服务器，和 device_id、user_id 绑定
*     
*   服务器保存：device_public_key、绑定时间、状态（active/revoked）
**4.2 每次签到的签名内容（推荐最小集合）**
签名 payload（例）：
*   challenge（一次性，防重放）
*   session_id
*   tag_payload_hash
*   device_id
*   client_time（仅辅助排错）  
    服务器验签后再进行时间窗与点位验证。
**4.3 换机流程（必须有审计）**
*   学生端申请换机 → 老师 iPad 审批 → 服务器撤销旧设备公钥（revoked）→ 绑定新设备公钥
*   全过程写入 audit_log（谁批准、原因、时间）
**5) 固定座位 + iPad 真实座位排列（你要求的关键 UI 逻辑）**
**5.1 一人一座位绑定**
*   数据结构：seat_id -> user_id 固定映射
*   seat_layout 保存每个 seat_id 的行列/坐标/区域，iPad 按此渲染成“真实座位图”
**5.2 点亮规则**
*   服务器把“签到事件”映射到该生 seat_id
*   推送 seat_update(seat_id, status, time, reason)
*   iPad 将该座位从灰变亮（准时绿 / 迟到黄 / 缺席红等）
**5.3 点击座位看详细信息**
点击某座位弹出详情：
*   基本信息（姓名/班级/宿舍房间）
*   本月扣分总计、迟到/缺席次数、阈值进度
*   最近 N 次点呼记录
*   健康申告（结构化内容 + 提交时间）
*   扫除提交、评分、退回重扫记录
*   手动改判记录与原因（审计片段）
**6) 扫除拍照：必须 App 相机拍 + 水印（你要求的细节）**
**6.1 强制 App 内相机**
*   禁止相册选取上传（只开放系统相机采集）
*   拍照后在本地生成水印版图像再上传，服务器也记录水印字段
**6.2 水印内容（建议）**
*   拍摄日期时间（服务器同步的场次时间戳或拍摄时间）
*   session_id（早/晚哪一场）
*   扫除区域/任务编号（如 dorm-A-cleaning-zone2）
*   学生座位/学号简写（避免全暴露隐私）
*   可选：随机校验码（防简单截图造假）
**6.3 老师审核与评分**
*   iPad 进入“扫除审核队列”
*   对每张：通过/退回重扫/评分
*   评分写入 cleaning_submission 与 score_ledger
**7) 扣分、处分、抵扣与预警（规则引擎落库方式）**
**7.1 点呼扣分**
*   准时：0
*   迟到：-0.5
*   缺席：-1.0
*   规则以 score_ledger 流水形式记录（可追溯）
**7.2 阈值处分**
*   月累计 ≥4：生成“下月罚扫”标记
*   月累计 ≥8：生成“禁足”标记
*   处分生成也写入审计与月度汇总
**7.3 扫除表现抵扣（你提到的业务）**
*   扫除评分转成“抵扣额度”
*   抵扣有上限（防刷扫除抵掉大量缺席）
*   原始迟到/缺席次数保留，只是处分计算时应用抵扣
*   每次抵扣写明细（来源哪次扫除、抵扣了多少）
**7.4 连续多月超标预警**
*   月结算时生成 alerts：连续≥N 月 ≥4 分或 ≥8 分
*   老师端集中查看并自动提示
**8) 点呼广播 + TTS（你描述的功能）**
开始点呼后老师可一键广播：
*   预录音频：服务器下发 audio_id 给播放端播放
*   文本转语音：老师输入文字 → 服务器 TTS 生成音频 → 播放端播放
*   播放端常驻 WebSocket，接到指令立即播；所有广播写 audit_log

**11) 你这套“碰一碰签到”在现实里能防到什么程度（按你设定）**
*   防不来：强（老师开场+时间窗+现场监督+设备验签）
*   防代刷：中到强（老师站点位旁，代刷必须交出手机并当场操作；再叠加单设备绑定）
*   防复制点位：取决于是否上安全 NFC 动态认证（普通 tag 复制理论上存在；安全 tag 可把复制变成无效）
*   防点完就溜：靠老师现场观察 + iPad 手动改判（系统不装作能自动识别走向）
