## 学到的 NFC 原理

- Near Field Communication,13.56 MHz
- 手机线圈产生电磁场 → 卡片线圈靠电磁感应获得电流(高中物理电磁感应)
- 距离 ≤ 4cm — 这个限制反而是优势
- 每张卡有唯一 UID(工厂烧录)
- iPhone 7 之后都能读,iOS 用 Core NFC

## 卡怎么来

- 空白卡 NTAG215,~¥30/张
- "做"不了(芯片是工厂造的),只能"买空白卡 + 自己写入"
- 100 张 ~¥2000-3000

## NFC vs 二维码的决策

- 二维码漏洞:学生可以截图发给不在场的同学
- 点呼的本质是"确认人在场",不是"确认有人扫了码"
- 选 NFC,贵一点但防作弊强

## 卡 vs 手机方案 — 分阶段决策

讨论过程中想到:
- 方案 A: 学生持卡 + 老师手机扫
- 方案 B: 固定 NFC 点 + 学生手机碰 + 播报
- Android 怎么办? (MEMORY 里写 v1.0 iOS only)

**最终决定**: 分阶段
- Phase 1: NFC 卡 + 后端 + 点呼机 (不做学生 App,最快上线)
- Phase 2: 加手机 App (iOS + Android),和卡共存
- 没智能手机的学生继续用卡 → 无人被排除

## 播报防作弊想法(原创)

### 真正的起点:现实观察 ※ 重要

**我之前在宿舍就观察到过**: 有同学会拿别的同学的手机代刷签到。
这不是理论上的漏洞,是我**亲眼见过**的真实场景。

这个观察是整个防作弊设计的源头——不是"我想到了一个技术问题",而是"我看到了一个已经在发生的问题,我要解决它"。

### 从观察到解决方案的完整思考链

1. **观察**(之前就有): 同学用别人手机代刷 → 任何手机/设备验证都防不住
2. **讨论中的推导**: 二维码也有类似漏洞(截图转发) → 选 NFC
3. **发现 NFC 也有漏洞**: 卡也能让朋友带来刷 → 单纯物理 NFC 不够
4. **关键的思维跳跃**: 不用更高级的技术,而是让老师参与验证 — 播报名字 + 老师站旁边看脸 = 必须本人到场

### 为什么这个设计是"原创"

不是因为技术难——语音合成、人脸识别都是成熟技术。
而是因为**这个组合的思路是我自己从真实观察出发推导出来的**:
- 我不是先学了"有个技术叫播报",再去找用处
- 我是先看到代刷问题 → 判断纯技术解不了 → 想到让老师参与 → 选了最便宜的方式(播报)

### 面试可用原话

> "任何打卡系统都有一个共同弱点:技术只能验证设备,验证不了人。所以我加了一个语音播报:学生碰一下后系统大声念出名字,老师在旁边对照人脸。这一步看起来很简单,但它把人脸识别做不到的事——'让一个认识学生的人当场对照'——用最低成本的方式实现了。技术 + 人,比纯技术更可靠。"

还可以补充的面试答法(面试官问"你为什么会想到防作弊这件事"):
> "因为我之前在宿舍就亲眼见过有同学拿别的同学的手机代刷。这不是我设计时突然想到的问题,是我在做这个项目之前就观察到的真实场景。所以从一开始我就把防作弊当成点呼系统的核心需求,而不是事后补丁。"

## 点呼机硬件 — 不是 iPad

AI 一开始假设点呼机 = iPad,我纠正:
- 我想的是**贴在墙上的专用小盒子**,像门禁刷卡机
- 不是 iPad/手机

**硬件方案决定**: Raspberry Pi + PN532 NFC 模块 + 扬声器
- 一台 ~¥13,500,两台 ~¥27,000
- 比商用读卡器便宜 80%
- Raspberry Pi 跑 Python → 和后端同一种语言

## 完整架构

```
两台点呼机(墙上) → WiFi → 后端(FastAPI+Postgres) → WiFi → 老师 iPad(管理界面)
          │←── 学生名字(播报) ───────┘
```

- 点呼机自己播报(Python pyttsx3,不依赖老师 iPad)
- 老师 iPad 只看管理界面,不负责播报
