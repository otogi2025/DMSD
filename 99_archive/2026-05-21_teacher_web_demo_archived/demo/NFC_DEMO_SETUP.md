# 点呼機 代替モード · iPhone 快捷指令 + 銀行カード デモセットアップ

**2026-04-22 itsuki の決定**：
点呼機 (Pi 3A+) の購入が間に合わないため、デモ当日は **iPhone 快捷指令 + 銀行カード** で代替する。

## 全体フロー

```
① itsuki が銀行カードを iPhone にタップ
         ↓
② 快捷指令の NFC オートメーションが発火
         ↓
③ POST http://<老师Mac の局域网 IP>:8787/checkin?no=00
         ↓
④ Mac 上の demo_server.py がイベント記録
         ↓
⑤ ブラウザの点呼画面が 1 秒以内に poll で検知
         ↓
⑥ 座席 リュウ イヒ が緑に変わる + 日本語で「リュウイヒ」を読み上げ
```

---

## 事前準備

### 1 · Mac 側（老师 PC）

**A · サーバー起動**
```
round3/开发模式跑.command  をダブルクリック
```

ターミナルが開き、以下のような出力が出る：
```
================================================================
  Tomoshibi demo server
================================================================
  ローカル:           http://localhost:8787/
  iPhone から接続用:   http://192.168.1.42:8787/    ← ⭐ これを控える
================================================================
```

**その IP アドレス（例: `192.168.1.42`）を iPhone 快捷指令で使う**。

**B · 点呼を開始**
ブラウザが自動で開く → ログイン → 担当者選択 → 「点呼を開始」→ Live 座席表に切り替わる。
右上に 📡 **NFC 待機中** バッジが出ていれば準備完了。

---

### 2 · iPhone 側（itsuki の iPhone 17 Pro）

**A · 同じ Wi-Fi に接続**
老师 Mac と同じ Wi-Fi に繋げる（必須）。

**B · 快捷指令 で NFC オートメーションを作成**

1. `ショートカット` App を開く
2. 下タブ「オートメーション」→ 右上 `+`
3. 「**NFC**」をタップ
4. 「スキャン」→ **銀行カードを iPhone の裏面にタップ**（NFC タグ UID が読み取られる）
5. 名前を付ける：例「Tomoshibi 点呼 番号 00」
6. アクションを追加：
   - 「**URL の内容を取得**」を選ぶ
   - URL: `http://192.168.1.42:8787/checkin?no=00`  （先ほど控えた Mac の IP）
   - 方法: **POST**（「詳細を表示」→「方法」→ POST）
   - リクエスト本文: なし
7. 「**実行前に尋ねる**」を **OFF**（タップしただけで走らせる）
8. 「**完了時に通知**」を **OFF**（silent）
9. 右上「完了」で保存

**C · テスト**
iPhone を銀行カードにタップ → Mac 画面の座席表で リュウ イヒ が緑になる + スピーカーから「リュウイヒ」と読み上げられる。

## トラブルシューティング

### ❌ タップしても何も起きない

**原因 1**: iPhone と Mac が同じ Wi-Fi にいない  
→ 設定アプリで両方の Wi-Fi を確認

**原因 2**: Mac の IP が変わった  
→ ターミナルに再表示される IP を見て、快捷指令の URL を更新

**原因 3**: Mac のファイアウォールが Python をブロック  
→ システム設定 → ネットワーク → ファイアウォール → Python を許可

**原因 4**: NFC オートメーションが「実行前に尋ねる」ON のまま  
→ オートメーションを開いて OFF に

---

### ❌ 座席は緑になったけど声が出ない

- ブラウザに一度クリックしたか？（Chrome は user interaction の前は speechSynthesis をブロックする）  
  → 「点呼を開始」ボタンを押した時点で satisfied のはずだが、念のため画面のどこかをクリックしてから再度タップ

- 音量がゼロになっていないか？  
  → Mac の音量を確認

---

### ❌ 「不明な番号」が出る

- 快捷指令の URL が `?no=00` になっているか確認  
  他の番号を使う場合は `?no=01` ～ `?no=23` のいずれか（`window.ACCOUNTS` で定義済み）

---

### ❌ 違う学生が光る

- 快捷指令の URL の番号が違う可能性  
  → `?no=00` = リュウ イヒ（itsuki本人）

- iPhone にタップしたカードの UID が違う（複数のオートメーションが存在し、間違ったほうが発火した）  
  → ショートカット App → オートメーション → 不要なものを削除

## 技術メモ

- **POST /checkin?no=XX** は CORS `Access-Control-Allow-Origin: *` なので同一 LAN 内ならどこからでも叩ける
- **seq** インクリメントで dedup → 同じイベントを複数回処理しない
- ブラウザは 1 秒間隔で poll（SSE や WebSocket ではない理由：Python の `http.server` を超えない最小実装）
- 複数の学生を連続でタップ可能（seq ごとに別イベントとして処理）
- リュウ イヒ 以外を演示したい場合：快捷指令の URL を `?no=01` ～ `?no=23` に変える、もしくは別カードに別オートメーションを割り当てる

## なぜこの構成か（AC 面接素材）

- **点呼機の購入が間に合わない**（4-28 デモまで 6 日）という制約に対して、すでに持っている端末（iPhone + 銀行カード）で代替
- 「要件（NFC で自動的に座席更新 + 音声フィードバック）」を機械ではなく iOS 快捷指令で実現 → **同じ体験、ゼロ追加コスト**
- Tomoshibi の思想「カードを持つ学生側の専用デバイス不要、タップ先（検知器）だけあればよい」と一致

> "4-28 のデモに間に合わせるため、点呼機を買う代わりに iPhone のショートカット機能を使って同じ体験を再現しました。
> これは一時しのぎに見えますが、実は Tomoshibi の設計思想『学生側はシンプルなカード、判定ロジックは全部サーバー』をそのまま示しています。"
