WIP.md 和 TODO.md 是两个不同职责的文件，**绝不**互相复述：

| 文件 | 职责 | 大小预算 | 给谁看 |
|---|---|---|---|
| **WIP.md** | 当下书签 + 最近 5 次会话 1-2 行总结 + 多会话占用 + 阻塞项 | ~150 行上限 | CC（每次会话开始读全文）|
| **TODO.md** | 所有未完成事项的完整 backlog（真值）| 无上限 | itsuki（主动问"还有什么没做"才读，CC 按需读）|

## 铁律（itsuki 2026-05-03 拍板，同晚治理 commit 收紧）

- 未完成的事**只写在 TODO.md**
- WIP.md **绝不**复述 TODO 的内容
- WIP「最近会话」section 最多保留 5 条，老的删（详细历史靠 git log + raw/ 找）
- WIP 头部「最后更新」长串历史不保留 — 压缩到「最近会话」5 条

## CC 启动流程（必做）

1. 读 `WIP.md` 全文（短，~150 行）
2. 跑 `git status`
3. 给 itsuki 1 段中文交代「现在站在哪 + 上次会话主题」
4. **不主动读 TODO，不主动催进度，不主动列待办**

## TODO.md 按需读（不主动）

**只在 itsuki 主动问下面任一时**才打开 TODO：
- 「还有什么没做？」
- 「下一步该做什么？」
- 「这个任务有 backlog 吗？」

**禁止**：
- 启动时主动读 TODO 列待办给他看
- 主动催「上次说要做的 X 还没做」
- 把 TODO 内容塞进收尾总结

**Why**: itsuki 不喜欢被 AI 催进度。读 TODO 的判断点在他，不在 CC。

## Why（更全的背景）

**5-03 早些时候 itsuki 主动指出**：「WIP 和 TODO 功能是不是有些重叠了？你不需要读 TODO 吗？」— 之前 CC 只读 WIP 没读 TODO，导致：
1. WIP 的「🔄 进行中的任务」section 218 行大段复述 TODO 的当前任务（轨道 A/B/C 等），两边都要更新容易漂移
2. WIP 头部「最后更新」字段堆积 20+ 行历史，每次 CC 启动得看一大堆过期信息

**5-03 早些时候我（CC）拍板**「CC 启动 WIP + TODO 顶部 200 行 都读」 — 当晚 22:34 治理 commit `1ab265a` 把这条**收紧成「只读 WIP, TODO 按需读」**。理由：CC 主动读 TODO = 隐含主动催进度，itsuki 不喜欢。

## How to apply

- 每次会话**结束**：更新 WIP「最近会话」（最上面加 1 条新 + 把第 6 条删，保持 ≤5 条）；新增的未完成事项写到 TODO.md
- 每次会话**开始**：只读 WIP 知道短期上下文 + git status；**不读 TODO 不催进度**
- 看到 WIP 里有「未完成的 X 任务」描述 → **bug，要警觉**，应该砍 WIP 里那段 + 在 TODO 里加 / 找对应条目
- 看到 TODO 里有「这个会话做了 Y」描述 → **也是 bug**，TODO 不是会话日志，应该挪到 WIP「最近会话」或 raw/
