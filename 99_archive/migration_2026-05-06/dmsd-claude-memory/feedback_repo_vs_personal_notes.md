## 真正的边界:事实 vs 叙事

DMSD 项目仓库(`~/dev/DMSD/`,包括 `05_logs_ac/`)装的是**真实发生过的事实**——
不管这件事最后会不会被教授看到。提交前 itsuki 会做一次 curation pass,决定哪些文件给教授看。
仓库本身不是"教授视图",仓库是"完整事实档案"。

### 可以放进项目仓库的(事实类)
- code(代码)
- specs(规格文档)
- dev_log(开发日志:今天做了什么、遇到什么、学到什么)
- problem_solving(问题解决记录:bug 怎么调出来的)
- reflection(反思:对一段经历的真实反思)
- progress_overview(进度总览)
- **ai_协作记录(AI 协作分歧记录)** ← 这也是事实记录,和 dev_log 同性质
- 任何"在 X 时间发生了 Y"的真实档案

### 不可以放进项目仓库的(叙事/框架类)
- 面试故事素材库 / 故事银行(把事实重新包装成"准备讲的版本")
- 面试话术模板
- 自我激励 / 鼓励性内容
- "怎么向面试官解释这个项目"之类的元叙事
- 任何"为面试表演"性质的文件
- 任何"框架先行"的文件(先设计模板,再往里填内容)

这些应该放到 itsuki 的 Mac 备忘录(`关于AC的随手记`)或别的私人空间。

## 关键判断标准

问自己一个问题:

**这个文件是"在记录已经发生的事",还是"在设计如何包装将要发生的事"?**

- 前者 → 项目仓库
- 后者 → 备忘录

### 经典对比
| 文件类型 | 性质 | 位置 |
|---------|------|------|
| `dev_log/2026-04-10.md` | 记录今天做了什么 | 仓库 ✅ |
| `problem_solving/NFC_NFD_bug.md` | 记录怎么解决一个 bug | 仓库 ✅ |
| `reflection_2026-04-10_一个月的空白.md` | 反思一段真实经历 | 仓库 ✅ |
| `ai_协作记录.md` | 记录 AI 协作分歧 | 仓库 ✅ |
| `ac_story_bank.md` ❌ | "把这些事整理成 5 个故事,每个 4 个字段" | 备忘录 |
| `interview_pitch_templates.md` ❌ | 面试话术模板 | 备忘录 |

## Why(精炼后的理由,2026-04-10 itsuki 两次澄清得来)

**第一次澄清**:故事银行被我错放进项目仓库时,itsuki 纠正我:
> "存到我的mac的备忘录里。DMSD项目文件里要的是写ac的规范或者别的,存这个不算规范的故事有什么用?"

**第二次澄清**:当我在协作记录文件该放哪时反复纠结,itsuki 又纠正:
> "协作记录文件放DMSD,不是除了交给教授看的文件以外都不许放,到时候具体叫文件的时候我肯定会做一次整理"

合起来,真正的规则是:
1. 仓库**不是**"教授视图",所以"教授看不看到"不是判断标准
2. 仓库**是**"完整事实档案",所有真实发生的事都可以进
3. **但**叙事/框架/包装类的东西不能进——它们污染事实档案
4. 提交前 itsuki 自己会做 curation,决定哪些事实展示给教授

## How to apply

1. 创建任何新文件前,问:**"这是事实记录,还是叙事/框架?"**
2. 事实记录 → 默认放进仓库(但仍然要选合适的子目录:dev_log/ vs problem_solving/ vs 顶层等)
3. 叙事/框架 → 默认放进 Mac 备忘录,先和 itsuki 确认
4. 不确定 → 先问 itsuki,不要自己拍板
5. **一个判断捷径**:如果文件名里出现"故事""话术""模板""提炼""怎么讲"——很可能是叙事类,不要进仓库
6. 边界宽容度:对仓库可以稍微宽松一点(因为提交前会有 curation),对备忘录的事实记录要克制(因为备忘录是 itsuki 的私人空间,不是 fallback 储藏室)
