## 命名（2026-04-21 拍板）

- **DMSD**（Dormitory Management System Digitalization）= 开发项目代号 / Git 仓库名 / AC 叙事项目名
  - 保留场景：项目名、仓库路径、AC 入試 叙事里"这个项目"、git 历史、CLAUDE.md 项目信息
- **Tomoshibi**（灯火 / ともしび）= 面向用户的**系统/产品名**
  - 使用场景：学生装的 iOS / Android App / 老师的 Web / 点呼机终端 / 面向管理员或用户的所有文案

## 为什么取日语名（AC 面试话术 — 不要改）

> "我在日本留学，宿舍是我在异国的第二个家。这个系统守护的是'灯火'——每个学生夜晚平安归来、房间亮起一盏灯。所以取日语名 Tomoshibi（灯火）。"

叙事可对应 AC 核心问题：
- #1 问題発見：从宿舍这个"第二个家"出发 → 产品叙事的情感锚点
- #5 志望動機：在日本学习/生活 → 产品文化认同 → 筑波

## How to apply

- **新建面向用户的文字（App title / Web 页面标题 / README / 对管理员/教授介绍）** → 用 Tomoshibi
- **讲项目开发过程（commit / spec / 技术决策 / 版本号）** → 用 DMSD
- **两者可共存**："DMSD 项目正在开发 Tomoshibi 宿舍点呼系统"
- 未来新会话：CLAUDE.md §项目信息 会明确这个区分，不会丢失
- 改旧文档时**区分上下文**，不要无脑 replace_all："DMSD 项目" ≠ "DMSD 系统"

## Why 记在 memory

- 跨会话必须一致（今天之后新开的会话都要知道系统叫 Tomoshibi）
- AC 面试话术是 itsuki 原话"这个记好"要求记的 — 不能漂移
