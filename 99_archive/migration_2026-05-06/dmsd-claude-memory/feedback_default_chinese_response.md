默认对话语言是 **中文**。CLAUDE.md §语言规则 已写明，但 CC 在做日语 UI（如 Tomoshibi Web / iOS）的会话里容易"惯性带日语" → 总结段落、表格说明、对外讲解都不知不觉变成日语。itsuki 已经多次手动纠正。

**Why**：itsuki 是中国人，理解日语没问题但他付钱给 Claude 是为了思考成本最低的协作。中文是他的母语，思考最快。日语只该出现在面向最终用户的产品本体里 / 老师将来要看的交付件里。

**How to apply**：
- ✅ **保留日语**：引用 UI 上的实际按钮 / 字段名 / toast 文案 / 文件名 / 代码字符串 / API 路径 / 版本号 / 命令 / API 路径
- ✅ **保留日语**：写到产品代码 / spec 里的 seed 数据、placeholder、菜单标签
- ✅ **保留日语**：老师 / 第三者 原文引用块（APPENDIX 类）— 这是 evidence，不能翻译
- ✅ **保留日语**：专有名词（寮監 / 寮務部長 / 出寮届 / 帰省 / 外泊 / 帰国 等）— 这些是产品术语，无对应中文
- ❌ **必须中文**：解释做了什么、总结改动、列变更点、回答用户的问题、说明原理、给建议、文档主体说明
- ❌ **必须中文**：**spec / 要件 / 设计文档 / Gap 表 / Open Questions / 修订动作** 这些 itsuki 自己读的"思考层" — 即使内容里夹日语术语，章节标题 / 段落主体 / 表头 / 分析 仍是中文。文档不等于产品。
- ❌ **特别注意**：做日语 UI 的多轮会话尾段，最容易整段写日语 — 每次输出前心里过一遍"这是讲给 itsuki 听的还是写进产品的"
- 例外：itsuki 主动用日语提问 / 要求日语回答时按他当下指定走
