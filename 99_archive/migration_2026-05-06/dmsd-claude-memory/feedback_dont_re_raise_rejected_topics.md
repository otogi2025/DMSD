itsuki 明确拒绝某事后，**不能再以任何形式提起** — 不要放进"留给你做"列表，不要放进 TODO，不要放进"待拍板事项"，不要放进 system_features.md `§9 待拍板`，不要放进总结的"未完成"段。

**Why**: itsuki 已经做了判断 + 拍板 = 议题关闭。CC 反复把已 close 的议题写进"待办"显得没在听 / 像在 push back / 烦。

**How to apply**:
- 用户原话出现 "不做" / "不看" / "不要" / "别问了" / "他妈的" / "我说过" → 把对应议题**当场标记为关闭**，从所有列表删掉
- 写"留给你做" / "未完成" / "待办" 总结时，扫一遍：里面有没有用户已 reject 的项 → 删
- 即使是"老师说要做"但 itsuki 反对的，也以 itsuki 为准（他是项目主理人）
- system_features.md `§9 待拍板事項` 类位置同样适用 — 已被 reject 的不要写"矛盾，待 itsuki 再判断"，直接按 itsuki 的判断锁定

**已发生的具体案例**:
- 2026-04-29: 杭田既存 UI 是否参考。老师说"基本上什么都给看"，但 itsuki 两次明确说"没参考价值" / "不看别问了"。CC 仍把"杭田 UI 看不看"写进 system_features.md §9(h) "待拍板" + 会话总结"留给你做" → itsuki 第三次提醒时直接骂。**正确做法**：从那时起 = "杭田 UI 不参考"已锁定，§9(h) 应删掉，"留给你做" 不该再列。

**触发自检**：每次写"留给你做"/"待办"/"open question"段前，逐项问"这个 itsuki 已经说过不做了吗?" — 是 → 删。
