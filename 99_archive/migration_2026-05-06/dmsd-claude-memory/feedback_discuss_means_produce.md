讨论 = 产出。和 itsuki 的每轮重大讨论结束后，CC **不能只停在"得出结论"**，必须立即把结论落地到相应权威文档，**尤其是 CLAUDE.md**。

**Why:**
- itsuki 原话 (2026-04-20 会话 ~20:00)：「我跟你讨论，最终目的是让你产出，以后别忘了记得加到 CLAUDE.md 里」
- 触发点：CC 在议题 D 审计时承认 "CLAUDE.md / WIP.md 按惯例会话结束统一改"。itsuki 不满意"等会话结束"这个默认行为——他觉得讨论完立即落地才是讨论的真正完成
- 根因：AI 容易沉迷"有来有回的讨论"，把"说清楚了"当作"完成了"。但 itsuki 的视角里，"说清楚" 是中间态，"写进权威文档"才是完成态

**How to apply:**
- 每轮重大讨论（新决策 / 推翻旧决策 / 重要概念澄清）后，**当场检查 3 个问题**：
  1. 这个决策是否推翻了 CLAUDE.md 里的旧表述？→ 立即改
  2. 这个决策是否引入了新的技术栈 / 架构 / 规则？→ 立即加到 CLAUDE.md 相应章节
  3. 这个决策是否产生了新的 meta 规则？→ 记 memory + CLAUDE.md 新节
- **不等会话结束统一做**（传统流程是会话结束 5 步走，但 CLAUDE.md 这种核心文档要立即更新）
- raw dump 和 CLAUDE.md 更新**同步做**，不是二选一
- 议题 A/B/C/D/E 切换之间 就检查一次 CLAUDE.md 是否需要更新
- 本条规则本身也属于"meta 决策"—— 同时加到 CLAUDE.md § 对话规则 + memory

**不适用场景：**
- 小的实施细节（例如某个变量命名）不必进 CLAUDE.md
- 还在讨论中途没拍板的候选方案不必加
- 只和当前代码库相关、可从 git/代码读出的信息不进 memory（见 auto-memory 规则）
