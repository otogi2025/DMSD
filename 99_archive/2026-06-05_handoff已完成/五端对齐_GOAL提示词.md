【目标】
把 DMSD 五端代码做一次全面对齐 + 深度找 bug。最终让五端在「功能 / 调用的后端接口 / 数据字段 / 业务规则」四层跟 iOS 学生端看齐。iOS 是当前最成熟的端，作对齐基准；后端是数据契约的真值源（所有字段名 / 接口以后端为准）。

【铁律约束 — 动手前必读】
1.「代码一模一样」指功能层面，不是逐字一样。iOS 是 Swift+SwiftUI，Android 是 Kotlin+Compose，语言和界面框架不同，逐字相同做不到。要对齐的是：有哪些功能、调后端哪些接口、用哪些字段、业务规则（几点算迟到、扣几分等）。
2. 五端成熟度差距大：iOS 最靠前，Android 还是早期骨架（约 22 屏只搭了界面没接后端），老师网页中等，点呼机最早。这是跨多阶段的大工程，按阶段推进，不要假装一次做完。
3. 防作弊核心（nonce 10 秒一次性随机数 / ECDSA 数字签名 / 设备注册校验 / 卡→学生映射）后端一行没写，是单独大议题（TODO A-010）。本次不实装它的设计决策，遇到只记 TODO，不动。

【执行方式 — ultracode 模式（本会话已开 ultracode：质量优先，token 成本不设限）】
- 阶段 0 摸底 + 找 bug 用 Workflow 工具做多代理编排，不要手动一个个 Agent：
  · 摸底：五端各派子代理并行扫，产出该端「功能 / 调用的后端接口 / 用的数据字段」结构化清单（用 schema）
  · 找 bug：每端多视角并行（正确性 / 跟后端字段对齐 / 安全 / 可简化），找到的每条 bug 再派独立 skeptic 子代理对抗验证（默认 refuted=true，多数判定为真才保留），过滤掉假阳性
  · loop-until-dry：连续 2 轮挖不出新 bug 才停
  · 汇总：一个子代理拿全部摸底结果产出「以 iOS 为基准的功能对齐差异矩阵」
- 阶段 1 及以后的修复也尽量用 Workflow 编排，每个修复项跑完独立验证
- 醒来时根据五端真实代码结构现写最优 workflow 脚本，别套死模板

【分阶段执行】
阶段 0 摸底（先做，只产出报告，别急着改）：
  派并行子代理扫五端，产出三块写成报告文件存到 05_logs/raw/：
  ① 全代码库 bug 清单（每条带文件 + 行号 + 严重度）
  ② 跨端字段对齐差异（后端 vs iOS vs Android 哪个字段对不上：命名漂移 / 可空性不一致 / 类型错 / 缺字段）
  ③ 以 iOS 为基准的功能对齐差异矩阵（每个功能在 android / web / device / backend 各端是 有 / 缺 / 半成品 / 不适用）
阶段 1 零决策修复：
  字段命名漂移、明确 bug、有唯一正确答案的对齐项 —— 直接改 + 验证。需要拍板的攒成清单不要自己决定。

  按对齐矩阵，把 iOS 有、Android 缺的功能逐个用 Kotlin+Compose 补到 Android，接同样后端接口、用同样字段、同样业务规则。
