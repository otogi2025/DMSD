## 1. 总览

Tomoshibi 点呼系统的硬件体系由 4 类物理设备构成：

| 类别 | 数量 | 位置 | 核心职责 |
|---|---|---|---|
| **点呼机** | 4 台 | 宿舍楼层（具体位置 TBD）| 读 NFC + 发 HTTP + 接 WebSocket + 播报 + 亮灯 |
| **NFC 卡** | ~120 张 + 备用 | 每学生 1 张 | 路径 A 的签到凭证（UID 绑学生账户）|
| **动态 NFC 贴纸** | 4 个（每台点呼机 1 个）| 贴在点呼机外壳 | 路径 B（iPhone / Android）的签到入口（含动态 nonce）|
| **老师端设备** | 1 台 | 管理室/现场 | 打开管理网站 → 点呼开始/结束 + 看座位表 |

### 架构原则（4-15 拍板）

- **thin client / thick server**：点呼机只搬运数据，业务判断全在后端
- **服务器是唯一判定者**：是否准时、是否在时间窗、是否缺席 —— 全由后端以 `server_now (JST)` 为准
- 点呼机硬件只负责：NFC 读写、HTTP 收发、声光反馈

## 2. 点呼机（4 台）

### 2.1 主板：Raspberry Pi 3 Model A+ ✅（2026-04-21 推翻 Pi 4B 2GB）

**选型决策**：4-21 [Mac-demo-sprint] 会话（raw §16:00-16:15）
- 触发：itsuki 查淘宝实际市场价 Pi 4B 2GB ¥500 RMB/台（CC 原估价 ¥300 偏低），判定"太贵"
- 回炉对比 5 个方案（Pi 4B / Pi Zero 2 W / Orange Pi Zero 2W / 二手 Pi 3B / ESP32）
- 发现 Pi 3A+ 反而最合适（反直觉结论）

| 项目 | 规格 |
|---|---|
| 型号 | Raspberry Pi 3 Model A+ |
| CPU | Broadcom BCM2837B0 (4× Cortex-A53 @ 1.4GHz) |
| RAM | **512MB** LPDDR2（紧但够）|
| 联网 | **双频 2.4 + 5GHz Wi-Fi** + Bluetooth 4.2 |
| 以太网 | 无（无需）|
| USB | 1 个 USB 2.0 |
| GPIO | 40-pin（I²C / SPI / UART / PWM 全支持）|
| 音频 | **3.5mm 模拟音频口**（直接接小喇叭）|
| 操作系统 | Raspberry Pi OS (Debian based) |
| 开发语言 | Python 3 |
| 尺寸 | 65×56 mm |
| 采购价 | **¥6480 日元（日本 Amazon，demo 1 台）** / **估 ¥180 RMB（淘宝，部署 3 台）** |

**为什么 Pi 3A+ 反而最合适（反直觉结论）**：
- ❌ Pi 4B 2GB（¥500 RMB）：严重 over-spec（点呼机 thin client 用不到 2GB + 4 核 Cortex-A72）
- ❌ Pi Zero 2 W（¥180）：无 3.5mm 音频要外接 USB 音频卡（零基础挑战）
- ❌ Orange Pi Zero 2W：国产，软件生态弱，教程少踩坑多
- ❌ 二手 Pi 3B：故障率 + 老板子
- ❌ ESP32：无 Linux + 无 Python 完整 + 本地 TTS 几乎做不到（大坑）
- ✅ **Pi 3A+**：**最便宜含音频口**的官方 Raspberry Pi + **双频 WiFi**（比 Pi 3B 的单频 2.4GHz 更强）+ Raspbian 软件 100% 兼容（教程海量）

**USB/以太网都用不到的论证**：
- PN532 NFC 读卡器：I²C 接口接 GPIO，**不占 USB**
- ST25DV16K 动态贴纸：I²C 接口接 GPIO，**不占 USB**
- 点呼机 headless 部署（SSH 远程登录）：**不插鼠标键盘**
- 宿舍用 WiFi：**不需要以太网**
- → 1 个 USB 够用 + 以太网可省

**512MB RAM 的风险评估**：
- Raspbian Lite 空载 ~100MB
- Python + 主程序 ~50MB
- pyttsx3 TTS（espeak 引擎）~30MB
- NFC 驱动 + 网络栈 ~50MB
- 系统缓存/buffer ~100MB
- **总计 ~330MB，余量 ~180MB**（"紧但够"）
- **硬约束**：未来如果加人脸识别 / 视频流 / 本地大缓存 → 不够
- **但**：v1.0 范围内不做这些（thin client 原则）

**核心职责（thin client 约束下）**：
- 读 PN532 的卡 UID（路径 A）
- 通过 I²C 写入 ST25DV16K 的 NDEF URL（路径 B）
- HTTP POST 签到数据到后端
- WebSocket 订阅后端的播报指令
- 播放学生姓名语音（pyttsx3 → 3.5mm 小喇叭）
- 点亮 LED（绿/红）

**历史决策链**（完整留痕）：
- **4-15**：itsuki 砍 Pi 4B 4GB → Pi 4B 2GB（砍过度配置第 1 次）
- **4-20 议题 A**：拍板 Pi 4B 2GB × 4 = ¥1200 RMB（CC 估价偏低）
- **4-21**：itsuki 查实际市场价 ¥500/台 → 回炉 → **Pi 3A+ × 1（Demo 阶段）**（砍过度配置第 2 次）

**AC 叙事价值**：两次主动下压 AI 过度配置建议 + 按真实需求（thin client）量体裁衣 → 详见 `raw/2026-04-21.md §16:15`

### 2.3 动态 NFC 贴纸：ST25DV16K ✅（上线版）/ NTAG215 静态（4-28 demo 阶段）

**选型决策**：4-20 议题 A（raw §16:00 方案 B 定型）

**⚠️ 2026-04-21 demo 阶段降级说明**：
- ST25DV16K 淘宝空运 7-10 天，4-28 demo 前到不了
- **Demo 阶段替代方案**：用 NTAG215 静态贴纸 + iOS Shortcuts Automation（NFC 触发自动调签到 API）
- 替代方案配置详见 `00_admin/demo_4-28/ST25DV_fallback.md`
- **影响**：Demo 阶段 URL 固定（可复制代签，不演示这个漏洞）；用户体验（iPhone 碰一下）100% 对齐上线版
- **上线版本保持 ST25DV16K 动态 nonce 方案不变**（nonce 每 10 秒刷新防代签）
- Demo 日后 ST25DV16K 到货 → 迁移零用户侧改动（换贴纸物理即可，iOS Shortcuts Automation 不需改）


| 项目 | 规格 |
|---|---|
| 型号 | ST25DV16K（STMicroelectronics）|
| 模块厂商 | 极客创享（淘宝）/ Adafruit / SparkFun 等 |
| EEPROM 容量 | 16 Kbit（2KB）|
| 接口 | I²C + Qwiic/STEMMA（4-pin JST-SH 即插即用）|
| 读取距离 | 2-5cm（典型）|
| 写入寿命 | 100 万次 @ 25°C |
| 数据保留 | 40 年 |
| 供电 | 3.3V（从 Pi GPIO 取）|
| 采购价 | ¥25 RMB/个（中国淘宝）|

**为什么选 ST25DV（不是静态 NTAG）**：
- 静态 NTAG215（¥3/个）URL 不变 → 学生复制后永久有效 → 代签漏洞（raw §15:30）
- ST25DV 可通过 I²C 动态刷新 EEPROM 内容 → 每 10 秒换 nonce → 复制的 URL 10 秒后失效

**为什么选 16K（不是 4K / 64K）**：
- NDEF URL 约 80 字节，4K（512 字节）就够用
- 16K = 2KB 留充足余量（未来可能存 device_id 签名、多 URL 等）
- 价格相同（¥25）→ 选最大容量

**核心工作模式**：
- Pi 4B 通过 I²C 总线连 ST25DV16K
- Pi 上 Python 代码每 10 秒：
  1. 向后端请求新 nonce（10 秒时效）
  2. 拼接 NDEF URL `https://dmsd.otogi2025.com/checkin?device=DEV001&nonce=XXX`
  3. 通过 I²C 写入 ST25DV16K 的 EEPROM
- ST25DV16K 被动等待学生手机 tap 读取

### 2.4 反馈设备 🟡 占位

- **LED**（绿/红 × 4 台）：显示签到成功/失败 — 议题 E 定型号
- **喇叭**：播报学生姓名 — 议题 E 定（USB 声卡 / HAT / 蓝牙音箱）
- **外壳**：防护 + 固定 — 议题 E 定

### 2.5 电源 ✅（2026-04-21 按 Pi 3A+ 修订）

- **Pi 3A+ 电源**：5V/2.5A **micro-USB**（不是 USB-C，Pi 3A+ 用老式 micro-USB 口）
- Demo 阶段：日本 Amazon 单买 ~¥1200 日元/个
- 部署扩容阶段：淘宝批量 ~¥20 RMB/个
- ~~PoE~~ 不考虑（Pi 3A+ 无 PoE 接口；墙插即可）

## 3. NFC 卡（NTAG215）✅

**决策**：4-19 G2 会话（raw §20:15 卡生命周期）

| 项目 | 规格 |
|---|---|
| 芯片 | NTAG215（NXP）|
| 形态 | 空白卡片（CR80 标准，85.6 × 54mm，类似银行卡）|
| UID 长度 | 7 字节 |
| 容量 | 540 字节 EEPROM（只存 UID，Tomoshibi 不写数据）|
| 采购价 | ¥3-5 RMB/张 |

**学生端使用**：
- 学生自己用"任意贴纸"（例如便利贴 / 胶布 / 写姓名的小贴纸）贴到卡背面
- **不贴学号**（学号随届变化）/ **不贴打印姓名**（不美观 + 成本）
- 目的：学生自己能分清哪张是自己的 + 毕业后撕掉贴纸即可回收给下一届

**生命周期**：
1. 入学：发空白卡 → App 内 tap 绑定 UID 到账户
2. 使用：日常签到（Path A）
3. 丢失：新卡发 + 新绑定 + 旧 UID 作废（不收钱）
4. 毕业：清除 UID 绑定（账户保留作历史）→ 卡回收给下一届

**没手机的学生**（偶尔 1-2 个）走"管理员代录"特殊通道。

### 4.4 Android App 签名证书（keystore）存储方案

**背景**：Android App 每次发布必须用 keystore 签名。keystore 丢失 = 所有已装学生必须卸载重装（数据丢失）。详见 `raw/2026-04-20.md §18:10-18:50`。

**存储方案**（2026-04-20 议题 B 定稿）：

| 位置 | 内容 | 为什么 |
|---|---|---|
| 当前开发机 Mac | `dmsd.keystore` 原文件 | 日常打包用 |
| 后端服务器 `/backups/` | `dmsd.keystore.enc` （openssl aes-256-cbc 加密）| **跨人传承基础设施**（毕业交接后接手人继承服务器）|
| 纸质笔记本 | keystore 密码 + AES 密钥 | 物理离线备份，毕业转交接手人 |
| ~~iCloud~~ | ~~（不使用）~~ | ~~个人账号不可传承~~ |

**传承考量**（itsuki 毕业交接思路）：
- itsuki 是学生（2026-04 高三 → 2028-03 毕业）
- Tomoshibi 2027-04 上线 → itsuki 只管 1 年 → 必须传给下一届学弟学妹或老师接管
- Mac / iCloud 都是个人资产，不可传承
- 服务器是 Tomoshibi 基础设施，**谁接手系统就继承服务器** → 最适合放 keystore

**校验纪律**：
- 每年 4 月春假期间，验证 keystore 还能用 + 密码没忘
- 毕业前 1 个月，给接手人完整"毕业交接包"（keystore + 密码 + DNS + GitHub + 服务器凭证）

## 5. 供应链

### 5.1 采购渠道：中国淘宝 → 空运日本

**理由**：
- 价格优势：ST25DV16K 中国 ¥25 vs 日本 ¥1500+ 日元（约 ¥75 RMB），差 3 倍
- Pi 4B 2GB：中国 ¥300 RMB vs 日本 ¥7000 日元（约 ¥350 RMB），差小但仍省
- 空运 8-13 天可接受（距离 2027-04 上线有富余时间）

**物流**：菜鸟直邮（空运） / 品牌"极客创享"等都支持

**AC 叙事点**：跨境供应链成本优化（展示国际工程视野）

### 5.2 风险

- 海关：ST25DV16K 属通用电子元件，目前无出口限制
- 品控：中国供应商品质参差，第一批到货后测试每一个再用
- 汇率：2026-04 1 RMB ≈ 20 JPY；汇率波动 ±5% 对本单影响 < ¥1500 JPY
