## 1. 必读 — 推翻 / 强调点（最高优先级）

> 与既有设计冲突 / 从根本约束 UX 的项。**漏掉这里 = 后期大改造**。

### R1. 通知 = 邮件固定（**push 通知不可**）

老师原文（日语）:

> 訂正：役職への通知はメールにしてください。
> 現在、メールで行っています。提出したことが「残る」からです。
> 今現在リュウイヒも外泊を提出していますが、国際交流部長が許可していませんね。
> メールは送信されているので、単純に後回しになっているだけだと思います。
> 国際交流部長忙しそうなので許してください。
> もしこれをプッシュ通知にすると、通知を消して忘れ去られる可能性が高いと思いますので、
> やはりメールでの通知にしましょう。

**意思**:
- 通知方式 = **邮件固定**。push 不可（消除 → 遗忘风险）
- 理由 = "残る"（留下记录）。邮件服务器侧也有 receipt，即使被推迟处理也不会消失
- 实例 = 4-28 リュウイヒ的外宿届，国际交流部长还没承认 → 因为是邮件所以仍在 inbox 里，迟早会处理。换成 push 早就被划掉，永远忘了

**与 Tomoshibi 既有设计的矛盾**:
- `system_features.md §5.4` 学生信息变更通知 = 明记 **「老师編集 → 学生に push 通知」**
- `system_features.md §6.4` 宅配通知 = 明记 **「自動 push」**
- 申请承认系通知方式在 §6.3 未明记（默认 push 想定）

**修订动作**:
- 把 `system_features.md` 通知章节（§5.4 / §6.4 / §6.6）改写为 **"邮件优先 / push 辅助"**
- 役职向承认待通知 = **邮件必须**（push 一律砍）
- 役职侧 dashboard 加 **未承认件数永续 badge**（"后回し" 在视觉上也留痕，作为兜底）
- iOS 的 push 实装范围重审

### R2. 老龄寮監向 UX = **极限简化**（条件分歧不可）

老师原文（日语）:

> ※上記は高齢の寮監が使用するため、使用法を極力単純化する必要あり。
> （この場合はこちらをタップ、こういう場合はこちらをタップ、というのは避ける。
> どの場合でも、これを「押して」、この次に「ここを押す」ぐらいがよい。

**意思**:
- 「X 的情况按 Y、Z 的情况按 W」型 UI = **不可**
- 不管什么情况都用 **同一套手顺** 完成的"一本道"UX = **必须**
- 适用对象 = ★ iPad 上的点呼・学習画面（Role C 全画面）

**对 Tomoshibi 的影响**:
- 现 teacher_web/round3 + iPad 画面的 Role C UI **按这条规则全画面再审**
- 例: 点呼开始按钮不要做状态判断 = "随时按都 OK / 内部决定是开始新 session 还是吸收进现有 session"
- 例: 出席判定只允许"✓ / ✗" 两键确认，不开多 tab / 多 modal 分歧
- 在 `IOS_DESIGN_LOG.md` + `WEB_DESIGN_LOG.md` 增设 **"老龄寮監 UX 原则"** section

### R3. 教师每人单独账号密码（itsuki 补足 I4）

itsuki 原话: 「每个老师都需要单独的账号密码」

**对现 spec 的影响**:
- `system_features.md §3` = **只定义了学生 ID 规则**（6 桁 学年×組×番号）
- 教师账号规则 = **未定义** → spec 里要补一章

**还要决的事项**:
- 教师 ID 怎么发（职员号？任意 ID？）
- 角色种类（寮監 / 寮務部長 / 寮務課長 / 国際交流部長 / 国際交流課長 / 寮務部教師）
- 初次密码发放运营（谁发？在哪发？）
- 密码重置流程（学生侧规则是"找宿监"，教师呢？ → §7 Q10）
- 共用 PC（事务室 PC, Role D）上是否也强制单独登录

### R4. 寮分别显示（1・2 寮 与 4 寮）

老师原文（日语）: 「1,2寮と4寮を分ける（別表示）」

**现状**:
- iOS 的 SEED 是 `dorm: 'men' | 'women'` 二值（M/W prefix），没有寮编号概念
- teacher_web/round3 也没有寮单位（1/2/4 寮）grouping（grep 0 hit）
- 性别和寮编号的关系不明（女寮 = 2 寮？4 寮 = 男？）→ §7 Q1

**Tomoshibi 侧应对**:
- 数据模型加 `students.dorm_unit` ENUM（例 `dorm_1` / `dorm_2` / `dorm_4`）
- Role D 出寮者一覧 = 按寮分组 + 别 view（打印时也分页）
