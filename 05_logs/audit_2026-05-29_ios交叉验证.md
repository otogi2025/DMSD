## 🔴 上线级核心（4 条，已亲自核实）

### IX-001【C】★已核实★ 点呼按钮根本不发后端
- 位置：`Features/Home/HomeStubs.swift:1435`（点呼按钮只调 `app.recordCheckin()` 本地改状态）+ `Foundation/Network/Endpoints/RollCallAPI.swift`（发后端的 `checkin` 方法**全项目零调用**，是死代码）
- 现象/后果：点呼是整个系统的核心。按钮点完只在手机本地把状态改成「已签到」，后端完全不知道。没被 `#if DEMO` 包住=生产代码。
- ⚠️ 这条 = 系统 bug 专栏已记的 **A-024 / FC-018「仍存在」**，本次第三方再确认。
- 修复方向：点呼按钮成功后必须调 `RollCallAPI.checkin`，拿到后端响应再更新本地状态。

### IX-002【C】★已核实★ 删账号接口后端不存在（卡苹果上架）
- 位置：`Foundation/Network/Endpoints/AuthAPI.swift:52`（iOS 调 `DELETE /api/v1/accounts/me`，注释写明「App Store 5.1.1(v) 强制要求」）；后端 `routers/accounts.py` **只有创建账号、无任何 delete 路由**（全后端 DELETE 路由只有删老师/删公告）
- 现象/后果：用户点「删除账号」必然失败。苹果强制要求 app 提供账号删除，坏的会卡审核。
- 修复方向：后端补 `DELETE /accounts/me` 路由；iOS 删除成功后清会话 + 跳回登录页（当前只清 token 没跳页）。

### IX-003【C】★已核实★ 时间带小数秒导致几乎所有响应解析失败
- 位置：`Foundation/Network/APIClient.swift:89`（`dateDecodingStrategy = .iso8601`，不解析小数秒）+ `Foundation/Network/NetworkModels.swift` 等 **20+ 个 `Date` 类型字段**（submitted_at / decided_at / created_at / checked_in_at / flight_dep_at 等，遍布申请/公告/点呼所有响应）
- 现象/后果：后端 `schemas.py` 全程没做「去微秒」处理（默认带微秒），iOS 的 `.iso8601` 默认不认小数秒 → 任何含时间字段的响应整段解码失败，用户看「加载失败」拿不到数据。**影响面最大的一条。**
- ⚠️ CC 第一轮对抗验证曾误判此条为「反驳成功」，实为真 bug。
- 修复方向：iOS 换支持小数秒的自定义日期解析（`withFractionalSeconds`）；或后端序列化前 `replace(microsecond=0)`。两端选一处统一。

### IX-004【双】修改届对真实用户整个坏掉
- 位置：`Features/StayList/StayListStubs.swift:1234`（load）+ `:1451`（submit）
- 现象/后果：`StayEditForm` 注释标了「仅演示」但**没真的用 `#if DEMO` 包住**，会编进正式版，且只读写假数据 `StayListMock`、不碰真接口。真实用户从详情点「修改届を提出」→ 传入后端 UUID → 假数据里找不到 → 弹「找不到申请」退回，编辑页根本打不开；就算打开提交也只改本地假数据、后端不变。
- 修复方向：load 加 UUID 校验 + 调 `ApplicationsAPI.detail`，submit 调 `ApplicationsAPI.update`；或切回前真的用 `#if DEMO` 包住。

## 🟠 数据错误（12 条）

### IX-013【W】「免餐时段」默认算出来是空，用户以为申报了

### IX-014【W】房间号带字母会拼成双前缀脏数据（A5→MA5）

### IX-015【W】生日设备日历设成和历时会写错年份

- 修复方向：补 `locale = en_US_POSIX` + `calendar = .gregorian`，必要时固定时区。

### IX-016【W】岡山駅（电车站）巴士被误标成「机场班车」
- 位置：`Features/BusList/BusListStubs.swift:73`

- 修复方向：只在路线名含「空港」时才标机场；或数据加明确字段。

## 🟡 逻辑错误（10 条）

### IX-017【双】删除成功却报失败（204 空响应被强行解码）
- 位置：`Foundation/Network/APIClient.swift:119`（delete）+ `:85`（成功分支无条件解码）
- 后果：后端删回复/删账号成功时返回 204（成功但无内容），iOS 强行把空内容解码 JSON 失败 → 报「加载失败」。用户以为没删掉重复操作。
- 修复方向：204 或空 body 直接成功返回，不走解码。

### IX-018【C】外泊同一天，没校验返回时刻晚于离开时刻
- 位置：`Features/Apply/ApplyStubs.swift:386 / 773`
- 后果：只校验「返回日 < 离开日」，没校验同一天时返回时刻要晚于离开时刻。同日 20:00 离校、08:00 返校能提交。
- 修复方向：按完整日期+时刻校验离校早于返校，后端同步补。

### IX-019【W】申请筛选标签漏「要修正/部分通过」两种状态
- 位置：`Features/StayList/StayListStubs.swift:408`
- 后果：筛选标签只有 4 个，精确相等匹配。状态 `.returned`（要修正）和 `.approved_partial`（部分通过）没对应标签。被退回要修正的申请点「差戻」标签看不到，只能在「全部」找。
- 修复方向：「差戻」标签匹配 {rejected, returned}、「承認済」匹配 {approved, approved_partial}。

### IX-020【W】点呼履历「4月/3月/2月」筛选完全失效
- 位置：`Features/MyPage/MyPageStubs.swift:765`
- 后果：点筛选按钮高亮变了，但渲染列表的计算属性没用到选中月份，列表纹丝不动。3月/2月本应空列表，却原样显示 4 月数据。
- 修复方向：渲染前按选中月份过滤记录日期。

### IX-021【W】点歌投稿页必填项空着也能投稿
- 位置：`Features/Community/CommunityStubs.swift:815`
- 后果：曲名/艺术家标了必填（红星号），但投稿按钮不检查这俩是否为空，空着也能点、还弹「投稿成功」。（提交是假动作，真问题是必填标记与按钮矛盾）
- 修复方向：按钮可点条件加「曲名非空 且 艺术家非空」。

### IX-022【W】日历换月显示出不存在的日期（如 4月31日）
- 位置：`Features/Community/CommunityStubs.swift:1287`
- 后果：换月按钮只改月、不调整已选日。5月选31日切回4月，下方「所选日详情」显示「4月31日 予定なし」这个不存在的日期。
- 修复方向：换月后 `selectedDay = min(selectedDay, 当月天数)`。

### IX-023【W】没填备注的特别活动班车被误分类成「通学便」
- 位置：`Features/BusList/BusListStubs.swift:74`
- 后果：用「有没有备注」判断特别便/通学便。5-16「みつ元気プロジェクト」那条没填备注，被错判通学便，特别便筛选里漏掉、通学便筛选里挂错标签。
- 修复方向：数据加明确 kind 字段，或补 5-16 那条备注。

### IX-024【W】点呼弹窗的延时任务会误关后开的别的弹窗
- 位置：`Features/Home/HomeStubs.swift:1432`
- 后果：点呼成功后睡 2 秒无条件关弹窗。用户 2 秒内点背景关掉点呼弹窗、又开了别的弹窗（如体调报告），任务醒来把新开的弹窗关了。（同 IX-011 机制，但点呼版无写数据副作用）
- 修复方向：任务存 `@State` 取消；关弹窗前确认当前还是点呼弹窗。

### IX-025【W】「今月の点呼」统计无视月份、全算进去
- 位置：`Features/MyPage/MyPageStubs.swift:235`
- 后果：卡片标题写「本月点呼」但统计遍历全部记录、不按本月过滤。当前数据全是4月碰巧对，接后端返回多月记录后会把所有月份算进去显示偏大。
- 修复方向：先按当前月份过滤记录日期再统计。

### IX-026【W】客户端长度校验写了从没被调用（死代码）
- 位置：`Foundation/Network/NetworkModels.swift:207`（`StudentAccountCreateBody.validate()`）
- 后果：`validate()` 专为「超长字段本地提前拦」加的，但全项目从没调用，注册直接发后端靠 422 才报错。体验退化 + 死代码。且只查上限没查下限。
- 修复方向：`createAccount` 发请求前调 `validate()`；补下限校验对齐后端。

- 后果：用数组下标当列表「身份」，删中间一行后行身份错位，输入框内容/焦点串到别行。（崩溃已被判断挡住，定性体验损坏）
- 修复方向：改带 id 的结构体数组，用 `ForEach($数组)` 绑定列举，删除按 id。

### IX-033【W】学習履历迟到日显示矛盾（汇总说迟到、日块说准时）
- 位置：`Features/MyPage/MyPageStubs.swift:1962`
- 后果：同一天判定口径不一致——汇总卡看「3次打卡齐+备注含迟到」算迟到，日块只看打卡数=3 就贴绿色「准时」。迟到日两处对不上。（只在演示数据下复现，但逻辑不一致客观存在）
- 修复方向：日块也判断当天是否含「迟到」备注，统一口径。

### IX-034【W】请假次数只在内存累加、不按月清零
- 位置：`Foundation/AppState/AppStore.swift:354`
- 后果：请假提交后计数+1 并弹「今月已休 N 次」，但只在内存、不持久化、不按月清零。跨月还累加，重启又归0，提示数字跟真实当月请假数不符。
- 修复方向：接后端从「当月真实计数」取值；没接通前别写死带数字的断言。

## 🔒 安全（3 条）

### IX-035【W】登录令牌会随手机备份迁移到别的设备
- 位置：`Foundation/Network/KeychainService.swift:41`
- 后果：登录令牌存进 Keychain 用的级别（`AfterFirstUnlock`）会被打包进 iCloud/iTunes 加密备份，恢复备份时能迁移到另一台设备。备份泄露/恢复到攻击者设备 = 令牌跟着过去，相当于绕过登录。
- 修复方向：改成带 `ThisDeviceOnly` 后缀的级别，令牌不进备份、不迁移。

### IX-036【W】过期令牌每次启动仍当已登录直接进主页
- 位置：`Foundation/AppState/AppStore.swift:101`
- 后果：登录响应解码了有效期 `expires_in` 却从不使用；启动只判断「有没有令牌」就当已登录。令牌过期后启动仍进主页，直到某请求收到 401 才被踢回登录，中间「进了主页但全部加载失败」。
- 修复方向：存令牌时一并存过期时刻，启动时过期就删令牌走登录页。

### IX-037【W】保存令牌失败时静默无感知
- 位置：`Foundation/Network/KeychainService.swift:43`
- 后果：`SecItemAdd` 返回的状态码被丢弃，写 Keychain 失败时函数静默返回。app 重启读不到令牌、自动登录失效，且无错误可定位。
- 修复方向：检查 `SecItemAdd` 返回的状态码，失败上抛/记录。
