## 第二次重大转折 — 2026-04-10: 回归日 + NFC/NFD 事件 + 学习哲学根本调整

**触发事件**: 一个月空白后回到项目,想 `git pull` 把 VPS 上的 commits 同步下来,结果遇到 NFC/NFD 编码冲突。

**为什么这是转折**(三层):

### 第一层: 被动回归

不是"打算回来所以回来",是**被一个技术问题强行拉回项目状态**。解决 NFC/NFD 的过程让我重新进入"我是这个项目的开发者"的角色。证明了"即使一个月没碰,我还是能处理复杂问题" — 信心恢复。

### 第二层: 学习哲学的根本调整(最重要)

这一天我主动提出了一个核心决定: **放弃"先学完 Python 再做项目"的传统路径,改为"边做边学 + AI 辅助"**。

**为什么这是根本性的**:
- 这一天之前我以为我失败是"不够用功"
- 这一天之后我意识到是"学习路径本身错了"
- 一个月空白的原因不是懒,是"单独学 Python 没有问题驱动,学不下去"

**配套的反 vibe-coding 三铁律**:
- 每行代码能解释
- 先猜后跑
- 写 dev_log

详见 `learning_path.md` 的"核心学习哲学"章节 + `decision_log.md`。

### 第三层: 建立 AI 协作方法论

这一天还诞生了"做镜子不做回音"的元规则 — AI 不是顺从的执行者,而是有原则的教练。

### 实际产出

- 解决了 Git pull 失败
- 写了第一篇 problem_solving 记录
- 写了第一篇 reflection(面对一个月空白)
- 写了"边学边做"的学习哲学转向

## 第三次重大转折 — 2026-04-12: 架构全面具体化

**触发事件**: 问 AI"NFC 到底怎么工作" + "学校有个老师也在做类似的系统,用二维码"。

**为什么这是转折**: 这一天把**抽象的"用 NFC"**变成了**具体的"怎么用 NFC"**。一连串的设计决定:

1. **NFC vs 二维码** — 不是"都行",而是"NFC 因为防作弊更好"

3. **分阶段上线** — Phase 1 卡 + 后端(最快上线),Phase 2 加 App
4. **播报防作弊** — 从"同学用别人手机代刷"的真实观察,推导出"技术 + 人"的组合设计
5. **点呼机硬件** — 不是 iPad,而是 Raspberry Pi + NFC 模块,贴墙安装

**这次转折的意义**:
- 从"想法"到"蓝图"的跨越
- 第一次有了**可以动手做**的清晰方向
- 原创设计(播报)出现 — 之前都是跟着教程/常识走,这次是自己推导的

## 第七次重大转折 — 2026-05 月中下旬: 从"写出来"到"写对"——质量工程化

**触发事件**: 代码量上来后,5 月中旬一次深度审查列出 131 条问题(findings),开了好几个并行窗口同时修;同期开始固定派 Codex(另一家 AI 编码助手)做"对抗复审"——专门挑我和 CC 改完的代码的毛病,一轮一轮挖到挑不出为止。

## 第十次重大转折 — 2026-06-03 / 06-09: 给一个多月的历史补上可追溯的版本证据链

**触发事件**: 5-11 到 6-02 连续施工一个多月,期间一直没及时打版本标签。6-03 一次性按语义化版本规范回溯补打 v0.8.1 ~ v0.12.0 六个标签;6-09 进一步把规则细化成"一个 bug 一个补丁号、连续功能批次才升次版本号",又补打 32 个标签到 v0.19.3。

**为什么这是转折**: 这是一次"元能力"的演化——不是给项目加功能,而是给项目的**历史本身**加上可追溯的结构。版本标签让"我连续施工了一个多月、每一步做了什么"变成可以用 `git tag` 一行命令调出来的证据链,这对 AC 入試讲"开发过程"是硬通货。

**前后状态对比**:
- 之前: 一个多月的提交记录是一长串没有里程碑标记的流水
- 之后: 每个有意义的节点都钉了版本标签,版本号的升法本身也讲清楚了(补丁号 vs 次版本号的分界)。

## 第十一次重大转折 — 2026-06-05: 老师网页迁到正规前端工程(吸取上一次失败的教训)

**触发事件**: 老师网页原来是一个 29305 行的单文件网页(所有代码挤在一个 `index.html` 里、浏览器现场编译)。6-05 迁移到 React + TypeScript + Vite(三样都是现代前端的正规工具:React 搭界面、TypeScript 加类型检查、Vite 负责打包)。**界面 100% 冻结、逐页原样搬**。

**为什么这是转折**: 关键不在技术升级,在于**这是第二次尝试**。5-26 第一次试着用 Vite 重做老师网页,我做出来的是另一套界面,被我当场否决"这他妈根本不是我的 web"。这次定死铁律"界面一个像素都不改、只搬底层结构",才成功。这是一次"在同一个坑里栽倒过、第二次绕开"的演化。

**前后状态对比**:
- 之前: 老师网页是个能跑但难维护的巨型单文件;上一次迁移因为擅自改界面而失败
- 之后: 迁到模块化的正规工程,实测 17 页全部正常渲染、27 个接口全通、界面跟旧版一致。也撤回了一个错误论据——我曾用"itsuki 零基础维护难"反对上 TypeScript,后来定了规矩:有 AI 辅助维护,"维护能力"不该当成技术选型的约束。

## 第十二次重大转折 — 2026-06-09 ~ 10: 做减法——砍功能 + 上线分两波

**触发事件**: 6-09 拍板 v1.0 上线**分两波**:第一波先把手机 App(iOS + Android)发出去、点呼签到入口先藏起来;第二波等卡 + 点呼机硬件到货后再激活签到。6-10 把整套"清扫 / 罚扫"功能从全部五端 + 数据库彻底删除。

**为什么这是转折**: 前面十一次转折几乎都是"加"——加功能、加端、加质量关卡。这两天是项目第一次大规模"减"。意识到"点呼签到依赖硬件,硬件没到就别让它挡住整个 App 上线",于是把上线拆成两波,第一波只留宿舍生活功能,能先跑起来。清扫功能则因为"不在 v1.0 核心价值里、是边角惩戒机制"被整体删掉。

**前后状态对比**:
- 之前: 想一次性把所有东西(App + 卡 + 点呼机 + 全部功能)一起上线
- 之后: 学会按"依赖关系"和"核心价值"切分——能先上的先上,依赖硬件的挪到第二波,不核心的直接删。**会做减法,是项目从"什么都想要"走向"知道什么最重要"的标志**。

## 补遗二 — iOS 上架冲刺 → 撤回的完整弧(2026-05-07 ~ 22)

**发生了什么**: 5-07 我一时拍板走激进路线 —— 先别管「三端一起上线」的原定计划,iOS 单独冲刺上架到苹果商店,把 iOS + 后端代码物理复制成两份(fork)专门冲上架。结果卡在苹果的上架前验证(Validate)环节两个多星期过不去。5-22 我正式撤回:「不冲刺上架了,先把 1.0 做完整再上架」,把那份 fork 归档删掉、改动并回主项目。

**为什么是节点**: 这是一个完整的「**激进尝试 → 撞墙 → 主动校准**」的故事。它珍贵在「我承认这条路走错了、果断撤回」,而不是为了面子硬撑。我原话总结得很清楚 ——「半冲半停 = 双输」「计划是动态的,不是写死的契约」。

**前后状态对比**:

## 回看这段演变的整体规律

几个重复出现的模式:

1. **大的进步不是线性的,是"跳跃+消化"交替** — 2 月规格冻结是跳跃,3 月空白是消化;4-12 架构具体化是跳跃,4-13 方法论升级也是在消化。
2. **"被逼的"进步往往比"计划的"深刻** — 4-10 NFC/NFD 是被问题逼的,4-13 版本重置是被自己发现错误逼的,都产生了高质量素材。
3. **从"做事"到"改进做事的方式"是重要分水岭** — 4-13 把大量精力放在记录体系、版本管理,看起来"没有推进项目",实际是投资未来几个月的生产力。
4. **原创想法来自现实观察,不是技术学习** — 播报设计不是"学了 AVSpeechSynthesizer 所以想到的",是"看到代刷现象 → 想解决 → 选最简单的方式"。

这些规律本身就是可以在面试讲的东西。
