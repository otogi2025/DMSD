## v0.0.x — pre-git 方案迭代（2025-12，全在 ChatGPT 对话里）

> 这 10 个 tag 都指向 initial commit `3baa168`，2026-04-20 追认

### v0.0.1 — 最初的幼稚想法

- **学生手机当 NFC 卡** — 最初以为手机可以主动发 NFC 信号假装成一张卡（后来才知道 iOS 没这个权限）
- **钥匙二维码 = 学生身份** — 每个宿舍钥匙挂一个二维码牌，扫码完成签到（后来发现截图就能伪造）
- **扣分规则雏形** — 迟到 -0.5 分 / 缺席 -1 分 / 月累计 ≥4 罚扫 / ≥8 禁足。**这是唯一保留至今的部分**
- **扫除拍照 + 加分抵扣** — 学生拍扫除照片，老师审核评分，可抵扣扣分

### v0.0.2 — 第一次方案翻转

- **放弃 HCE**（Host Card Emulation）— 发现 iOS 第三方 App 没有 HCE 权限，"手机当卡"从根本上走不通
- **改为 iPhone 读固定 NFC tag** — 教室贴一张 NFC 贴纸，iPhone 碰一下读取。方向反转
- **session 时间窗** — 老师开点呼 → 系统记"这一场的时间窗" → 学生必须在窗内签到
- **挑战/签名基础模型** — 服务器发 challenge，手机签名返回，防简单抓包

### v0.0.3 — 关键认知突破

- **学 NTAG 424 DNA 的 SDM/SUN 动态认证** — 这种 NFC 芯片每次被读的时候产生不同的数据，不是固定的
- **"静态 ID 不能当凭证"的领悟** — 之前以为有个 UID 就能认人。错。别人复制 UID 就能伪造
- **防重放计数器** — 每读一次计数器 +1，服务器存最新值，复制旧数据会被拒绝

### v0.0.4 — v2 综合方案（第一个"可交付级"设计）

- **设备密钥（Secure Enclave + P-256 ECDSA）** — iPhone 硬件里存私钥，不能导出。签名 = 这台手机签的
- **一次性 nonce** — 每次签到服务器发一个随机数，用完作废，防"拿之前的签到数据重放"
- **事件溯源（append-only）** — 数据库只加不改，所有历史变更可追溯
- **状态机** — present / late / absent / invalid / manual_override 5 种状态，老师改判也走状态机
- **扫除水印** — App 内相机拍照时自动打水印（日期 + session_id + 学生编号），防"拿昨天的照片糊弄"

### v0.0.5 — v2.1：简化 + 定后端栈

- **去 FaceID** — 发现 Android 没 FaceID，强行要求会排除 Android 用户。改用"账号登录 + 设备私钥签名"
- **后端选型** — Python + FastAPI + PostgreSQL + WebSocket。决定用这套
- **内网部署** — 宿舍里自建服务器，不走公网，省成本 + 防外部攻击
- **Android Keystore** — Android 端用系统 Keystore 存私钥（硬件级，不强制 StrongBox）

### v0.0.6 — v2.1 加固版（pre-0.1 最成熟方案）

- **Android enableReaderMode** — Android NFC 读卡的特殊模式，前台读更稳
- **ECDSA 格式统一（DER base64）** — 不统一的话 iOS 和 Android 互相验不了签
- **nonce 预取池** — 弱网环境下"学生请求 challenge → 回应 challenge 过来时已经过时"的悖论。预取一池 nonce 解决
- **内网服务发现** — 路由器静态 DHCP + 内网 DNS + App 内置 Base URL 改入口（方便部署）
- **内网 HTTPS** — 校内自建 CA 或证书 Pinning。不用"自签名 + App 里忽略验证"那种偷懒方法
- **PostgreSQL 备份** — 每日 pg_dump 加密 + 双地点存。防数据丢
- **同教室 2-3 个 tag 并行** — 如果一张 tag 大家挤在门口读，拥堵。多贴几张并行
- **无 NFC 学生兜底** — 没手机或者手机坏了的学生，老师手动签 + 临时设备登记

### v0.0.7 - v0.0.10（2026-02-02 到 02-08）

### 推翻 4-19 G2 两条架构决策

- **D1：静态 NFC 贴纸 → 动态 ST25DV16K** —
  - 原方案：路径 B 用被动 NFC 标签，签名 + nonce 防代签在 App 端
  - 发现漏洞：**学生可以用 NFC Tools App 读真贴纸 → 拿到静态 URL → 复制到自己空白贴纸 → 在宿舍房间 tap 就能完成"签到"**。签名只能证明"A 用自己的设备签"，不能证明"A 在点呼机前面"
  - 新方案：**ST25DV16K 可写 NFC 芯片 + 点呼机每 10 秒通过 I²C 刷新 URL（含一次性 nonce）**。URL 复制 10 秒后作废
  - 成本：¥100 人民币 × 4 台 ≈ ¥2000 日元。**我选最贵但彻底的方案**，不选 AI 推荐的"BSSID + 老师人防" 省事组合
- **D2：取消"一设备一账号" → 老师面签** —
  - 原方案：一个学生账号只能绑一台设备，换机要老师后台审批
  - 问题：学生换手机麻烦 + 设备指纹靠不住
  - 新方案：**任意设备都能签名 + 入学日老师扫码面签确认**。面签 = "我认这张脸就是这个学号的学生"，后面系统的签名都算合法

### 技术细节层（议题 A 落地）

- **iPhone 路径 = BTR + Universal Link + AASA** —
  - BTR（Background Tag Reading）= iOS 11+ 的功能，学生手机靠近 NFC 贴纸，系统自动唤起 App
  - 学生操作从"前台读"的 7 步（亮屏 → 解锁 → 找 App → 打开 → 进页面 → 按按钮 → tap）缩到 2 步（拿出手机 → tap）
  - 需要配套：正式 HTTPS 域名（如 dmsd.otogi2025.com）+ AASA 文件
- **点呼机硬件 = Pi 4B 2GB × 4 台** —
  - 4-15 的 Pi 型号留白，这次敲定。¥300 × 4 = ¥1200 人民币 ≈ ¥24000 日元
  - 不选 Pi Zero 2 W（GPIO 要焊接，一个人开发学习成本高）
  - 不选 Pi 4B 4GB（点呼机只搬运数据不需要大内存，过度配置）

## 关于 git tag 的查看方式

```bash
git tag | sort -V              # 版本号正序（推荐）
git tag -l "v0.3.*"             # 过滤某个系列
git show v0.3.2                 # 看某个 tag 的信息 + 指向的 commit diff
```

**GitHub 的 Tags 页面默认按 creation time**，不按版本号，所以会看到视觉跳跃（例如 v0.0.10 → v0.3.1 相邻，因为 v0.0.x 是后补追认的）。要看语义版本顺序用 `git tag | sort -V`。
