### F1 — admin_accounts 3 端点缺寮边界过滤（采纳，修复 3 个，遗留 11 个）

**问题**: `GET /students`、`POST /students/{id}/password-reset`、`POST /students/{id}/unlock-account` 三个端点在权限分级后 M 组老师都能访问，但没有按老师所属寮过滤，一般宿管可读/改其他寮学生。

**CC 独立核实**: git diff 对比 `63f9cfc` 前后 20 个路由文件的 `dorm_units_for_teacher`/`demo_scope` 调用数，确认只有这 3 个端点的过滤调用数从非零降为零（F1 是真问题）；另 11 个端点之前就没有寮过滤，是「预存在问题」不是本次引入，不在本次范围内修。

**修法**: 新增 `_assert_student_in_dorm(teacher, student)` helper（403 FORBIDDEN_DORM）；`list_students` 在查询语句加 `dorm_units_for_teacher` 过滤；`password_reset` / `unlock_account` 拿学生后立即 `_assert_student_in_dorm`。

**提交**: `718cced`

### F2 — renewal-start 端点漏挂 require_permission（采纳）

**问题**: `student_promote.py` 的 `/renewal-start` 端点仍用旧的 `require_teacher_roles(*_ADMIN_ROLES)`，没有迁移到 `require_permission(C_STUDENT_ACCOUNT, MANAGE)`。

**修法**: 删 `_ADMIN_ROLES` 常量，改挂 `require_permission`，import 更新。

**提交**: `4cb86b1`

### F3 — required_reason 字段可不填（保持现状）

**问题**: codex 指出某端点 `required_reason` 可选，认为应强制。

**CC 裁决**: itsuki 拍板保持可不填 + 职位回退——这是有意设计，不是遗漏。**不修**。

### F4 — delete_teacher 最后管理员保护用错集合（采纳）

**问题**: `TEACHER_ADMIN_ROLES = {"寮務部長", "寮務課長", "寮監"}` 判断「当前活跃老师里还有没有管理员」。但这个集合有两个错误：寮監 实际映射到 一般宿管+晚自習（只有 VIEW 权限，不是真管理员）；校長 映射到 寮管理者（有 MANAGE 权限，但不在集合里）。

**修法**: 新增 `_has_teacher_account_admin(teacher)` 函数（按 `effective_group` + `C_TEACHER_ACCOUNT >= MANAGE` 判断）；删除端点遍历活跃老师、Python 侧计数替代旧 SQL 角色过滤。

**提交**: `b217453`

### F5 — 学習担当 fallback 组错误（采纳）

**问题**: `ROLE_DEFAULT_GROUP` 映射把 `学習担当` 指向 `申請承認専用`（审批专用，无学生账号管理权、无普通操作权），但 学習担当 是管晚自习的老师，应该有对应权限。

**itsuki 决定**: 改映射到 `一般宿管+晚自习`。

**修法**: `permissions.py` ROLE_DEFAULT_GROUP 改一行；alembic 迁移回填同步；`gakushu_promote` 测试夹具显式设 `permission_group="申請承認専用"`（防测试依赖已变更的 role fallback）。

**提交**: `2087587`（fix）+ `8f3e854`（留痕）+ `d1291db`（TODO 上线警示）
