# dev_log 工程简报 — 格式说明

> **这是什么**：`05_logs/dev_log/` 是 DMSD 的「今天到底改了哪几个文件、修了什么 bug」纯工程流水账。
>
> **为什么有这个**：2026-06-08 itsuki 拍板复活。原因 —— 收尾流程严重偏向 AC 素材（`05_logs/raw/` 给筑波入试用的叙事「我怎么想的」），导致「实际做了什么」被叙事淹没、记不住。dev_log 把工程事实单独拎出来，一屏看完。

---

## 铁律：跟 AC 素材物理分开

| 文件 | 写给谁看 | 内容 |
|---|---|---|
| `05_logs/dev_log/YYYY-MM-DD.md`（本目录） | **itsuki 自己** | 纯工程事实：改了哪些文件、修了什么 bug、跑了什么验证、commit 清单 |
| `05_logs/raw/YYYY-MM-DD.md` | 给教授看的素材池 | AC 叙事：怎么想的、为什么这么选、学到什么、模式分析 |

**dev_log 里绝对不写的**（这些全留给 raw/）：
- ❌ 「学到什么」「AC 价值」「AC 入試 5 核心问题自检」
- ❌ 模式分析（模式 1-6）/ 思考层数 / 认知改变叙事
- ❌ itsuki 原话引用 + 内心活动

dev_log 只回答一个问题：**今天这个项目的代码 / 文档，客观上变了什么。**

> 历史背景：4 月中旬之前 dev_log 也混了大量 AC 内容（看 `2026-04-15_*.md` 最后的「学到什么」「AC 入試 5 核心问题自检」），结果跟 raw 重叠、4-15 后停笔废弃。这次复活砍干净，只留工程事实，避免重蹈覆辙。

---

## 命名

- 默认 `YYYY-MM-DD.md`（一天一篇）
- 同一天多个独立主题想分开 → `YYYY-MM-DD_主题.md`
- 同一天同会话延续 → append 到当天那篇

---

## 格式模板（CC 收尾时按这个自动生成）

```markdown
# YYYY-MM-DD 工程简报

**类型**: dev_log / 工程流水账（纯工程事实，AC 素材见 raw/YYYY-MM-DD.md）

## 改了什么
- `文件路径` — 这文件干嘛的 — 改了啥（一句话）
- ...

## 修了什么 bug
- 症状 → 原因 → 怎么修的（一行一个，没修 bug 就写「无」）

## 跑了什么验证
- 跑了什么命令 / 测试 / 编译 + 结果（绿/红）。没验证就写「无」

## 本日 commit
- `hash 短码` 一句话 commit message
- ...（当天的 commit 全列，从 git log 抓）

## 没做完 / 留到下次
- ...（跟 TODO.md 呼应，没有就写「无」）
```

---

## 数据从哪来（CC 生成时）

1. **改了什么 / commit** → `git log --oneline --since="今天0点"` + `git diff --name-only` 抓当天动过的文件
2. **每个文件干嘛** → CC 已知 / 查 project-overview skill
3. **bug / 验证 / 没做完** → CC 从本会话上下文里抓

关键：**尽量从 git 自动抓，CC 别手写长篇**。上次 dev_log 废弃就是因为手写太累 —— 这次让它便宜到不会再死。
