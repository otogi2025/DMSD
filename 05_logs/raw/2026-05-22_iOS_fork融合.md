## 21:45 [问题解决 / 自己认识] xcodebuild 戳穿「Bot 1 闯祸 30+ 编译错误」是 SourceKit 误报

### 背景 / 触发

TODO §🔧「Bot 1 闯祸 — 30+ iOS 编译错误」+ itsuki 上次选「(c) 自己看」状态。

CC 改完 5 个文件后跑实际编译验证。

### 经过

```bash
cd 03_dev/student_ios/v1
xcodebuild -project TomoshibiApp.xcodeproj -scheme TomoshibiApp \
  -sdk iphonesimulator -configuration Debug \
  -destination 'generic/platform=iOS Simulator' build
```

**结果**：
- ✅ Swift 编译阶段全部通过（日志显示 `Ld __preview.dylib normal arm64` 链接成功 + `CreateUniversalBinary` 通用二进制创建成功）
- ❌ actool 资源编译失败 — `No simulator runtime version available`（iOS 模拟器系统版本不匹配，跟 Swift 代码无关）

**真相**：
- Xcode 编辑器里看到的「30+ 编译错误」全是 **SourceKit（Xcode 单文件代码检查器）的误报**
- SourceKit 单看一个 .swift 文件时不知道其他文件里定义的类型（`RouterStore` / `AppStore` / `T` / `SEED`）
- 真实 xcodebuild 编译时同模块下能找到 → 不报错

itsuki 上次大概看到 Xcode 编辑器一堆红线就以为是真编译错误，所以选「(c) 自己看」搁置。

### 关键判断 / 学到的东西

- **编辑器红线 ≠ 真编译错误** — 这是 iOS / Xcode 开发的基础认知
- **xcodebuild 命令行验证** 才是真实编译结果（SourceKit 是 IDE 单文件辅助检查）
- **教训**：iOS 工程报「编译错误」前先跑 xcodebuild 验证一遍，再判断是否真问题

### AC 价值

- 对应核心问题：#3 問題解決 + #5 自己認識
- 展示了什么：
  - (a) **CC 主动诊断 unknown unknowns**（feedback 主动诊断 memory）— itsuki 不知道「编辑器红线 ≠ 真编译错误」
  - (b) Bot 1 闯祸事件的真相不是「30+ 编译错误」，而是「编辑器索引误报」 — 完全相反的结论
  - (c) 工具链分层认知（SourceKit 单文件 vs xcodebuild 全编译）— iOS 工程必备
