## 中午 [模式 2 / 失敗修正] VPS CC 找到 backend 3 个隐藏 bug — itsuki 5-04 写代码时遗留

### 背景

VPS CC 部署 backend 时连续踩 3 个 bug，**每个都是真问题**（不是 CC 失误，是 5-04 backend 实装时的设计 bug）：

### Bug 1: `alembic/env.py` 不读 env DATABASE_URL

- **现象**：alembic migration 跑到 `alembic.ini:89` 硬编码的 SQLite，**Postgres 一张表都没建**
- **根因**：alembic 默认配置写 ini 文件，env.py 不会自动读环境变量
- **修法**：env.py 加 4 行 `os.environ.get("DATABASE_URL")` 覆盖

### Bug 2: `docker-compose.yml` 不传 `APP_ENV`

- **现象**：alembic 修好后再跑 → 18 张表创建了但 alembic_version 表没有
- **根因**：api 容器内 `APP_ENV` 不存在 → fallback 到 `app/config.py:21` 默认 `"dev"` → `app/main.py:70` 跑 `create_all()` 绕过 alembic
- **修法**：`APP_ENV: ${APP_ENV:-production}`

### Bug 3: migration 文件用 SQLite-only 的 `batch_alter_table(recreate='always')`

- **现象**：`alembic/versions/b2c3d4e5f6a7_align_application_schema.py` 在 Postgres 上 DROP applications 表撞外键
- **根因**：itsuki 5-04 用 SQLite 写 migration，没考虑 Postgres
- **修法**：dialect-aware（SQLite 保留 batch / Postgres 用普通 op.xxx）

### 模式 2 关键

- **CC 假设崩了 → 继续调查 → 真因**：第 1 个 bug 修完跑 → 18 张表出现 → 假设「成功了」 → VPS CC 检查 alembic_version 表 → 发现没有 → 真因是 create_all() 绕过
- 这是合格者最爱的「假设崩了但没放弃」模式

### Mac fork 同步修

CC 立刻把 4 处修复（alembic env.py / docker-compose APP_ENV / .env.example 注释 / Dockerfile -w 2）应用到 Mac fork，防下次 rsync 回退。

## 晚上 [模式 1 / 失敗修正] Xcode 编译链式踩坑 — iOS 26 → 18 降级 + Validation Version empty

### 踩坑 1: `\.supportsImagePlayground` iOS 18.1+ only

- 现象：Build Failed `'supportsImagePlayground' is only available in iOS 18.1 or newer`
- 修法：把 `@Environment(\.supportsImagePlayground)` 改成 `private let supportsImagePlayground = false`（v1.0 禁用 AI 头像生成）
- **CC typo bug**：第一次改写成 `supbportsImagePlayground`（多了 b）→ 编译又报 "Cannot find in scope" → 二次修

### 踩坑 2: `.imagePlaygroundSheet(...)` modifier 同样 iOS 18.1+

- 现象：第一次 fix 后 Build 还失败
- 修法：删整段 `.imagePlaygroundSheet(...)` block（即使 `showImagePlayground` 永远 false，编译器对 modifier 做静态可用性检查）

### 踩坑 3: Archive Validate 失败 — CFBundleShortVersionString empty

- 现象：Validation failed, `CFBundleShortVersionString is empty` + `CFBundleVersion is empty`
- 根因：CC 5-07 在 `project.yml` 用 `INFOPLIST_KEY_CFBundleShortVersionString` 写法，**Xcode 26 + xcodegen 26 对这两个 key 不识别**
- 修法 A（CC 改 fork）：改 yml 用 `MARKETING_VERSION` + `CURRENT_PROJECT_VERSION`（Xcode 14+ 现代标准）
- 修法 B（itsuki 操作）：在 Xcode General tab 直接填 Version: 1.0.0 / Build: 1（最快路径，绕过 yml 重 generate）

### 教学

CC 解释了 Xcode 14+ 引入的现代 build setting 写法：
- `MARKETING_VERSION` → Info.plist 自动写 CFBundleShortVersionString
- `CURRENT_PROJECT_VERSION` → Info.plist 自动写 CFBundleVersion

**比 INFOPLIST_KEY_* 写法靠谱**（后者在 Xcode 26 + xcodegen 26 不生效）。

### AC 价值

- **对应核心问题**：#3 問題解決 + #4 失敗と修正
- **展示了什么**：
  - 链式踩坑（iOS 26 → 18 降级触发 3 个连锁问题）
  - CC 也会犯 typo（supbports）— itsuki 截图能看到错误，但实际 review 是看代码细节而不是依赖 CC 的话术
  - 不同 Xcode 版本对同一 build setting 的不同支持 = production 工程经验
