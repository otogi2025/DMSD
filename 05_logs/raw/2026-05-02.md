### #AC候选 ⭐⭐ JWT Keychain vs UserDefaults — CC 主动诊断 unknown unknown

**金句**（CC 主动告诉 itsuki）：「**UserDefaults 是明文 plist、越狱机能直接读、JWT 这种机密放进去不安全。业界标准是放 Keychain**」

**背景**：iOS 网络层建设到 commit 3（KeychainService）时，CC 按 §对话规则 §7 主动诊断告诉 itsuki：
- itsuki 不知道：UserDefaults 是明文存储
- itsuki 不知道：JWT token 这种 credential 跟普通 user data 应该分级保护
- itsuki 不知道：iOS 系统自带 Keychain 这种硬件加密的 secure storage
- itsuki 不知道：`kSecAttrAccessibleAfterFirstUnlock` 等访问控制 attribute

CC 给 itsuki 解释:
- 类比：UserDefaults = 你电脑桌面的 .txt 文件 / Keychain = 银行保险箱

### §9.2 装机 + 工程脚手架

1. **brew 单线程下载 Android Studio dmg = 0.07 MB/s → 6 小时**（Google CDN 对日本节点限速）

### §9.6 ⭐⭐⭐ 4 会话并行架构（最大 takeaway）

发现单会话连续做 22 屏视觉对齐 iOS = 10-30 小时编码 = 不可能一次完成。

**当场提出**：「我要四个会话同时运行，把任务分成四份」。

CC 设计具体架构（我做的判断 = 接受这个架构）：

```
预启动（main 上提交基础）:
  - data layer 升级 (Models + MockData 060218 真值)
  - 4 contract stubs (GlobalScaffold / RollCallSheet / HomeCards / TopRollBar)
    - 空壳但 API 签名对，让依赖它们的 B/C/D 编译能过
  - push 到 main → 4 worktree 都 base on 这个 commit

git worktree × 4 (同 repo 不同分支，互不冲突的 working tree):
  - ~/dev/tomoshibi-A → feature/A-infra (基础设施)
  - ~/dev/tomoshibi-B → feature/B-auth-home (Auth + Home omnibus)
  - ~/dev/tomoshibi-C → feature/C-apply-mypage (申し込み + MyPage + 通知 + 减点)
  - ~/dev/tomoshibi-D → feature/D-community (Community 7 屏 + NFC)

4 prompt 文件 (写在 ~/.claude/plans/):
  - 每个 self-contained (告诉 agent 必读哪些文件 / 任务清单 / 文件白名单 / 黑名单)
  - 关键: ABSOLUTELY 不能动列表 (避免误改其他会话负责的文件)

我手动开 4 个 terminal 窗口 → cd 到对应 worktree → claude 启动 → 粘贴对应 prompt
4 会话同时跑约 2-4 小时 → 各自 commit + push 到 feature 分支

最后由 CC 帮我 merge 4 branch → main → installDebug → 截图比对 iOS
```

**关键发现 / 学到**：

1. **git worktree 这个工具我之前完全不知道**。`git worktree add ../foo branch-x` = 同一个 repo 在不同目录有独立 working tree（共享 .git/）。**比 4 次 clone 高效 + 共享 git 历史**。
2. **Contract stub 模式**：B/C/D 依赖 A 写的组件（GlobalScaffold 等）。如果 4 真同时 spawn → B/C/D 编译失败（找不到 class）。解决 = 提前在 main 推空壳（API 签名对、内部 placeholder）→ B/C/D 用 stub 写代码 → A 后期填真功能 → merge 后自动升级。**这是 contract-first design** — 大型软件公司多团队协作的标准做法，今天第一次自己用上。
3. **冲突避免靠文件白名单**：4 个 prompt 各自有「ABSOLUTELY 不能动的文件」清单。4 会话改的文件**零交集**。最后 merge 4 branch 实测 0 conflict。
4. **emulator 互斥处理**：4 会话不能同时 install + run（emulator 只一个）。规定每个会话只 `./gradlew compileDebugKotlin` 验证编译，不 install。最后由我（CC）merge 后单一次 installDebug。

**#AC候选 ⭐⭐⭐ 「4 会话并行架构」 — 对应核心问题 #1 + #3 + #4 全部 3 问** —
- #1 為什麼做：单会话 10-30 小时不可行 → 必须并行

- #4 学到了：第一次知道 git worktree / 第一次理解 contract-first / 第一次自己设计 4-way 并行架构
