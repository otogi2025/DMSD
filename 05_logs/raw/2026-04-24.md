## §2 決策 · 両前端会真上線 + demo 捷径必须删干净 ⭐

itsuki 2026-04-24 原话：

> 「虽然我现在一切都是为了给老师演示才做成现在这个样子的，但是这两个前端，Web 和 APP 的前端，我大概率也会真的拿去用。然后现在我们为了演示方便，加了一个长按那个卡片就可以改我们的信息、改接下来点呼、然后迟到之类的展示。把这个记好，免得到时候等正式版上线了，结果忘记删这个功能了。」

**拍板**：
1. Tomoshibi iOS（`~/dev/TomoshibiiOSApp/`）+ teacher_web/round3 演示后直接产品化基础，不重写
2. 演示用 demo 捷径（客户端自走 rollState 等）**必须在 v1.0 产品化前全部删掉**
3. 建索引：
   - 项目 memory `project_demo_scaffolds_to_remove_before_v1.md`（清单）
   - 项目 memory `project_frontends_headed_to_production.md`（两前端方针）
   - TODO.md §🔴 高优先级 加了一条跟踪项

**Why 这是 AC 素材**：
- 体现"时间压力 vs 安全"取舍意识：为了 4-28 demo 做了前端伪造状态机，但主动识别这是风险，落到文档里防漏
- 展示系统设计思维：「rollState 变化必须由后端 NFC event 驱动，客户端不得自主修改」是 v1.0 设计原则

## §4 Demo 前 pre-flight check ⭐

**Tag**: `#AC候选 #过程 #工程方法`
**对应 AC 核心问题**: #3 问题解决（AI 并行 agent 编排）+ #4 自己认识（承认我一人改不完这么大的代码量）

**动机**：明后天给老师 demo。iOS + Web 两前端今日变动巨大（iOS +800/-163 × 10 文件、Web +2441/-366 × 12 文件），一个人现场改代码 + 看 bug 几乎不可能。决定**用 3 个并行 Explore agent 分头扫**，主会话不碰同文件，结果回来再 diff 优先级执行。

**分工**（三个独立 Explore agent，后台并行）：
1. **iOS bug + 逻辑漏洞**（范围：`~/dev/TomoshibiiOSApp/TomoshibiApp/` 全仓）
2. **Web teacher bug**（范围：`teacher_web/round3/Tomoshibi_v3_single.html` + src）
3. **日语自然性**（范围：两仓所有日语 UI 文案）

**耗时**：3 agent 并行，约 2-3 分钟出结果。串行跑要 10+ 分钟 × 3 主会话上下文爆炸。

**findings**：
- iOS: **14 findings**（P0×2 / P1×4 / P2-P3×8）
- Web: **8 findings**（🔴×3 / 🟠×3 / 🟡×2）
- 日语: **18 findings**（🔴×4 / 🟡×8 / 🟢×6）

**最致命的 3 处**（demo 现场一露馅就尴尬）：

1. **リュウ イヒ 数据自相矛盾**：Web `gender: 'female'` + `dorm: 'men'` + `room: 'M101'` — 女の子が男寮に？老师会问。同时 Web 账号 `060217` 但 iOS 是 `060218`，手机和老师屏对不上
2. **「審核」日本語に存在しない中国語**：iOS ApplyStubs 5 处 / AuthStubs 2 处「宿監」是寮舍旧说法 — 日本教职员看到就 low
3. **RegisterDone 硬编码「ようこそ、リュウ イヒ さん」**：若 demo 现场让老师试注册别的名字，欢迎页仍显示「リュウ イヒ」 → 前端假货被识破

**AC 素材价值**：
- 证明"已经到交付前 24 小时"的 pressure test 意识：不是自嗨写完就算完，而是 adversarial 地找自己作品里能让评审皱眉的地方
- AI 并行 agent 的编排能力：把"大仓看 bug"这种人脑 O(n) 的任务并行拆到 3 agent，再 synthesize = 一个人做工程师+团队管理的范式
- 中日双语 gap 的自觉：自己写日文容易无意识保留中式表达（審核 / 宿監 / 合宿误用），所以特地开一个 "日语自然性 agent" 把自己代码当外文文档 review

## §附：demo 当天 cheat sheet（给 itsuki 备着）

**iOS app 演示顺序**：
1. Splash 2 秒（灰→红火焰）
2. Onboarding 3 屏（NFC 点呼 / 申請 / 生活） — 新用户第一次看
3. Login 输入 `060218` + 任意密码 → Home
4. **长按黄卡 0.6 秒** → 循环切 6 态（平常 → 点呼中 3:00 → 0:10 → 遅刻 → 欠席 → 時間内 done → 自动回平常）
5. 中央 ⭐ 点呼按钮 → RollcallSheet（Liquid Glass）
6. 底部「申し込み」→ 外泊申請 8 section
7. 「マイページ」→ 個人情報編集 → 改学年，保存后看変更履歴

**老师 Web 演示顺序**：
1. 管理员登录 → 点呼 landing
2. 开始点呼 session → 7 秒延迟 → 座位表
3. iOS 碰 NFC / Web demo console → 学生卡片变绿
4. 外宿学生（ヨウシエン）显示「外宿 04-19〜04-22」而非 late
5. session 结束 → 扣分自动记录

**Demo 现场备答口径**：
- 「这个长按切点呼状态的功能是 demo 限定的，正式版会由 NFC 硬件事件驱动」
- 「4.5 点是月累计扣分，规则是迟到 0.5 / 缺席 1.0，月满 4 点罚扫除、8 点外出禁止 — 这个阈值表可后台配置」
- 「老师通过 Web 看到学生实时状态，iOS 学生看到自己的点呼倒计时和罚分详情 — 两端数据同一后端权威，前端只是 view」
