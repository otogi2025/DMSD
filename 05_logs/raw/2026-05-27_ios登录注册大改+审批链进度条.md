## 20:50 [问题解决] Xcode 没识别 APIErrorPresenter.swift — pbxproj 文件清单漏注册

### 背景

```
03_dev/student_ios/v1/TomoshibiApp/Foundation/Network/APIErrorPresenter.swift:1

```

文件存在但 grep pbxproj 找 `APIErrorPresenter` → 0 处。**确认 = 别的会话新建文件后忘加到 Xcode 项目清单**。

修法：用 Python 生成 2 个 24 位十六进制 ID（AC2188E6673E4A1E8567DE96 / 94F434359A574DD1A999B77D），照旁边 `APIClient.swift` 的注册模式手动 Edit `project.pbxproj` 4 处：

1. PBXBuildFile 段加 build 引用
2. PBXFileReference 段加文件引用
3. Network 文件夹组加 fileref
4. Sources 编译阶段加 buildfile

### 关键判断 / 学到的东西

**Xcode 项目结构关键认知**：`.swift` 文件放磁盘上**不够**，必须在 `project.pbxproj` 注册 4 处（build 列表 + 文件清单 + 文件夹分组 + 编译阶段）。新建文件只用 Finder 复制粘贴 = Xcode 看不到。

正规做法：Xcode 里右键 Add Files → 自动加 4 处。手动改 pbxproj 是补救（别会话遗留场景）。

- **对应核心问题**：#3（问题解决 — 别会话遗留问题 + 现场补救）

## 21:05 [设计决策][技术判断] 申请履歴审批链 UI 改造 — 役职名 chip → 进度横线 + 无名节点

- 节点下方一条横线 — 底层灰色，上层绿色覆盖已通过部分
- 进度公式 = `approvedCount / total`
- **无论 approve 顺序如何**，进度只往右填
- 任一节点 rejected → 整条进度横线变红

同步改 2 个文档：

1. `IOS_DESIGN_LOG.md §11.9 I11` 加「2026-05-28 进度条样式拍板」补充段

### 关键判断 / 学到的东西

UI 设计原则：**「明了」≠「不丑」**。

带役职名 chip 链确实信息密度高（一眼看到谁批了谁还没批），但：

1. 5 役职文字宽度差异大（「担任」2 字 vs 「国際交流部長」7 字）= chip 宽度不齐
2. 横向排列文字密集 = 视觉拥挤
3. 列表卡片不需要 inline 显示役职名 — tap 节点弹出役职名+决定时间就够

→ 直观传达「N / total 通过」用进度条形式比文字 chip 更合适。
