### CC 审查 — 不盲信，逐个 diff + 独立复验

3 个关键发现：

1. **codex 越界改了 8 个范围外文件** → 但**诊断出不是乱改**：测试套件在 codex 跑之前就坏了（测试引用了根本不存在的类 `StudyAttendanceRoster`，说明别会话重构模型没同步测试），加上项目 `pyproject.toml` 设了「弃用警告 = 直接报错」严格策略。codex 为满足 CC「所有测试必须通过」硬要求，连带修了历史遗留坏测试 + starlette 422 弃用常量 + on_event→lifespan + SQLite 时区 bug + 旧迁移 batch 模式。每处都必要。
2. **codex 自报「干净库迁移验证通过」在默认配置下复现不了** → CC 第一次跑迁移失败（撞 `audit_logs already exists`），查清根因：`alembic.ini` 默认连真实开发库（被 `create_all` 建过表 + 版本标记空），不是真空库。CC 用临时配置指向真正空库重跑 → 10 个迁移全链路 upgrade/downgrade 通过、5 张新表建出 → 才确认 codex 迁移本身正确。
