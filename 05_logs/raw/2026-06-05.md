## 09:00 [问题解决][技术判断] 代録出寮届网页表单实装 + 三路审查

### 背景
无人值守那轮做了「老师代学生补录出寮届」的后端接口（POST /applications/by-teacher），但网页表单没做。itsuki 醒后提供实物纸质申请表（届け類.pdf 样式3-2 外泊 / 3-3 帰省）让 CC 参照，要求做出表单。

### 经过
CC 先摸清后端能存哪些字段（数据库 Application 表 + KisheiCreateIn/GaihakuCreateIn/KikokuCreateIn schema），发现一个**权限不一致的坑**：代録接口允许 5 角色（_DAIROKU_ROLES），但现有「列学生」的 admin 接口只允许 3 角色 → 寮監/寮務一般教師 能代録却拉不到学生选择器。CC 没默默用现有接口，而是新建 GET /applications/proxy-candidates（权限对齐代録 5 角色 + R4 寮边界），把事做对。

表单字段照抄学生 iOS 侧 ApplyStubs.swift（交通手段选项、食事不要期间展开算法 expandMealsSkip）保证三端口径一致。

### 关键 — 三路审查发现并修一批 bug
做完后 itsuki 要求「派 Codex 审 + 自己也审 + 用 workflow」。CC 跑了三路并行：
- **CC 自审**：自己读代码发现错误提示取值路径写错（`e.body.detail.code` 应是 `e.code`，client.js 把后端错误铺平到顶层）——这是 CC 主动发现，agent 审时已读到修正版反而判它误报，印证修对了
- **workflow（24 个子代理）**：21 个原始发现，对抗验证后确认 11 个、驳回 10 个误报。真 bug：todayStr 用浏览器时区算今天（非日本时区电脑会错）、提交后字段不重置连续代録串值、出租车预约时刻直接套用出寮时刻（iOS 有独立输入框）
- **Codex（gpt-5.5 xhigh）**：6 条，独有发现「帰寮时刻只比日期不比时刻」（同天 17点出/8点回能提交）+ 「注释里有日语假名违反中文铁律」

## 12:00 [认知改变][学习] HTML / Vite / Next.js 三档区别 — itsuki 从不懂到理解前端架构光谱

### 背景
itsuki 问「一般大家做网站用 html 还是 vite 还是别的？」+「第二档和第三档的区别我不明白」。这是他对"现代前端工程到底怎么分层"的认知空白。

### 学到的东西
CC 讲了三档：① 纯手写 HTML（简单静态页）② 框架+构建工具（React + Vite，现在主流）③ 全栈框架（Next.js，服务器端渲染）。

itsuki 不懂第二三档区别 → CC 用「宜家家具」比喻讲清核心差异：**区别在"网页在哪台机器上被组装"**——
- 第二档（React+Vite）：服务器发零件，**用户浏览器自己组装**（客户端渲染）
- 第三档（Next.js）：**服务器先组装好再发**（服务器端渲染），首屏快 + 搜索引擎能读到内容

并定位 itsuki 现在的老师网页是"HTML 单文件 + 浏览器内编译 React"的过渡写法（做原型常见、正式产品很少这么做）。

### itsuki 原话
> "第二档和第三档的区别我不明白"

### AC 价值
- 对应核心问题：#5 自己认识（认知边界拓展）
- 展示：itsuki 通过 AI 协作理解了前端架构的分层光谱（从"只会改一个 HTML 文件"到"理解客户端渲染 vs 服务器端渲染的本质区别 + 各自适用场景"）——典型模式 5「原本不知道 → 通过 AI 知道 → 能据此做架构决策」
- 模式 5（认知改变，itsuki 主线）

## 14:00 [设计决策][技术判断] 老师网页迁 React+TS+Vite + 邮件换 Resend

### 决策一：老师网页从 HTML 单文件迁到 React + TypeScript + Vite
itsuki 选了"现在就迁（不先用 HTML 上线）"+"一步到位上 TypeScript"。

**关键是吸取 5-26 失败教训**：上次有人做 Vite 迁移被 itsuki 否决（"这他妈根本不是我的 web"），根因不是技术是产品方向——重做了一套全新界面。CC 派调研员查清失败原因后，把"界面 100% 冻结、逐页原样搬、绝不重新设计"立成这次迁移的头号铁律。

为什么选 Vite 不选 Next.js：老师网页是内部管理后台，不需要被搜索引擎收录，Next.js 最大卖点（服务器端渲染 + 搜索引擎友好）用不上。

### 决策二：邮件服务 SendGrid → Resend
SendGrid 2025 春取消永久免费，60 天后 19.95 美元/月。itsuki 要求"永久免费或自建"。CC 查证后给三选项：永久免费第三方（Brevo 300封/天、Resend 3000封/月）vs 自建（技术能搭但投递率是大坑——自建 IP 没信誉、邮件易被判垃圾、云服务器常封发信端口）。itsuki 定 Resend。

### itsuki 原话
> "B"（选"现在就停下功能开发、先迁到 Vite"）
> "现在一步到位上 TypeScript"
> "用Resend可以"

### AC 价值
- 对应核心问题：#2 技术判断 / #4 失败与修正
- 展示：① 模式 3（失败→吸取教训）——5-26 Vite 失败的复盘直接转化成这次迁移的铁律，不是重蹈覆辙 ② 模式 6 取舍——Vite vs Next.js 按"是否需要搜索引擎"判断、邮件按"永久免费 vs 自建投递率风险"判断 ③ itsuki 听完投递率风险后没头脑发热选自建，选了务实的 Resend
- 已立 memory：project_teacher_web_vite_migration
