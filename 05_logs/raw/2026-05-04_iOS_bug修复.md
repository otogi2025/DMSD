## §2 ⭐⭐⭐ AC 候选 ——「暗夜模式黑闪」`.preferredColorScheme(nil)` 跟随系统的语义陷阱

**模式**：模式 1（问题→分析→解决）+ 模式 5（不知道 SwiftUI `nil` = 跟随系统这个 API 语义）  
**思考层数**：4 层（症状 → 假设系统 dark → 验证 → 根因 + 修复）  
**对应 AC 核心问题**：#1 / #3 / #5

### 背景 / 触发

itsuki 真机使用反馈：

> 「我把这个 APP 上传到我的手机以后，我的手机白天的时候正常使用没有问题，用这个 APP 同模习笔，但是到了晚上，我点某个页面的时候就会黑一下，然后再回到，再去到那个页面，这个黑的时间有点长，很影响观感。是不是因为暗夜模式之类的？而且现在我也没上线暗夜模式啊」

itsuki 自己已经怀疑到「暗夜模式」方向，但没找到代码位置。

### 经过

CC 找到 entry point `TomoshibiApp.swift:20`：

```swift
.preferredColorScheme(app.isDark ? .dark : nil)
```

诊断：`nil` ≠ `.light`，`.preferredColorScheme(nil)` = **跟随系统主题**。

晚上系统切 dark mode：
1. SwiftUI 自动给所有 view 喂 dark color scheme
2. view 里硬编码 `T.paper` / `Color.white` / `T.ink` 等 light token 跟 dark 背景冲突
3. SwiftUI 渲染流程：先按 dark 重算 layout（瞬间黑底）→ 再 fade 到硬编码 light → 用户看到「点页面黑一下再正常」

### 关键判断 / 学到的东西

**修复**：`.preferredColorScheme(.light)` 强制 light，不依赖 `app.isDark`（保留字段不破坏 AppStore 接口给设置页 binding 用，未来真做 dark mode 时再激活）。

**学到**：
- SwiftUI `.preferredColorScheme(nil)` ≠ 不指定 — 显式声明"跟随系统"
- iOS 默认行为：app 跟随系统 dark mode，**没有 opt-out**，必须显式 `.light` 才能锁定
- 当 view 内有硬编码 light token 但允许系统切 dark → SwiftUI 双重渲染 → 黑闪转场

[CC 注：itsuki 自己已经诊断到 80% — 「是不是暗夜模式之类的」+「我也没上线暗夜模式啊」隐含「按理不该走 dark」。CC 的工作只是定位代码 + 解释 SwiftUI 的 `nil` 语义。]

### AC 价值 ⭐ 必填

- 对应核心问题：#1（在真机使用中发现 dev 模拟器看不到的问题）/ #3 / #5
- 展示了什么：
  - **真机测试 vs 模拟器测试** — itsuki 主动装到手机上线生产场景测试（不只是 Xcode simulator），发现了模拟器不会复现的 bug

## §4 ⭐⭐ AC 候选 — UI 文案设计判断「剧情化 placeholder vs 中性 placeholder」

- `StayListStubs.swift` × 2 处（外泊修改届：宿泊先 / 修改の理由）

### 关键判断 / 学到的东西

**核心 UX 设计判断**：剧情化 placeholder 看似帮助用户但实际有害：
1. **诱导虚假填写** — 用户看到「友人の結婚式」会想「我不是这个理由要不要编一个类似的」
2. **审美降智** — itsuki 用「太他妈蠢了」表达 — 这种例子在严肃应用（学校宿舍点呼系统）里 jarring
3. **隐私 / 文化预设错位** — 「祖母の通院」「祖父の米寿祝い」假设了核心家庭语境，海外学生（itsuki 自己）这些预设全错位

**正确的 placeholder 设计**：
- 字段名重复 + 行动提示（「住所を入力」）
- 单位提示（「体温（℃）」）
- 不写"例：xxx"，因为 placeholder 本身已经是 hint，不需要再加「例」

**CC 原本的判断错误**：CC 之前抄 demo prototype 的 placeholder 时**没意识到这是设计决定不是文案翻译** — 把 jsx 里的 demo 例子原样移植到生产 Swift。

## §5 ⭐ CC 主动发现 — iOS 26 Text + Text deprecation 升级到字符串插值

**模式**：模式 6（API 升级取舍）  
**思考层数**：2 层  
**对应 AC 核心问题**：#3 / #5

### 背景

启动 build error 同时 Xcode 报 2 处 warning（`CommunityStubs.swift:1561-1565`）：

```
'+' was deprecated in iOS 26.0: Use string interpolation on `Text` instead: `Text("Hello \(...`
```

### 经过

旧代码（多 Text 用 `+` 拼接 + 共享 modifier）：

```swift
(
    Text("⚠ ")
    + Text("臨時公告").fontWeight(.bold)
    + Text(" · \(SEED.busNotice.text)")
)
.font(.system(size: 12.5))
```

iOS 26 deprecated：Apple 推荐字符串插值嵌套 Text：

```swift
Text("⚠ \(Text("臨時公告").fontWeight(.bold)) · \(SEED.busNotice.text)")
.font(.system(size: 12.5))
```

### 学到

- iOS 26 SwiftUI 的 `Text` 字符串插值支持嵌入另一个 `Text` 实例并保留 modifier — 比 `+` 拼接更简洁
- 这是 SwiftUI API 演进的小趋势，类似 React 的 Fragment 简化

### AC 价值

- 对应核心问题：#3 / #5
- 展示了什么：跟进 iOS 26 新 API 的演进，及时升级 deprecated 写法
