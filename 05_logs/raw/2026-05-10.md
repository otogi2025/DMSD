- `## AC 信号 (HH:MM) [类型]` ← ac-radar 实时（短）

## 15:00 [认知改变 / 模式 5] "通用工具 vs per-repo 配置" 分层架构 ⭐⭐

### 背景 / 触发

- **Anthropic 官方**（/plugin）→ `~/.claude/plugins/cache/claude-plugins-official/<name>/` + manifest `~/.claude/plugins/installed_plugins.json` 注册

CC 解释 skill 物理位置都在底层全局，**DMSD 项目通过 `docs/agents/*.md` per-repo 配置告诉 skill 在 DMSD 里怎么干活**。同一个 `to-prd` skill 在 DMSD 写 issue 到 `00_admin/TODO.md`，在交易系统里读那边的配置走默认 GitHub Issues。

### 关键判断 / 学到的东西

这是软件工程里的**分层抽象 / namespace 模式** —— 跟下面这些是同一个心智模型：

- Linux：`/usr/bin/` 工具全局可用 / `~/.config/<app>/` per-user 配置
- Git：global config / repo-local config（`git config --global` vs `git config`）
- Programmer's PATH：工具在 PATH 全局 / 每项目 .env / package.json 定制行为
- Claude Code skill：`~/.claude/skills/` 全局 / per-repo `docs/agents/` 定制

之前 itsuki 默认以为"装 skill 就是装到 ~/.claude/skills/"是个**单层心智模型**。理解 per-repo 配置层后变成**双层心智模型** —— 工具住底层、每项目自己配。

这个分层一旦理解，未来碰到任何"装新工具到 dev 环境"问题都不再问"装哪儿"，而是问"工具住哪 / 怎么 per-repo 定制"。
