## 1. [方法论][认知改变] 多轮 AI 对抗复审才算收敛 — 不是「跑一次绿就完」

### 背景
itsuki 拍板规矩：每做完一个开发阶段，派 Codex（gpt-5.5 思考等级 xhigh）只读审查挑刺。这次 IX-004「修改届接后端」真走满了 5 轮。

### 经过（每轮都真挑出问题，不是走过场）
- 阶段2：5 条（修改理由丢失 / 状态没重置 / 日期误拒 / returned / 文案）
- 阶段3：又 5 条 —— 含 2 个我自己没看出来的：① 无实质修改也重置审批链（空提交能反复清空别人的部分承认）② audit 端点任何老师能读任意申请履历（越权）
- 阶段4：0 严重 + 2 条（flight 时间带时区比较误判 / 修改理由没真正强制）
- 阶段5：「收敛 — 无新增严重/中问题」

### 关键判断 / 学到的东西
**单一来源（哪怕我自己带编译+测试验证）一定有盲区**。我每轮都新增针对性测试（从 1 个长到 18 个），但还是阶段3 才暴露「无实质修改重置链」这种滥用面 —— 这是只盯「功能对不对」想不到的，要「有人故意乱用会怎样」的对抗视角。

但**也不能盲信 Codex**：每条 finding 我都先 `git show` + 读真实代码核实再修。比如阶段3 说的 `returned` 我去查证 —— 确认后端 `_recompute_application_status` 根本产不出 `returned` 状态（老师「退回」动作没实装），所以那是个独立功能缺口、不是我引入的 bug，我只做前向兼容保留 + 记 TODO，没瞎改。

### itsuki 原话
> "继续做。每一个阶段做完以后，都要判 Codex 去审查一遍。拍 CodeX 挑刺，找 bug 找漏洞和给建议。用5.5 xhigh"

### AC 价值

## 2. [问题解决][自己认识] Codex 额度耗尽时，我自己顶上做安全审查 — 当场逮到自己引入的隐私 bug

### 背景
IX-008 iOS 做完要派 Codex 审，结果 Codex 撞使用限额（并发会话用光了）。审查门跑不了。

### 经过
我没有「跳过审查直接收尾」，而是**自己照 Codex 该查的清单逐条自审**。审到「安全网」设计时 —— 我让 loadMe 把真实用户写回全局 `SEED.user`（覆盖 ~60 处没法用 app 的站点）—— 当场意识到：**登出时没清，上一个真实用户的姓名/房号会残留**，下一个人登录前 / 演示态可能读到。这是隐私泄漏。

立刻修：给 SEED 加 `demoUserSeed` 不可变副本，登出（authToken=nil 的 didSet，覆盖登出按钮/401/过期所有路径）清 currentUser + SEED.user 复位。

### 关键判断
**审查能力不能外包给 AI 完全依赖**。Codex 是放大器不是拐杖 —— 它不在时我得能自己撑住质量。而且这个 bug 是「我自己的设计副作用」，最该我自己抓。

### itsuki 原话（这轮的指令背景）
> "其他的继续做，做完了就收尾。"

### AC 价值
- 对应核心问题：#3 问题解决 / #5 自己认识
- 展示：不依赖工具的独立安全审查能力 + 对自己代码副作用的警觉（全局可变状态的生命周期管理）
- 模式 1（问题→修）+ 模式 5（从「图省事写全局」到「意识到全局态要管登出复位」）

## 3. [设计决策] IX-008 怎么把 73 处演示假用户接真后端 — 发现 User 结构混了三类数据

### 背景
iOS 各页 73 处直接读写死的 `SEED.user`（リュウ イヒ / A5 / 4.5分）。要让生产显真实、演示留假。

### 经过 / 关键判断
1. 先调研，发现 `User` 结构**混了身份（名字/房号）+ 统计（扣分/迟到/欠席）+ flag** 三类，而后端 `/me` 只能给身份 —— 「73 处一把换」不成立。
2. 字段分布实测：身份 ~57 处、统计 10 处、学習flag 3 处。
3. 选了 `currentUser ?? SEED.user`（`displayUser`）+ 登录拉 /me 的方案（符合代码里已写的 `isAuthenticated` 门控设计意图），加 SEED.user 安全网收口剩余站点。
4. 统计字段 /me 给不了 → 真人先显 0（itsuki：「真人登录肯定是先看0分啊，4.5分是 demo 的数据」）。

### itsuki 原话（学習対象 flag 的产品判断）
> "为什么要默认 true？要老师在后台手动调的人才能看到。算了，UI还是可以看得到，但是点进去就显示他不需要晚自习。"

→ 我据此把 isStudyTarget 默认 false + MyPage 学習卡片去掉隐藏门控（常显）+ 学習详情页对非对象显「学習対象外です」提示页。

### AC 价值
- 对应核心问题：#1 问题发现（看出 User 结构数据职责混乱）/ #2 技术判断（displayUser vs 全局突变的取舍）/ #3 问题解决
- 展示：大规模重构前先调研数据流、按真实约束拆分阶段（身份 now / 统计留 IX-008b）、跟产品方（itsuki）对齐边界行为
- 模式 6（取舍三角）
