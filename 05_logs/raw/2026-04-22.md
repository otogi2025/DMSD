## §16:28 · Round 3 bundle 解包

**标签**：`#demo4-28 #engineering #AC候选`  
**对应 AC 核心问题**：#3 問題解決 · #4 自己認識（技术问题 → 工具解法）

Claude Design 的 standalone 是为了 "双击即跑 / 断网也能 demo"，所有 JS / 字体 / 图片都塞进一个 HTML 里。缺点：没法读代码 / 没法接后端 / 没法二次开发。

**解包思路**：
1. 读 HTML 里 3 个 `<script type="__bundler/*">` block → 拿到 manifest（UUID → base64+gzip）和 template（整页 HTML，资源用 UUID 引用）
2. Python 遍历 manifest → base64 解码 + gzip 解压 → 写文件
3. 每个 JS 文件头部有 Claude Design 加的 `// ComponentName — 说明` 注释 → grep 出来作为 rename 依据
4. 把 template 里的 `_assets/UUID.ext` 替换成人类可读路径
5. standalone 依赖 `window.__resources` 对象（运行时注入）→ 解包后手动在 `<head>` 加一行 `<script>window.__resources={tomoshibiIcon:"assets/tomoshibi-icon.png"}</script>`

**产出**：
- `round3/Tomoshibi_Prototype_v3.html`（原 standalone，demo 直接用）
- `round3/src/` 可编辑版：index.html + 12 个 `components/*.jsx`（app / shell / theme / login / select-teacher / roll-call-landing / live-roll-call / override-modal / applications / outstay-detail-modal / discipline / pages-records-search-etc）+ vendor/（React/ReactDOM/Babel）+ assets/tomoshibi-icon.png + _assets/ 130 个 woff2

**AC 角度**：itsuki 可以在面试时说"我遇到一个问题 — Claude Design 给的是 self-unpacking 的单文件 bundle，demo 能跑但改不了代码。我就研究了它的 unpacker JS，写了个 Python 脚本逆向出 manifest 结构，把 146 个资源解出来，按组件头部注释自动重命名成人类可读的文件结构，最后修复运行时注入的 `window.__resources` 对象在静态版里的缺失。" → 体现 #3 問題解決 + #4 自己認識（"我不懂就去读源码然后写工具"）。

## §17:55 · 白屏事件 2 连 — 根因排查实录

**标签**：`#demo4-28 #debugging #AC候选🌟`  
**对应 AC 核心问题**：#3 問題解決 · #4 自己認識（debugging methodology）

**Round 1 · 双击 src/index.html 全白屏**
- 症状：浏览器地址栏是 `file:///.../src/index.html`，页面纯白
- 误判：最初怀疑 JSX 语法错，跑 Babel.transform 校验 12 个 jsx 全部 ✓ → 排除语法问题
- 真因：**file:// 协议下 Babel standalone 用 fetch() 拉 `<script type="text/babel" src="components/X.jsx">`，浏览器把 fetch 本地文件判定为跨源 block**。还有 `<script src integrity="sha384-..." crossorigin="anonymous">` 在 file:// 也被 CORS 拒绝（Claude Design 的 unpacker JS 专门 strip 了这 2 个属性，我解包时漏了）
- fix：(a) strip integrity/crossorigin (b) 做 `rebuild.command` 脚本把 jsx 内容直接内联进 index.html，不依赖 fetch（文件大小 560KB）

**Round 2 · 修好后点「記録」页面又白屏**
- 症状：登录 + 进主页正常，一点左 nav「記録」就白
- 误判：再怀疑 syntax → 又 verify 一遍，依然 clean
- 真因：**数组越界**。把リュウ イヒ移到男寮后男寮 12 人 → 13 人，但 records.jsx 里 `statuses = ['ok',...]` hardcode 12 项，`roster.map((x,i) => statuses[i])` 当 i=12 时返回 undefined → `RecStatusBadge` 里 `map[undefined]` → TypeError → React 整个组件树崩溃 → 白屏
- fix：(a) `statuses[i % statuses.length]` 保证不越界 (b) RecStatusBadge 加 fallback `|| [ink3, soft, '—']` 防未来同类 crash

**为什么值得记 🌟**：
- 真实 debugging 过程，2 次都最初走错方向（都怀疑 syntax）→ 诊断工具（Babel.transform）告诉我不是 syntax → 被迫思考运行时
- 学到教训：**「空白 = 组件 crash = 跑到一半的 React 错误」，不是 syntax**。React 组件树里任一节点 throw 都会让 root 白屏（没 ErrorBoundary 时）
- 第 2 个 bug 是**系统性 bug**：改了 roster 大小，但其他文件里的 hardcode 数组没跟上。教训：**demo 数据应该用固定长度 cycle（i % len），不要假设 roster 固定 12 人**
- AC 角度："硬编码数组长度耦合"是初学者常犯的错 → itsuki 已经能通过 bug 学到设计原则

## §18:00 · 日本語 native-speaker 视角文案审查

**标签**：`#demo4-28 #web #japanese #AC候选`  
**对应 AC 核心问题**：#4 自己認識（跨语言工作优势）

itsuki 问："名单这个词是日语吗？"  
→ **不是**。「名単」是中文词，日语只有「名簿」「リスト」「対象者一覧」。

走一次全量文案扫描发现一堆中文词残留（Claude Design 虽然是 Anthropic 产品但日语 + 中文都认，生成时会混用）：

| 中文残留 | 改成日语自然版 |
|---|---|
| 名単 | リスト |
| 距清掃まで / 距禁足まで | 清掃まで残り / 外出禁止まで残り |
| 本月 / 当月 | 今月 |
| 改判者 | 手動調整者 |
| 晚点呼 | 晩点呼（晚 是中文字，日语用 晩） |
| 部活早朝 | 部活生（原词不自然，早朝部活和部活早朝是不同意思） |
| push 送信済み | プッシュ通知送信済み |
| 自分で入力可 | 自分で記入可 |
| 担任 先生（有空格） | 担任 |
| スプレッドシート × 入力可 | 食数の自由記入可（× 含义不明，Claude Design 随便塞的）|
| 避難訓練 · 軍歌斉唱後 | 集合・点呼後（軍歌 避難訓練 语境太诡异）|

**为什么值得记**：
- **itsuki 的 language edge**：她是留日留学生，中文日文都 native，能一眼 spot 出 AI 生成内容里的"中日混血"文案。这是 AI 做不到的（它不知道"名単"在日本人眼里是异国词）
- AC 面试话术候选：
> "AI 生成的日语文案中经常夹杂中文词汇，比如'名单'、'距清扫まで'这种对日本人来说不自然的表达。我作为既懂中文又懂日语的用户，能在每个页面扫描时立刻发现这些问题。这让我意识到：**AI 不是语言上的 native，最终的语言 QA 永远需要真人**。这个视角也成了我对'AI 时代人类的角色'的回答的一部分。"

## §18:11 · 单文件 bundle 脚本化

**标签**：`#demo4-28 #engineering #tooling`

itsuki 问："以后双击 index.html 就能 demo 展示了吗？"  
→ 可以，但要带整个 `src/` 文件夹（vendor + assets + 130 字体）。

→ 干脆做**真正的单文件版本**，像 Claude Design 原版一样能 U 盘拷一个文件走：

**`build_single_file.py`** 脚本：
1. 把 `components/*.jsx` + `vendor/*.js` 全部 inline 进 index.html
2. 把 woff2 字体用 `base64` 编码嵌进 CSS `url("data:font/woff2;base64,...")`
3. 把 `tomoshibi-icon.png` 同样 base64 inline 到 `window.__resources`

**产出**：`Tomoshibi_v3_single.html` 32.2 MB（Claude Design 原版是 9.4 MB 因为 gzip 了，我的没 gzip 所以大一些）

配套 `打包单文件.command` 双击脚本。

**什么时候用这个**：demo 当天 U 盘拷走、借任何别人的电脑演示 / 管理员教授有要求把成果留下一份 / 4-28 演示当场 Wi-Fi 有问题的兜底。
