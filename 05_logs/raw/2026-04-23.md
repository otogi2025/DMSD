## §1 · 20:30 · 学号体系 6 桁 拍板  🌟 #AC候補 #問題解決

**問題**: 現状 2 桁番号（00 demo seed / 01-23 真实学生）— 注册順に割当。学年情報なし。進級・転校対応なし。

**itsuki の問い** (20:25): 「番号也不按注册顺序了，输入年级和番号后自动识别分配，比如说我高３B組18番就是060218」

**決定**: 学号 = `学年(2) + 組(2) + 番号(2)` 6 桁
- 学年: 中 1=01 〜 高 3=06（当校 = 中高一貫 6 年制）
- 組: A=01 / B=02（C 以降無し）
- 番号: 班里通し（01-99）
- 高 3 B 組 18 番 → `060218`
- リュウ イヒ（itsuki）: 00 → **060218** に移行

**ライフサイクル**: 進級で変わる → App 内で学生が更新 → 老师 Web に改动履歴自動記録。転校生は末番+1 を自分で入力。

**反省**: itsuki から "输入年级和番号后自动识别分配" 発話を受けた瞬間、**7 つの hole** を列挙して確認（年級コード / 組コード / 升学時挙動 / 転校生 / 00 移行 / 注册 step / 房间号紐付け）。itsuki が全部即答 → 決定即実装仕様に。`feedback_find_5_holes_after_any_proposal.md` の正しい運用例。

**AC 素材**: "決定を急がず、設計の穴を先に発掘する" という学び。学号体系は PK じゃなく「計算プロパティ」にすることで進級時 ID 変更のデータ整合性問題を回避 — 初学者でもデータベース設計の原理原則に触れられた。

## §3 · 20:50 · 跨会话同步規則 A+B+C  🌟 #AC候補 #自己認識

**問題**: iOS Swift 実装は独立 repo `otogi2025/Tomoshibi-iOS`（Anthropic cloud agent 並走）。Web は DMSD 内。後端も DMSD 内。**共用機能**（账号 / 申請 / 通知 / コミュニティ）を片方で改動すると必ず漂移する。

**根因**: cloud agent は DMSD repo を取得不可 → 設計文書は Tomoshibi-iOS/refs/ に **物理コピー**で配置するしかない（symlink 不可）。

**解決 A+B+C**:
- **A = Single Source of Truth**: `02_design/system_features_v0.1.md`（新建）を全実装層の真値に。
- **B = Sync Script**: DMSD 内 `bin/sync-ios-refs.sh` で単方向コピー DMSD → Tomoshibi-iOS/refs/
- **C = Rules**: CLAUDE.md § 跨 repo 同步规则 に「改動の種類 → 必須アクション」マトリクスを明文化。Tomoshibi-iOS/REMOTE_AGENT_GUIDE.md にも refs/ を共通源として明記

**跨会话改动履歴** = `Tomoshibi-iOS/SESSION_CHANGELOG.md` + DMSD の `05_logs/raw/YYYY-MM-DD.md` で時系列記録。

**AC 素材**: 単独開発では不要な "多 repo + 多 agent 同期問題" を、自分で設計パターン（source of truth + 片方向 sync + 明文ルール）で解決した。Git sub module じゃなく物理コピー + 明示的 sync を選んだ理由 = "cloud agent + submodule は調試地獄" の経験的予見。

## §9 · 21:37 · HTML 最新版トラブル  🌟 #AC候補 #自己認識

**事故**: itsuki が `Tomoshibi_Prototype_v3.html`（Claude Design 4-22 凍結版、9 MB）をダブルクリック → パスワード `12345678` 弾かれる。

**根因**: 4-22 以降の改動（密码変更 / 男寮教員名 / 学号 / 外泊期限 / アカウント管理 etc）は **全て `src/` の jsx に入り**、`Tomoshibi_Prototype_v3.html`（Claude Design 原始交付）には **一切反映されていない**。しかも LATEST.md で私がそれを ⭐ 最新と標記していた — **誤情報**。

**さらに**: `Tomoshibi_v3_single.html`（32 MB、src から打包）も **古い打包**だった。rebuild 順序を忘れていた:
1. `.jsx` 編集
2. `rebuild.command` → jsx を src/index.html に内联
3. `build_single_file.py` → single HTML 生成

2 を飛ばして 3 を走らせると、src/index.html の古い inline キャッシュから打包される → single が古いまま。

**対処**:
- `Tomoshibi_Prototype_v3.html` を `_ORIGINAL_CLAUDE_DESIGN_2026-04-22.html` にリネーム → **itsuki が再び誤点（21:38）** → 即削除
- src/applications.jsx + theme.jsx に最新改動適用 → rebuild → repack → `Tomoshibi_v3_single.html` 32 MB が真の最新に
- `LATEST.md` 修正: ⭐ 最新 = single（not Prototype_v3） + ビルド順序明文化 + 今回のハマり例記載

**AC 素材**: "最新版はどれ？" という基本問題を舐めた結果 itsuki が 2 回ハマった。single source of truth 原則は文書だけでなく**バイナリ成果物**にも必要だった。後日、teacher_web/ 下の .html は 1 つしか存在させない運用に。
