- CC 不是一直醒着的同一个脑子，每个会话从零开始

## 16:xx [问题解决][技术判断] 诊断出个人网站仪表盘「倒计时冻死」的真 bug + 建一键自动更新

### 背景
itsuki 要 CC 读个人网站 `pj.tomoshibi.cc` 全部内容 + 审查 + 设自动更新。

### 经过
- 读完 9 个页面，审查仪表盘时发现一个真 bug：倒计时的脚本把「今天」**写死成 2026-05-26**，还故意不用实时日期 → 倒计时永远按 5-26 算，「筑波 R9 募集要項公表」显示剩 20 天实际只剩 10 天
- 修法：改成按**日本时间**当天实时算（网页脚本每次打开当场算，零维护）
- 项目状态（版本号）：写了个生成脚本 `生成仪表盘.py`，自动读 DMSD/Tango/QTS 三仓库的 CHANGELOG 版本 + git 最后提交日 → 重新渲染 → 推 VPS。一条命令刷新
- 过程踩 2 个小坑：`grep -m1 -oE` 在 macOS 上没只取第一行（把整个版本历史全抓了）→ 改 Python 逐行读；正则又抓到说明段里的版本号 → 收紧成只认 `## [版本]` 标题行

### 关键判断
- itsuki 原本想「VPS 装定时」刷项目状态，CC 摊牌技术约束：项目代码在 Mac、VPS 读不到，且 DMSD 没推 GitHub、Tango/QTS 没传 → VPS 定时拿不到真实版本。最终 itsuki 选「一条命令手动」
- 「倒计时」和「项目状态」分两半处理：前者客户端实时全自动，后者一键脚本
