## 3. ⭐⭐⭐ 核心事件：Codex「116 天磨穿」被常识推翻

CC 调 Codex（GPT-5.5 + x-high 推理）做独立硬件审查。Codex 报出一个「致命问题」：ST25DV16K 每 10 秒重写 EEPROM，按 100 万次寿命算，约 **116 天磨穿**，建议整个动态贴纸方案改 NTAG424 DNA。

CC 把这个结论**原样转给 itsuki 当致命问题**，建议暂停下单。

itsuki 当场重算质疑：
```
Codex 假设：7×24 全天每 10 秒写 → 8,640 次/天 → 116 天
真实情况：点呼只在固定时间窗（学生晚上回宿舍那 20 分钟~1 小时）
         → 120~360 次/天 → 7.6~22.8 年
```

**Codex 没算错，但前提假设错了** —— 它默认设备 7×24 满负荷运行，而点呼根本不是全天候的。CC 给 Codex 的 brief 里确实写了「每 10 秒刷」（因为 `hardware_design.md §2.3` 就这么写，漏了「只在点呼时间窗内」的限定），但 CC 转述结论时**没质疑这个前提是否合理** = CC 失职。

itsuki 抓出后，让 CC 写一份给第二个 AI 的审查提示词，开头第一句就警告「点呼不是 24 小时一直跑，别乱假设，先写清你假设每天写几次再算」。第二个 AI（同样跑高推理）确认 116 天是伪问题，并补了 ST 官方手册 / Adafruit / Raspberry Pi 官网引用源。

→ 结论：ST25DV 方案可行，不必改 NTAG424 DNA。Codex Q1+Q10「116 天 → 改方案」作废。

## 4. 逐件核对 + 零基础教练问答

itsuki 截图发来选型，CC 逐张核对（13 件）。期间答了一串零基础问题：
- 电阻干嘛用 → 限流保护 LED，不焊接（面包板插）
- LED 为什么多色 → 状态映射（绿成功/红失败/蓝待机/白启动），演示可先做 2 个
- ST25DV 为什么买 4 个 → itsuki 自己改主意从 1 个 → 4 个（锁货做 4 台）
- USB 喇叭能不能用 → 能，Pi 当 USB 声卡，0.5W 供电够，占唯一 USB 口
- 不焊接怎么接 ST25DV → 用 SparkFun Qwiic 免焊线套件

发现的真问题：
- 第一次截图的风扇是 12V（Pi 要 5V）→ 换 5V 30×30×10mm（不买外壳了 10mm 厚无所谓）
- 绿色 LED 在最后一批截图漏了（签到成功最重要的灯）→ 提醒补上
