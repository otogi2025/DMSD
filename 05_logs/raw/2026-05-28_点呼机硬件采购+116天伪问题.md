# 2026-05-28 点呼机硬件采购 + 「116 天磨穿」伪问题

## 1. 起因

itsuki 启动「今晚把点呼机硬件全买好」。CC 读 `02_design/hardware_design.md` 发现：5-22 海关查扣事件后 itsuki 已拍板「撤回中国海运 → 日本本地买」，但 §5.1' 全部型号 / 价格 / 渠道还是「待选型 ⏳」占位，没真回填。所以「直接下单」隔着一道「日本渠道选型」关卡。

## 2. 选型回填 + 方案 A

## 3. ⭐⭐⭐ 核心事件：Codex「116 天磨穿」被常识推翻

CC 调 Codex（GPT-5.5 + x-high 推理）做独立硬件审查。Codex 报出一个「致命问题」：ST25DV16K 每 10 秒重写 EEPROM，按 100 万次寿命算，约 **116 天磨穿**，建议整个动态贴纸方案改 NTAG424 DNA。

CC 把这个结论**原样转给 itsuki 当致命问题**，建议暂停下单。

itsuki 当场重算质疑：
```
Codex 假设：7×24 全天每 10 秒写 → 8,640 次/天 → 116 天
真实情况：点呼只在固定时间窗（学生晚上回宿舍那 20 分钟~1 小时）
         → 120~360 次/天 → 7.6~22.8 年
```

**Codex 没算错，但前提假设错了** —— 它默认设备 7×24 满负荷运行，而点呼根本不是全天候的。CC 给 Codex 的 brief 里确实写了「每 10 秒刷」（因为 `hardware_design.md §2.3` 就这么写，漏了「只在点呼时间窗内」的限定），但 CC 转述结论时**没质疑这个前提是否合理** = CC 失职。

itsuki 抓出后，让 CC 写一份给第二个 AI 的审查提示词，开头第一句就警告「点呼不是 24 小时一直跑，别乱假设，先写清你假设每天写几次再算」。第二个 AI（同样跑高推理）确认 116 天是伪问题，并补了 ST 官方手册 / Adafruit / Raspberry Pi 官网引用源。

→ 结论：ST25DV 方案可行，不必改 NTAG424 DNA。Codex Q1+Q10「116 天 → 改方案」作废。

## 4. 逐件核对 + 零基础教练问答

itsuki 截图发来选型，CC 逐张核对（13 件）。期间答了一串零基础问题：
- 电阻干嘛用 → 限流保护 LED，不焊接（面包板插）
- LED 为什么多色 → 状态映射（绿成功/红失败/蓝待机/白启动），演示可先做 2 个
- ST25DV 为什么买 4 个 → itsuki 自己改主意从 1 个 → 4 个（锁货做 4 台）
- USB 喇叭能不能用 → 能，Pi 当 USB 声卡，0.5W 供电够，占唯一 USB 口
- 不焊接怎么接 ST25DV → 用 SparkFun Qwiic 免焊线套件

发现的真问题：
- 第一次截图的风扇是 12V（Pi 要 5V）→ 换 5V 30×30×10mm（不买外壳了 10mm 厚无所谓）
- 绿色 LED 在最后一批截图漏了（签到成功最重要的灯）→ 提醒补上

## 8. 晚段续：把「采购链接」逐个抓取核对，揪出 12V 风扇

> 同日晚段，itsuki「做一个 HTML，包括购买清单和点呼机信息，方便快速查看」+「我发你的这些链接你都确认了吗？确认了后放上去」+「图片塞进去」。

### 8.1 起因

itsuki 给了 16 张采购页截图 + 一长串采购链接（秋月 8 个 / Switch Science 1 个 / Amazon 6 个），要求 CC「自己去查看确认，然后所有清单确认一遍，包括我没意识到的方面」。CC 用 WebFetch（联网抓网页工具）把链接逐个抓取，而不是只看截图。

### 8.2 抓出的真问题（截图看不出、靠抓链接才发现）

| 问题 | 怎么发现的 |
|---|---|
| 🔴 **风扇链接是 12V** | Amazon `B0DYV31FJZ` 抓出来是「JYUDAUFU 30×10mm DC 12V 4 个装」。Pi 3A+ 只有 5V，12V 风扇转不动。上次会话明明说好换 5V，itsuki 又贴了 12V 链接 |
| 🟠 **喇叭链接和截图对不上** | 截图是 HONKYOB ¥1,980，但链接 `B0G64JFMNR` 抓出来是 Apqfw HM5002 另一款 |
| 蓝色 LED 漏链接 | itsuki 给的秋月 8 个链接里没有蓝色 LED（截图却有） |
| 杜邦线买重 | `g103475`（母母 15cm）+ `g115868`（母母 20cm 连排）功能重叠 |
| PN532 链接抓不到 | `B0C7Q1PX3R` 服务器一直报 500 错误，没确认成 |

### 8.3 关键点：CC 没有假设「链接 = 需求」

如果 CC 偷懒，只按截图（截图大多是对的）做清单，就会漏掉「12V 风扇」这种藏在链接里、截图没拍到的坑。itsuki 一句「你都确认了吗」逼出了逐个抓取的动作 —— 这跟早段「转述 Codex 116 天没审前提」是同一类教训的正面版：**给 itsuki 放数据/链接前，自己先实际验证，不能想当然**。
