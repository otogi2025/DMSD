> **想读成品级叙事** → 看 [`project_evolution.md`](../project_evolution.md) / [`decision_log.md`](../decision_log.md) / [`dev_log/`](../dev_log/)

## 这里的文件是什么

`raw/` 里的每个文件是一次**会话或讨论的原始 dump**，由 Claude Code（CC，AI 协作助手）或 itsuki 本人在会话结束时整理。特点：

- **保留原始语气**（讨论过程中的犹豫、推翻、方向切换）
- **可能包含吐槽、玩笑、和 AI 的争吵**
- **不精简**，按 `CLAUDE_CODE_记录指南.md §3.4` 要求每条 500-2000 字
- **可能过期**（决策后来改了；技术方案推翻了；原文不回溯更新）

这些特点是**有意的**。原因：

1. **AC 入試 叙事需要"过程"证据**，光看结论（成品叙事）显不出思考的曲折
2. **回看原始讨论能挖出忘了的细节**（例如几个月后问"当时为什么选这个"，raw 里有答案）
3. **推翻的方案也是有意义的记录**，展示"不只是做对，也能识别做错"

## 命名规则

两种共存（按 `CLAUDE_CODE_记录指南.md §12`）：

- **日期版**：`YYYY-MM-DD.md` —— 一天只有一个会话 / 一个主题时使用
- **主题版**：`YYYY-MM-DD_主题.md` —— 一天多会话 / 多主题时区分

例：
- `2026-04-12.md`（4-12 只有一个架构讨论会话）
- `2026-04-12_NFC架构讨论.md`（4-12 同一会话的主题化重命名）
- `2026-04-20.md` + `2026-04-20_v0.3.1发布执行.md`（同日两会话，主题区分）

## 怎么读最有效

1. **不要从这里开始读项目**。从根目录 `README.md` 开始
2. **想了解某次决策来龙去脉** → 先看 `05_logs/decision_log.md` 索引，那里有 `相关: 05_logs/raw/YYYY-MM-DD.md §HH:MM` 的指针，顺指针来
3. **按时间反推**：每个 raw 文件顶部有"当日目录"，标注了 `#AC候选` 的是适合 AC 叙事的关键片段
4. **不喜欢读？跳过即可**。raw 是"挖宝的矿"，不是"展示的橱窗"
