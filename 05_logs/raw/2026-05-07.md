### itsuki 的逻辑

## 22:45 [模式 5] CC 第一次教 itsuki SSH 公钥认证

### 背景

itsuki 习惯了 Vultr 风格「root + 密码」登录，第一次连 GCP VPS 用 `ssh root@34.85.74.70` → 报错 `Permission denied (publickey)`。

### CC 教学（深度 + 类比）

**SSH 公钥 vs 密码 类比**：
- 密码 = 银行卡 PIN（4-8 位能猜）
- 公钥 = 银行 USB key + 复杂密钥（512 位算到太阳灭也算不出）

**GCP 不让 root 登录**：Linux 安全惯例，强制 user + sudo。

**3 种 SSH 登录方式对比**：
| 方式 | 时间 | 长期友好 |
|---|---|---|
| 浏览器内 SSH | 10 秒 | ❌ |
| gcloud CLI | 装 SDK 10 分钟 | ✅ |
| 手动配公钥 | 10 分钟一次性 | ✅✅ |

→ CC 推荐方案 C（手动配公钥），最长期友好。

### itsuki 跑命令的细节

- `ssh-keygen -t ed25519 -C "kurekoduki@gmail.com"` → **报「id_ed25519 already exists」** — itsuki Mac 上之前已经有 SSH 密钥（GitHub 推送用过）
- CC 立刻教学：「**SSH 密钥可以重用**，绝不能覆盖（覆盖会让 GitHub 失效）」 → 跳过 Step 1，直接 cat 公钥
- itsuki 上传公钥到 GCP metadata → 用 `kurekoduki` user 登录 ✅
- 5 个验证命令全过（whoami / hostname / os-release / sudo whoami / df -h）

### AC 价值

- **对应核心问题**：#5 自己認識（模式 5 经典）
- **展示了什么**：
  - **第一次接触**远程服务器 SSH 登录 + 公钥认证概念
  - 不只学命令，学**机制**（公钥 vs 密码 / GCP 为何禁 root / 公钥可重用）
  - 元认知：踩坑「以为新生成密钥会覆盖 GitHub 密钥」 → 学到「SSH 密钥跨服务通用」
- **AC 叙事潜力**：「我从只会用 GUI 工具的高中生 → 通过 AI 协作学会 Linux 服务器运维」 = 模式 5 主线
