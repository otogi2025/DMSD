## 滑动条件（realistic expectations）

如果进度跟不上计划：

| 实际情况 | 采取方式 |
|---|---|
| Tier 2 backlog 5 月底做不完 | 优先保 **Tier 2 的 spec 漏洞修复 + Device_Contract**（代码 demo 延后），先保 AC 材料 |
| 代码 8 月底跑不起来 | 承认"spec 阶段 + 设计阶段的深度"就是本项目的卖点，不强求代码跑 demo |
| 志望理由書 7 月底写不出来 | 降级为 "8 月底完稿"，但不再推迟 |
| 模拟面试没人陪 | iCloud `面试準備/` 里自己录音 → 自己听 → 自己改 |
| **AC 入試 自身未通过** | 继续保项目 → 一般入試 → 入学后继续 DMSD 作为研究素材 |

## 这个 checklist 本身的元素材价值

**倒推时间表 + 分阶段 gate + 滑动条件**是一个可以在面试讲的素材：

> "我从 4-20 开始（约 AC 前 6 个月）做了一份倒推 checklist，把 '项目 / AC 叙事 / 模拟面试' 三条线分别切到每个月的 gate 上。这让我避免了'最后两周突击'的失败模式。现在（YYYY-MM）我在 X 阶段，gate Y 已经闭合 / 还差 Z 项。"

这展示**工程化的时间管理 + realistic 的自知**。

## 月度审视

每个月月底：

1. 打开本文件，看上月的 gate 是否闭合
2. 如果闭合 → 打 ✅（在状态列）
3. 如果没闭合 → 进入滑动条件表判断是否降级
4. 写 monthly_review（iCloud）记录本月 gate 达成情况 + 下月计划调整
