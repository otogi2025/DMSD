## 直接粘贴这一块（`/goal` 后面）

```
把 Android 学生 App（03_dev/student_android/v1/）按 00_admin/iOS_Android_对齐规格.md 对齐到 iOS，做到功能、界面布局、配色、日语文案、调的后端接口、用的字段都跟 iOS 一致。施工细节照那份对齐规格逐屏来。

【完成的可测量终态 — 每条都必须把证据贴进对话，检查模型只看对话不跑命令不读文件】
1. 摸底矩阵：产出文件 05_logs/raw/android对齐_差异矩阵.md，列对齐规格里每个功能屏在 Android 是「有/缺/半成品」，并把矩阵全文贴进对话。
2. 逐屏实装：每完成一屏，在对话里贴一行「屏名 | 对应截图编号(06_assets/app_screens_2026-06-05_ios/) | 状态=已对齐 或 记TODO+原因」。
3. 编译过：每改一批跑 ./gradlew assembleDebug（或项目实际 gradle 命令），把命令 + 输出最后 15 行贴进对话，退出码必须 0。
4. 网络层对齐：Android 调的每个后端端点 + 每个字段，贴出跟 03_dev/backend/v1/app/schemas.py 的逐项对照（端点路径一致、字段 snake_case 一致）。
5. 收尾：把「已对齐 N 屏 / 记 TODO M 屏 / 总 K 屏」数字贴进对话，并产出对齐总结报告存 05_logs/raw/。

【不能动的约束】
- 绝不改 iOS 任何文件（03_dev/student_ios/ 只读参照，要动先停下问 itsuki）。
- 绝不改后端代码（03_dev/backend/ 只读，只对字段）。
- UI 文案保持日语原文，跟 iOS 一字不差，不许翻译成中文/英文（对齐规格里每屏都列了日语原文）。
- 防作弊核心（nonce 一次性随机数 / ECDSA 数字签名 / 设备注册 / 卡→学生映射）后端还没写，遇到只记 TODO，不动。
- commit 用显式 pathspec 不许 git add -A；不 push；commit 不写 Co-Authored-By；不碰 iCloud 文档。
- 开工前先看 00_admin/WIP.md「多会话占用」避免跟别会话撞文件。

【验证铁律】每改完真跑 gradle 编译（不许只语法解析）；每屏做完跟对应截图肉眼对照布局/配色/文案；派子代理/codex 干活后独立核实自报不盲信。

【刹车】跑满 40 轮，或连续 2 轮没推进任何新屏，就停下，把当前差异矩阵进度 + 已对齐/待办屏数贴进对话报告，不要空转烧 token。
```
