> **作用**：repo 里**每个文件**是什么、干什么用的、谁能改、什么时候读 —— 一次全列清楚。
> **目的**：防止 itsuki / AI / 将来接手的人找不到文件、不知道有什么文件可用。
> **建立**：2026-04-21 晚 by [Code-Agent]
> **最后更新**：2026-04-22 下午（Round 3 交付后刷新 teacher_web/ 子条目）
> **权威关系**：
> - 顶级目录（DMSD/{00-99}/）见 `CLAUDE.md §目录结构` + 本文 §2
> - 文件级详细（每个 `.md` / `.py` / `.jsx` 做什么）**以本文为准**
> - 两者必须保持一致；本文应当完整覆盖 CLAUDE.md 里列的顶级目录

## 0. 怎么用这个指南

### itsuki（查找文件）
- 想找某类文件（"AC 叙事的 XX 放哪"）→ §3 反向索引
- 想知道某个文件夹里都有什么 → §2 完整目录树
- 想知道某文件能不能改 → §4 权限速查表

### AI / CC（session 开始时）
- CLAUDE.md → 本文件 → WIP.md 三件套快速建立 context
- 新建文件后 → 追加到本文对应 section
- 删除 / 重命名 / 移动文件 → 同步更新本文

### 更新规则
- **任何人**新建 / 删除 / 重命名文件时，同步更新本文对应行
- 大规模重构（整文件夹 mv）→ 更新 §2 整棵树 + §3 反向索引
- 本文版本戳在末尾（纯 `YYYY-MM-DD` 注释，不是 SemVer —— 否则 pre-commit hook 会拦）
