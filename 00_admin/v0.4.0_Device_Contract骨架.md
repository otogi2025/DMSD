## 建议章节结构

### §0 文档元数据
- 版本、最后更新、对应 `RollCall_Spec.md` 版本
- 文档定位："Device ↔ Server 的接口契约。代码 / 硬件 / 架构决策变化都会 bump 本文件版本号"

### §1 目的 + 适用范围
- 本文件定义：点呼机（device，路径 A 的 `card_reader`）和后端 server 之间的**所有交互协议**
- **不定义**：点呼机内部硬件（PN532 接法 / I²C 命令）—— 那是 `02_design/hardware_design.md`
- **不定义**：学生端 / 老师端 App 契约 —— 那是 `API_CONVENTIONS.md` 和其他 spec
- 术语对齐：device（点呼机 / Pi）/ server（后端 FastAPI）/ session（点呼场次）/ card（NFC 卡）

### §2 点呼机职责边界（从 `RollCall_Spec.md §9` 抽过来 + 扩展）
- **职责**：读 NFC 卡 UID / HTTP 发后端 / 听 WebSocket 推送 / 播报姓名+状态 / 亮灯（红/绿/黄） / 可选屏幕显示
- **非职责**：
  - ❌ 不保存学生身份（UID ↔ 姓名映射全在后端）
  - ❌ 不判准时 / 迟到 / 缺席（服务器唯一判定者）
  - ❌ 不缓存 session 状态（每次签到都实时查服务器）
  - ❌ 不计算幂等键（要么不用，要么后端去重）
- **网络假设**：设备和后端之间走 HTTPS（TLS），延迟 < 1s（校园 WiFi 正常情况）

### §3 HTTP 契约

#### §3.1 POST `/api/v1/checkin`（路径 A 核心，Phase 1 必须）

**请求 body**（draft）：
```json
{
  "device_id": "dorm-1-01",       // 🔄 取值范围 see DEVICE_REGISTRY §6 候选位置 — 是否确认保留 `A/B` 命名（S18）？
  "card_uid": "04a1b2c3d4e5f6",   // 14 位 hex 小写（S2 field draft）
  "scanned_at": "2026-09-01T18:30:12+09:00"  // 🔄 是否需要客户端时间？后端可以用 server_now 一致
}
```

**响应 body（成功）**：
```json
{
  "ok": true,
  "data": {
    "student_name": "张三",
    "base_status": "present",         // 或 "late" / "absent"
    "path_type": "A",
    "session_id": "s_20260901_morning",
    "broadcast_text": "张三 准时",     // 播报用文本（后端生成，前端直念）
    "led_color": "green",             // 🔄 是否用 "success/warn/fail" 语义而不是颜色？
    "seat_no": 3                      // 可选，老师端已经通过 WS 更新，设备只用于播报
  }
}
```

**响应 body（失败）**：参见 §6 错误处理。

**Open questions**（需 itsuki 拍板）：
- 🔄 **设备身份认证**：是 `device_secret` header / mTLS 客户端证书 / JWT device token？三选一
- 🔄 **是否需要请求签名**（nonce + HMAC）防止重放攻击？（看议题 A 的 ECDSA 方案是否也适用于 device-server 通信）
- 🔄 **响应超时**：设备 HTTP 超时后怎么处理（红灯 + 声音 "联网失败"？还是自动重试 N 次？）

### §4 WebSocket 契约（收口附录 B.17）

#### §4.1 连接建立
- URL: `wss://<server>/ws/device/<device_id>`
- 认证：🔄 header `Authorization: Bearer <device_token>` / query param `?token=xxx` / 首条消息做 handshake
- 连接生命周期：设备开机 → 连接 → 保持 → 断网重连（exp backoff）→ 设备关机 → 断开

#### §4.2 消息格式（统一 JSON）
```json
{ "type": "broadcast", "data": { ... } }
```

#### §4.3 消息类型清单（draft）

| 方向 | type | data | 用途 |
|---|---|---|---|
| server → device | `broadcast` | `{student_name, base_status, led_color, ...}` | 路径 B 场景下，服务器收到学生 iPhone 签到后推回设备播报（收口附录 B.17）|
| server → device | `session_started` | `{session_id, scheduled_window_start_at, ...}` | 老师按开始钮时通知所有设备"可以读卡了" |
| server → device | `session_ended` | `{session_id, settle_at}` | 老师按结束钮时通知 |
| server → device | `device_reload` | `{}` | 配置变更时通知设备重新拉 `/api/v1/device/config` |
| device → server | `heartbeat` | `{ts, firmware_version}` | 心跳（若不用 HTTP health） |
| device → server | `error_report` | `{code, message, context}` | 硬件错误 / 异常事件上报 |

#### §4.4 心跳 + 重连
- 🔄 心跳间隔：30s / 60s
- 🔄 超时未收到心跳：server 侧标 device 离线（多少秒？）
- 🔄 重连策略：exp backoff 初始 1s 最大 60s

### §5 设备配置字段（给 device 本地 `config.json` / env var 用）
- `device_id`（静态，从 DEVICE_REGISTRY 分配）
- `device_secret`（🔄 放 env var 还是 TPM / Keychain）
- `server_url`（`https://dmsd.otogi2025.com` 或同类）
- `ws_url`（同上 scheme `wss://`）
- `led_pin_red` / `led_pin_green`（GPIO 号，硬件设计决定）
- `speaker_device`（ALSA device 名）

### §6 错误处理

#### §6.1 HTTP 错误码 → LED/声音对照表

| 错误码 | LED | 声音 | 播报 |
|---|---|---|---|
| `UNKNOWN_CARD` | 红 | 失败 | "未登记的卡" |
| `UNREGISTERED_UID` | 红 | 失败 | "卡已停用" |
| `SESSION_NOT_RUNNING` | 黄 | 等待 | "点呼未开始" |
| `INVALID_SIGNATURE` | 红 | 失败 | "设备未授权"（通常是设备问题，不该直接发声，建议黄灯 + 静默） |
| `ALREADY_CHECKED_IN` | 绿（静默）| 静音 | 无（幂等重复不算错，静默接受） |
| 网络超时 / 5xx | 黄 | 短"嘟"声 | 不播报 |

#### §6.2 网络降级策略（收口附录 B.8）
- 🔄 **方案 A 严格拒绝**：离线则拒绝签到，红灯 + 播报"联网失败"（需老师手动处理）
- 🔄 **方案 B 缓存等待**：本地缓存 UID + 时间戳，网络恢复后批量 POST（需要本地 SQLite）
- 🔄 **方案 C 降级模式**：网络中断 > N 分钟时设备自动进入"记录模式"（只记不验），老师事后处理
- **推荐**：**A**（Phase 1 点呼期短 [~10 分钟]，断网概率低，Thin client 原则简化实现）

### §7 生命周期

#### §7.1 设备上电流程
1. 读 config.json
2. 向 server POST `/api/v1/device/register`（首次）或 handshake（已注册）
3. 建立 WebSocket 连接
4. 进入 ready 状态，LED 熄灭 / 白灯待机
5. 等待 session_started 消息

#### §7.2 设备维护 / 更新
- 🔄 固件更新机制：手动 SSH / OTA / server 推送

#### §7.3 设备退役
- `DEVICE_REGISTRY §5 device_active=false`（临时停用）/ `device_retired_at` 非 null（永久注销）
- 🔄 退役前本地数据清理 checklist
