
**编号规则**: 前缀数字表示工作流顺序(00 管理 → 01 规格 → 02 设计 → 03 开发 → ... → 99 归档)。空目录是预留的,等需要时再用。

## 根目录文件

| 文件 | 作用 | 修改频率 |
|------|------|---------|
| `CLAUDE.md` | Claude Code 的项目指令。每次 AI 会话自动加载。记录对 AI 的要求、项目信息、沟通规则。 | 偶尔(AI 协作规则变化时) |
| `CHANGELOG.md` | 版本变更记录。每次发版本号时更新,按 SemVer 规范。 | 每个版本更新一次 |
| `.gitignore` | 告诉 Git 哪些文件不要追踪(`.DS_Store`、编辑器临时文件等)。 | 很少 |
| `.git/` | Git 内部文件夹,**不要手动动**。版本历史全在这里。 | Git 自动管理 |

## 00_admin/ — 项目管理

**什么放这里**: 项目的**管理性、快照性**文档。不是日志(日志在 05_logs),也不是规格(规格在 01_specs)。

```
00_admin/
├── progress_overview.md              项目当前状态快照(每次会话结束更新)
├── executable_dev_checklist_v0.1.md  可执行开发清单(v0.1 规格冻结时定的)
└── 目录架构.md                        ← 本文件
```

| 文件 | 作用 |
|------|------|
| `progress_overview.md` | 项目走到哪了。包括: 进度 checklist、技术学习时间线、关键决策索引、问题解决索引、当前待办、仓库结构地图。**每次会话结束必须更新**。 |
| `executable_dev_checklist_v0.1.md` | v0.1 冻结时写的开发清单,按阶段拆分(0-10 阶段)。后面按这个清单推进开发。 |
| `目录架构.md` | 本文件。解释每个文件夹/文件的用途。 |

### raw/ 和 dev_log/ 的关键区别

**不是**"AI 写的 vs itsuki 写的"。
**是**"**对话过程转储 vs 叙述式总结**"。

| | raw/ | dev_log/ |
|---|------|----------|
| 性质 | 对话过程的原始捕捉 | 一天的叙述总结 |
| 长度 | 可能很长、很碎 | 紧凑、结构化 |
| 风格 | 包括讨论过程、弯路、被否决的想法 | 只留结果和关键推理 |
| 类比 | 科研的"实验记录本" | 科研论文的"方法和结果" |
| 来源 | AI 对话 / 随手记 / 会议录音转录 | 可能从 raw 提炼,也可能直接写 |

**同一个事件可以两个文件都有**,它们互为引用。raw 是"证据",dev_log 是"叙述"。

### 三种文档的分工

| 层级 | 性质 | 例子 |
|------|------|------|
| **方法论层** | 教你怎么做 | ac_入試准备/AC考试记录指南.md |
| **开发叙事层** | 累积式总览 | learning_path.md, project_evolution.md |
| **日/主题累积层** | 一个个独立记录 | dev_log/*.md, problem_solving/*.md |
