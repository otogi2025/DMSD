## 1. 先要许可 — 话术（demo 结束后顺势问）

**时机**: `demo_script.md §10` 收尾后，接 `questions_for_admin.md A2`。

**原话（推荐直接读）**：

> "老师，点呼机要连宿舍 Wi-Fi 才能把学生的签到发给后端。我想 demo 结束后在宿舍大厅和玄关这些公共区域，用我自己的 Mac 和 iPhone 做一次 Wi-Fi 测试，大概 30 分钟。
>
> 我**不会**接触学校任何设备，**不会**登录任何学校账号，**不会**访问学校内网系统。只是像查地图一样扫一下空气中的 Wi-Fi 信号，测一下我自己带来的两台设备之间能不能通话。
>
> 这样我才能判断点呼机应该放哪里信号最好，demo 后的采购数量也能算得准。可以吗？"

**为什么这样说**:
- 明确"被动测量"（扫信号）和"主动入侵"（登录系统）的区别
- 只用自己的设备 = 对学校网络零影响
- 讲清楚目的 = 为上线规划做准备，不是好奇心
- 给管理员一个"说不"的退路（"这样可以吗？"）

**如果管理员说"要问 IT 部门"**:
> "好的，您方便的话帮我转达一下，或者告诉我 IT 部门的联络方式。我可以等 IT 部门批准后再测。"

**如果管理员说"不行"**:
- 不要争辩。回去用"询问式"研究：让管理员告诉你 Wi-Fi SSID 名称 / 速度大概多少 / 大厅有没有插座 —— 这些他都知道。
- 降级方案：先按"默认宿舍有可用 Wi-Fi + 没有客户端隔离"设计，上线前再要一次许可。

## 2. 要测什么（4 个核心点）

| 测什么 | 为什么重要 | 10 秒判断法 |
|---|---|---|
| **信号强度** | 点呼机装的地方信号不到 -75 dBm 就会断连 | Mac 菜单栏按 Option 点 Wi-Fi 图标看 RSSI |
| **客户端隔离** | 如果宿舍 Wi-Fi 对学生开启客户端隔离，点呼机和 iPad 无法互通 — 这是**最致命**的 | Mac 连上后 ping iPhone 的 IP |
| **速度 + 延迟** | 影响 WebSocket 推送是否卡 | speedtest.net 一次 |
| **SSID 结构** | 搞清楚有几个 SSID（学生 / 管理 / 访客）+ 各自网段 | Mac 菜单栏扫一下 |

## 4. 具体操作步骤（按位置测 4-5 点）

### 4.1 选测试点位（演示前和管理员商量）

典型位置：
1. **宿舍大厅**（入口处，学生必经点）
2. **玄关 / 下駄箱**（换鞋区）
3. **每个楼层电梯口**（点呼机理想位置）
4. **itsuki 自己房间**（对照点）
5. **走廊中段**（信号最远点）

每个点测 5 分钟。

### 4.2 每个点位做的 5 件事

**步骤 1 · 看 Wi-Fi 信号强度（30 秒）**

Mac 操作：
```
1. 菜单栏按 Option 键 + 点 Wi-Fi 图标
2. 看 "RSSI" 那一行（单位 dBm）
3. 记录：SSID 名字 + RSSI 数字
```

**判断标准**:
- `-30 ~ -50 dBm` = 极佳（像站 AP 旁边）
- `-50 ~ -65 dBm` = 好（够点呼机用）
- `-65 ~ -75 dBm` = 一般（刚好能跑，WebSocket 可能断）
- `-75 dBm 以下` = 不行（点呼机会频繁掉线）

**例子记录**:
```
位置：宿舍大厅入口
SSID：Dormitory-Student
RSSI：-58 dBm
判断：好
```

---

**步骤 2 · 扫描所有 Wi-Fi SSID（30 秒）**

Mac 操作（Terminal）：

```bash
# 注：airport 命令 macOS Sonoma 起被部分移除，新机器用 wdutil
# 方法 A（老 Mac / 大部分还能用）：
/System/Library/PrivateFrameworks/Apple80211.framework/Versions/Current/Resources/airport -s

# 方法 B（新 macOS 14+）：菜单栏看 Wi-Fi 图标展开列表即可
```

**判断**:
- 有几个**明显属于宿舍的** SSID（例如 `Dormitory-Student` / `Dormitory-Staff` / `Dormitory-Guest`）
- 哪些是**学校的**（例如 `University-Main`）
- 哪些是**学生热点 / 邻居干扰**（例如 `iPhone-Zhang` 这种）

**记录**: 列出宿舍相关 SSID 名字 + 频段（2.4/5GHz）。

---

**步骤 3 · 测客户端隔离 ⭐⭐⭐ 最关键（2 分钟）**

**为什么关键**: 如果宿舍 Wi-Fi 开启了 "客户端隔离"（每个连上的设备看不见其他设备），点呼机就没法把 WebSocket 推到 iPad、iPhone 也没法直连 Mac 后端。**这会直接卡死整个架构**。

**测法**：

```
1. Mac 连上宿舍 Wi-Fi（比如 Dormitory-Student）
2. iPhone 连上同一个 Wi-Fi
3. iPhone 查 Wi-Fi 详情 → 看"IP 地址"（例如 192.168.10.45）
4. Mac 打开 Terminal：
   ping 192.168.10.45
```

**判断**:
- ✅ **ping 通**（看到 `64 bytes from ...`）→ 没有客户端隔离，可以跑
- ❌ **ping 不通**（全部 `Request timeout`）→ **客户端隔离开启**，架构要改（走外网 WebSocket 代替局域网）

**如果 ping 不通，不要慌**，这是好消息 — 早发现早想办法：
- 方案 A：点呼机 + iPad 都连**管理员的 Wi-Fi**（如果有独立 Staff SSID）
- 方案 B：后端放外网 VPS，所有设备连外网 → 绕过隔离
- 方案 C：Mac 开自己的热点，所有设备连热点（demo 可用，上线不行）

---

**步骤 4 · 测速度 + 延迟（30 秒）**

iPhone 或 Mac 访问：
```
https://fast.com
https://speedtest.net
```

记录：
- 下载速度（目标 > 5 Mbps 够用）
- 上传速度（目标 > 2 Mbps 够用）
- 延迟（Ping，目标 < 50ms）

**判断**: 点呼机只发小包，速度不是瓶颈；但**延迟 > 200ms** 会让"tap → iPad 变绿"感觉卡，这是 demo 的 wow moment 必须保证。

---

**步骤 5 · 查网关 IP + DHCP 信息（30 秒）**

Mac Terminal：
```bash
# 看 Mac 拿到的 IP 和网关
ifconfig en0 | grep "inet "

# 查 DHCP 详情
ipconfig getpacket en0
```

记录：
- Mac IP（例如 `192.168.10.23`）
- 网关（`192.168.10.1`）
- DNS（`8.8.8.8` 或学校内 DNS）
- DHCP lease 时长

**判断**: 如果 DHCP lease < 1 小时（例如 30 分钟），点呼机每 30 分钟 IP 就可能变 — 得跟老师申请固定 IP 或 Reservation。

## 7. 零基础术语速查

| 词 | 意思 | itsuki 能理解的说法 |
|---|---|---|
| SSID | Wi-Fi 的"名字" | 比如 "Dormitory-Student" 这个名字 |
| RSSI | 信号强度 | 类似手机信号格数，数字越接近 0 越好 |
| dBm | 信号强度单位 | -50 比 -70 强（负数，越靠近 0 越强）|
| 客户端隔离 | AP 把每个连的设备彼此隔开 | "连上同一 Wi-Fi 但互相看不见" |
| DHCP | 路由器自动分 IP | "连上 Wi-Fi 自动给你个门牌号" |
| 网关 | 上外网要经过的出口 | "Wi-Fi 的大门" |
| VLAN | 虚拟局域网分组 | "同一个物理 Wi-Fi 分成多个不同小组"|
| Captive Portal | 连上后弹登录页 | 机场 Wi-Fi 那种要求输账号的页面 |

## 8. 如果管理员 IT 部门不允许测

**降级方案**（仍能推进）:
1. 管理员自己回答的**定性**信息足够起步：
   - 学生能连宿舍 Wi-Fi 吗？（是 / 否）
   - Wi-Fi 卡不卡？（流畅 / 一般 / 卡）
   - 学生之间能互相 AirDrop 吗？（是说明没隔离 / 否说明可能隔离）
2. 先按"宿舍 Wi-Fi 能用 + 没有客户端隔离"的**乐观假设**做 demo
3. 上线前 2 周**再要一次许可**（那时候已经有 demo 采纳背书，管理员更容易同意）
