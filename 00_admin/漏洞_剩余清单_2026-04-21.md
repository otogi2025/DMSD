## 给下次会话的操作指引（严格按以下三条走）

### 1. 开工前验证
- 读 `00_admin/WIP.md` 顶部看"当前焦点"有没有本会话能认领的文件
- 跑 `git status` 看有没有跨会话未 commit 冲突
- 读本文件对应的漏洞条目（含 backlog line 指针）

### 2. 修完单条后
- backlog.md 里该条打 ✅ + 尾巴加 `~~2026-04-2X 打 ✅：[改了哪个文件的哪段] [改成什么]~~`（保留原文字做证据链）
- 不删 backlog 条目
- pre-commit hook 会自动跑（含硬编码版本号会被拦）

### 3. commit + push 纪律
- commit 前只 stage 本会话改的文件（`git add <specific files>`，不 `git add .`）
- commit message 用 HEREDOC，带 Why + What + Not doing 三段
- 不写 `Co-Authored-By` trailer（memory `feedback_commit_style`）
- 不 push 除非 itsuki 明说"push"（今日 4-21 晚这次是明示了所以 pushed）
- 不打 release tag 除非 v0.4.0 MVP 必修全闭合 + itsuki 授权

### 4. 遇到以下情况 —— 停 + 问 itsuki，不自己推进
- 漏洞标 **[等拍板]** —— 先问业务决策
- 漏洞标 **[等授权]** —— 先确认"做 X"
- 要动 `05_logs/decision_log.md` / `project_evolution.md` / `learning_path.md` 正文 —— CC 永不直写
- 要动 iCloud AC 目录 `03_素材_候选/` / `04_素材_成品/` / `05_产出/` —— 需 itsuki 当场授权（`05_产出/` 永不写）
