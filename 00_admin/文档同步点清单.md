## § 1 — 版本号

**单一真值**：`CHANGELOG.md` 顶部第一条 `## [vX.Y.Z] - YYYY-MM-DD` 就是"当前版本号"。

**二级源**（双源同步，bump 时一起改）：`00_admin/WIP.md` 头部第一行 `**当前版本**: vX.Y.Z`（带 `<!-- VERSION_OK -->` 豁免）。

**版本 bump 操作流程**：`.claude/skills/version-bump/SKILL.md`（**skill 形态运行手册**，2026-05-04 从 `00_admin/版本管理SOP.md` 整体迁入 skill；itsuki 说"迭代/bump/发版本/打 tag"自动触发；加 4 条新铁律：CC 否决权 / 版本演变一览必更新 / 全量扫描 / 关键词加"迭代"）。和 iCloud `00_通用指南/版本管理实践指南.md`（**教科书**）分工。

### 规则

- 其他文件**不写**具体版本号
- 引用时用 "当前版本见 `CHANGELOG.md` 顶部" 这类指针

### 声明性文件（pre-commit hook 会拦）

下面这些文件里如果出现 `v0.X.Y` / `v1.X.Y` 等模式，pre-commit hook 会拒绝 commit：

- `CLAUDE.md`
- `00_admin/WIP.md`
- `00_admin/TODO.md`
- `00_admin/progress_overview.md`

### 允许出现版本号的文件（hook 不检查）

- `CHANGELOG.md`（权威）
- `01_specs/**/*.md`（spec 里引用历史决策 "v0.2 时决定..." 是正常的，不是状态声明）
- `05_logs/**/*.md`（日志写"今天 bump 到 v0.3.0"是记录）
- `99_archive/**`（归档区）
- `00_admin/2026-04-19_项目审查_backlog.md`（审查报告里引用各版本）
- `00_admin/hooks/**`（hook 脚本本身会举例提版本号）
- `00_admin/文档同步点清单.md`（本文件）

### 豁免机制

如果某行必须写具体版本号（极少见），**在该行末尾加 `<!-- VERSION_OK -->`** 注释，hook 会跳过。

例（本清单也用得着）：

```markdown
当前版本见 CHANGELOG.md 顶部
上个版本 v0.2.0 做了字典重构 <!-- VERSION_OK -->
```

## § 6 — 打 tag 前的 Release Checklist

每次 `git tag v0.X.Y` 前按这个清单走一遍：

- [ ] `CHANGELOG.md` 加新版本条目（含日期 + "为什么 bump 的说明"）
- [ ] `CHANGELOG.md` 头部"最后更新"时间戳刷新
- [ ] 跑 `git status` 确认相关改动全部已 staged
- [ ] `git commit` 前 pre-commit hook 自动跑一致性检查（通过后再打 tag）
- [ ] `git tag vX.Y.Z -m "..."` + `git push origin vX.Y.Z`
- [ ] 本次 bump 有"重大决策" → 在 `05_logs/raw/YYYY-MM-DD.md` dump 一份（CLAUDE.md 规定"版本号 bump 时必须触发 AC 记录"）

## § 11 — 文件联动规则（2026-05-04 拍板，A+B 方案）

> **背景**：itsuki 2026-05-04 指出"改 X 必查 Y"的人肉 checklist（CLAUDE.md §会话结束 §3 文件关联追踪表）只在会话结束跑 1 次，中途漏率高。**拍板做 A+B**：A = pre-commit hook 加内容检查；B = `bin/sync-check.sh` 中途随时查。规则代码化在 `00_admin/hooks/lib/sync-rules.sh`。

### 单一真值（双层）

- **人类可读**：`CLAUDE.md §会话结束 §3 文件关联追踪表` — itsuki 查这里
- **代码源**：`00_admin/hooks/lib/sync-rules.sh` — 工具读这里

> **铁律**：两边内容必须等价，加规则时同步两边。

### 工具

| 时机 | 命令 | 行为 |
|---|---|---|
| **commit 前自动** | `git commit`（pre-commit hook 自动调用）| 仅提示 staged 文件的联动漏改，不阻断 |
| **会话中途随时** | `bash bin/sync-check.sh` | 检查全部 working tree（含 untracked）|
| **会话中途仅 staged** | `bash bin/sync-check.sh --staged` | 模拟 pre-commit 行为 |
| **指定文件** | `bash bin/sync-check.sh <file1> ...` | 检查特定文件 |

### 规则表（当前 13 条 — 详见 `lib/sync-rules.sh` 源码）

| 名字 | 触发 | 必查（must）/ 提示（action） |
|---|---|---|
| `backend-models` | `models.py` | must: schemas.py / migration / routers / iOS NetworkModels.swift |
| `backend-routers` | `routers/*.py` | must: iOS Endpoints/*API.swift |
| `system-features` | `system_features.md` | must: 各端 *_DESIGN_LOG.md（任 1）|
| `ios-route` | `Route.swift` | must: RootView.swift |
| `ios-hook` | iOS 任意 .swift | action: 跑 sync-ios-refs.sh |
| `spec-body` | `01_specs/*.md` | action: 触发 version-bump skill §10 |
| `design-doc` | `02_design/*.md` 主设计 | action: 触发 SOP §2 |
| `hooks` | `00_admin/hooks/*` | must: hooks/README.md |
| `bin-script` | `bin/*.sh` | must: CLAUDE.md / 同步点清单 / hooks README |
| `ios-foundation-{pill,card,avatar,glasssheet}` | Foundation/*组件* | action: grep 全 repo 找 caller |
| `new-declarative` | 新建 CLAUDE.md / 00_admin/*.md | action: 加入本同步点清单 |

### 维护

加新规则 → 改 `lib/sync-rules.sh`（add_rule 一次）+ 同步 `CLAUDE.md §会话结束 §3` + 同步本节表 + 更新 `00_admin/hooks/README.md "如何调整"`。
