## 🟥 Tier A · Demo 当天必问（5-8 个精选，阻塞上线决策）

> **使用**: 演示结束的 §10 收尾部分（`demo_script.md §10`）自然接入。目标 5-10 分钟问完。

### A1. ⭐ 系统上线预算谁出？（2.1 + 2.2 + 2.3 合问）

**问法**：
> "如果方向可以，硬件采购大概需要初始 ¥30800 日元（点呼机 4 台 + NFC 卡 120 张 + 配件）+ 月费 ¥500 日元（服务器）。这笔预算是宿舍出、学校出、还是我自己垫先运营？"

**为什么问**: 不问就不知道采购策略 — 自垫 vs 申请拨款 vs 众筹，流程完全不同。
**期待答复格式**: "宿舍 / 学校 / 学生プロジェクト支援金 / 你自己先垫后报销 / 再讨论"
**答复**: _（demo 当天填）_

### A3. ⭐ 学生数据存私人 VPS 合规吗？（5.1）

**问法**：

## 🎯 Demo Day 使用说明（itsuki 打印一张放口袋）

**演示流程（`demo_script.md`）走完 §1-§9 后到 §10 收尾时：**

1. **先问 Tier A 的 A8**（管理员头疼什么）— **让她先说**，避免你自嗨
2. **再问 A1 / A2 / A3 / A4 / A5 / A6 / A7** — 按这个顺序（预算 → 测试许可 → 合规 → 现状 → 规模 → 时间 → 角色）
3. **如果气氛好 + 她主动问系统细节** → 追 Tier B 相关题
4. **其余 Tier C** → 结束后写邮件 or 下次见

**录音**: 征求同意后用 iPhone 录音（Apple Notes 内置录音 or Voice Memos），演示后 itsuki 自己听 + 誊录到 `raw/2026-04-28.md`。

**不要问**:
- 技术实现细节（管理员不懂 / 不是她职责）
- 暗示系统已经决定要上的话术（要保持"请您评估"的姿态）
- 其他竞品 / 过往失败案例（敏感，除非她主动提）
