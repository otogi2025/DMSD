## 3. 开始点呼 + 学生 tap 签到（3 分钟）⭐ 核心

### 3.1 老师开点呼

**动作**：引导管理员点击"点呼" → "开始点呼"按钮

> "第一步，您点'开始点呼'。这就进入了实时座位表。"

**iPad 显示**：座位表，所有学生灰色（未签到）

> "现在所有学生都是灰色，表示还没签到。"

### 3.2 学生 tap

**动作**：itsuki 拿 iPhone 和一张 NFC 卡（银行卡 / Suica / PASMO / 学生证），站到管理员旁边

> "现在我作为学生，拿手机碰一下这张 NFC 卡 — **上线版这是贴在宿舍玄关点呼机上的专用 NFC 贴纸**，今天我用手里这张卡演示同样的动作。"

**动作**：iPhone 靠近 NFC 卡 → 等待 1-2 秒

**发生的事**：
- iOS Shortcuts 自动触发 → 后端 POST /api/checkin
- 后端 WebSocket 推送 → iPad 座位变绿（リュウイヒ 的座位）
- iPad Safari Web Speech API 发声："リュウイヒ"

**动作**：指 iPad + 听 iPad 扬声器

> "看，**我的座位瞬间变绿了，iPad 也念出了我的名字 リュウイヒ**。
>
> 这个念名字的功能是故意设计的 **防作弊** — 如果有人用别人的手机来代签，系统念的是被代签学生的名字，其他在场的学生一听就知道不对，会举报。这是我的一个**原创设计**，我专门写了设计说明文档 `原创设计_语音播报防作弊.md`。
>
> 上线版这个声音会从**宿舍门口的点呼机喇叭**发出，覆盖整个玄关区域。今天 demo 我暂时用 iPad 的扬声器代替，原理一样。"

### 3.3 讲颜色含义

**动作**：指 iPad 座位表

> "座位表颜色的意思是：
> - **绿色** = 准时到
> - **黄色** = 迟到
> - **红色** = 超时仍未到，缺席
> - **灰色** = 点呼进行中，还没签到
> - **蓝色** = 免点呼（批假了）
> - **红色十字叠加** = 提交了健康问题（发烧、不舒服等）
> - **橙色问号叠加** = 提交了'本次不去点呼'申请，等您审批"

## 11. 管理员可能的追问（备用应答）

### Q1: 学生拍照 URL 发给朋友代签怎么办？
→ 见 `ST25DV_fallback.md §5.2`（讲上线版 ST25DV 动态 nonce）

### Q2: 学生换手机怎么办？
> "学生新手机下载 App 登录时，旧手机的密钥会自动作废。换机不用找老师，但最开始注册账号时需要老师扫码面签确认身份。"

### Q3: 没手机的学生怎么办？
> "有两种方式：一种是发 NFC 卡（NTAG215 空白卡），学生贴个自己的名字贴纸，在点呼机上刷卡签到。另一种是老师管理员后台代录。大多数人会用手机，但宿舍肯定有 1-2 个没手机的，这两个通道都有。"

### Q4: 点呼机坏了怎么办？
> "上线版计划是 4 台点呼机分布在宿舍不同位置，1 台坏了其他 3 台还能用。如果全坏了，可以降级为老师 iPad Web 直接手动勾选到齐（就是刚才我演示的手动改判）。
>
> **另外 demo 今天您看到的场景就是'没有点呼机硬件'的极端情况**：我用 iPhone + 一张 NFC 卡模拟，整个系统照样跑 — 这个 fallback 能力是架构设计时就有的。"

### Q4.5: 今天为什么没真的点呼机？（管理员可能注意到）
> "好问题。Raspberry Pi 和 NFC 读卡器的硬件我 4-21 做过完整选型（我可以给您看 hardware_design 文档），但 7 天 deadline 里最大的风险是硬件驱动调试 — PN532 NFC 读卡器通过 I²C 接到树莓派有可能调不通，那样我 demo 就卡住了。所以我有意把硬件推迟到您采纳以后再采购实装。
>
> 今天 demo 只用软件跑，**流程和最终版 100% 一样** — 只是扬声器从点呼机移到 iPad。这样 demo 成功率从 60% 拉到 95%，我和您都能看清楚系统能做什么。"

### Q5: WiFi 断了怎么办？
> "点呼机会本地缓存签到记录，WiFi 恢复后自动上传。老师 Web 也能离线查看之前的记录。"

### Q6: 学生在别的学生手机上装 App 代签？
> "App 注册时用 Apple 的 Secure Enclave 硬件安全芯片生成密钥，这个密钥绑定手机硬件取不出来。一个手机登录 A 同学账号后，给 B 用就必须重新登录 B 的账号 — 但同时 A 的旧密钥就作废了，A 签不了。相当于'一部手机同时只能是一个活跃学生的签到工具'。"

### Q7: 一个人同时持有多个手机怎么办？
→ 这个场景 demo 没覆盖完整风控，老实答：
> "这个边缘情况我想法是：每个学生注册只能绑一个 '当前活跃设备'，换新设备旧设备自动作废。如果两个设备同时想签到，后来的被作废那个就失败。我会在上线前补全这块策略。"

### Q8: 系统成本能细一点吗？
→ **上线采购（您采纳之后）**：
- 点呼机 4 台（Raspberry Pi 3A+ + PN532 NFC 读卡器 + 喇叭 + 外壳）：单台 ¥6500 日元 × 4 = **¥26000 日元**
- NFC 卡 120 张（NTAG215 空白卡）：¥40 × 120 = **¥4800 日元**
- 后端服务器（日本 VPS）：**¥500 日元 / 月**
- **初始一次性 ¥30800 日元 + 月费 ¥500 日元**
- 淘宝批量采购（点呼机 3 台 + 110 张卡 + 配件）约 ¥1345 RMB ≈ ¥26900 日元，稍省
- **Demo 当前开销**：¥0 — 所有设备（Mac / iPhone / iPad）都是我自有的，演示用的 NFC 卡是我手里的银行卡 / Suica
- **关于这笔预算谁承担**，我正想和您商量（宿舍 / 学校申请 / 我先垫付？）

### Q9: 学生隐私 / 数据保护？
> "数据存在我个人租的服务器上，GPDR / 个人情报保护法的要求我会按规范做。毕业交接时会完整交给下一届接手的学生或老师。"

### Q10: 这个系统维护谁来做？
> "我毕业之前我自己维护 + 带一个学弟学妹跟着学。毕业前会把所有运维文档、账号密码、服务器凭证、Android App 签名证书打包交接。我会设计整套交接流程保证连续性。"
