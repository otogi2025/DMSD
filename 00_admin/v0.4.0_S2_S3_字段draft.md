## 1. `card_uid`（S2 🔴）

**应放位置**：`FIELD_REGISTRY_v0.1.md §2.2 身份与对象`，紧接 `device_id` 之后。

### 推荐定义

```markdown
- `card_uid`（**4-21 新增** — 详见 `RollCall_Spec_v0.1.md §10.2` + `ENUM_REGISTRY_v0.1.md §13 path_type=A`）
  - 类型：string，长度 14（固定，NTAG215 UID = 7 bytes hex 编码）
  - 约束：`UNIQUE`，大小写不敏感（统一存小写）
  - 关联：**多对一**到 `student_id`（支持换卡 — 旧 UID 作废但记录保留，新 UID 绑定同一 `student_id`）
  - 生命周期：`card_issued_at` / `card_active`（见 2.9 卡生命周期）
  - 仅路径 A（NFC 卡）使用；路径 B（iPhone / Android 贴纸）不通过此字段识别
```

### 建议新增配套字段（§2.9 卡生命周期，新建 subsection）

```markdown
### 2.9 卡生命周期（**4-21 新增**）
- `card_uid`（见 2.2）
- `card_active`（boolean，是否启用；停用 = false，废弃但保留历史记录）
- `card_issued_at`（发卡时间）
- `card_revoked_at`（作废时间；null = 仍在用）
- `card_revoke_reason`（自由文本："挂失补办" / "毕业回收" / "被停用" 等）
```

### 取值范围说明

- NTAG215 标准 UID：7 字节（例如 `04 A1 B2 C3 D4 E5 F6`），读卡器返回时通常转为 14 位 hex 字符串
- 推荐存储格式：**小写 hex 字符串，无分隔符**（如 `04a1b2c3d4e5f6`）
- 不推荐存 base64 / binary：调试时 grep 和 SQL 写 WHERE 很麻烦

### 依赖 / 连锁

- **S10 路径 A 幂等方案依赖**：`idempotency_key` 改成 `(card_uid, session_id, ts_secondbucket)` 复合唯一索引
- **S1 修复依赖**：§7 边界 `卡未启用` 判据用 `card_active=false`（而不是错位的 `device_active=false`）
- **数据库约束**（v0.6.0 migration 阶段）：CREATE UNIQUE INDEX on `(card_uid) WHERE card_revoked_at IS NULL` —— 同一时刻同一 UID 只能绑一个 active 学生

### 备选方案（如 itsuki 有不同偏好）

- **存 bytes 而非 hex**：DB 层省 7 字节存储，但 debug 体验差 → **不推荐**
- **UID 大小写敏感**：多数读卡器返回大写，但 NFC Forum 标准不区分大小写 → **不推荐**（统一小写更省事）
- **允许多张卡绑同一学生同时 active**：场景："学生主卡 + 备用卡"。目前 spec 一卡一人，如需扩展留 v0.5.0+ 讨论

## 2. `student_status`（S3 🔴）

**应放位置**：`FIELD_REGISTRY_v0.1.md` 新建 `§2.10 学生生命周期`（原 §2.x 编号可调）。

### 推荐定义

```markdown
### 2.10 学生生命周期（**4-21 新增** — 对应 `RollCall_Spec_v0.1.md` 附录 C.5）

- `student_status`（ENUM，取值见 `ENUM_REGISTRY_v0.1.md §14 student_status`）
  - `active`（在寮，进入每日 session 座位表）
  - `paused`（请假期间，用"免点呼范围"覆盖；见 spec §8.2）
  - `transferred`（转学离开，此状态后的 session 不再计入）
  - `graduated`（退寮 / 毕业，同上）
  - default: `active`（新学生入寮即 active）
- `student_status_changed_at`（最近一次变更时间）
- `student_status_changed_by`（操作老师 `teacher_id`）
- `student_status_change_reason`（自由文本）
```

### 同时要在 `ENUM_REGISTRY_v0.1.md` 新增

```markdown
### §14 student_status（**4-21 新增**）

| 取值 | 中文 | 含义 | 是否进入座位表 |
|---|---|---|---|
| `active` | 在寮 | 正常参与点呼 | ✅ |
| `paused` | 请假 | 长期请假期间（如病假 / 家庭原因），用"免点呼范围"覆盖 | ❌（但保留名单） |
| `transferred` | 转学 | 已转去别的学校 / 寮，此后 session 不计入 | ❌ |
| `graduated` | 毕业退寮 | 毕业后离寮，此后 session 不计入 | ❌ |

**状态转换规则**（对应 spec 附录 C.5）：
- 新入寮：null → `active`（首个 session 起计算）
- 长期请假：`active` → `paused`（请假期间免点呼）
- 请假结束：`paused` → `active`（回寮当天起恢复）
- 离寮：`active` / `paused` → `transferred` / `graduated`（此后 session 不再计入）
- 任意转换必须 audit：记录 `student_status_changed_at` + `student_status_changed_by` + `student_status_change_reason`
```

### 依赖 / 连锁

- **S1 修复依赖**：§7 边界 `学生离寮` 判据用 `student_status != 'active'`
- **B.5 依赖**（spec 附录 B.5 学生 → session 归属）：新入寮 / 退寮 / 转学流程拍板后填入 spec §附录 C.5
- **ERROR_CODES 新增候选**：`STUDENT_NOT_ACTIVE`（学生状态非 `active` 时签到尝试）—— 也可以合入现有 `UNREGISTERED_UID` 语义（S4 讨论点）

### 备选讨论（itsuki 拍板点）

1. **`paused` 是否区分理由**（病假 / 事假 / 留学 / 家庭）？
   - 推荐：**不区分**（理由写 `student_status_change_reason` 自由文本）
   - 理由：ENUM 越少越好；业务场景不需要对理由分类做报表
2. **是否保留 `graduated` 学生的历史数据**？
   - 推荐：**保留全部**（`student_status = graduated` 但 record 不删）
   - 理由：AC 叙事 + 未来"毕业生查本人数据"功能；数据库 GDPR-lite 考量
