# 交接：iOS 点呼时间窗状态机首批单元测试

> itsuki 2026-06-11 拍板。背景：iOS 至今只有「编译通过」一种验证，6-10 全量审查发现「点呼显示链整条是假的」而编译一直绿 — 需要逻辑层测试兜底。从点呼时间窗状态机起步（正是造假重灾区，且 R-1/R-2 刚接真后端）。

## 目标

给 iOS 点呼时间窗状态机写 5-6 条单元测试（Swift Testing，Xcode 自带），跑 `xcodebuild test` 全绿。

## 范围（只做这些）

1. **找到被测逻辑**：R-1/R-2 会话（2026-06-11）实装的时间窗状态机 — AppStore 里驱动 `rollState` 的判定（idle → 进行中 → 欠席）+ 签到判定。先 `git log --oneline --since=2026-06-11 -- 03_dev/student_ios/` 找到相关 commit 看改了哪些文件。
2. **测试用例（至少覆盖）**：
   - 当前时刻在窗口前 → 显示「点呼前」状态
   - 窗口内未签到 → 「进行中」
   - 窗口内已签到 → 已签到状态
   - 窗口过后未签到 → 「欠席」
   - 跨日边界（深夜点呼窗口跨 0 点的话）→ 按实际逻辑定
3. **测试目标（test target）**：iOS 工程现在大概率没有测试目标。在 `project.yml` 里加（**必须写 project.yml，不要在 Xcode 里手点** — xcodegen 重新生成时会擦掉手动配置），然后跑 `xcodegen` 重新生成工程。
4. **验证**：`xcodebuild test -scheme TomoshibiApp -destination 'platform=iOS Simulator,name=iPhone 17 Pro'` 全绿 + 双 scheme 普通构建仍 BUILD SUCCEEDED。

## 注意

- 时间相关测试**把「现在几点」作为参数注入**，不要在测试里读真实时钟（否则测试结果随跑的时间变）。被测函数如果直接用 `Date()`，先小幅重构成可注入。
- 提交用显式文件路径，一个改动一笔。
- 如果状态机逻辑散在 View 里没法单测 → 先把判定抽成纯函数再测，抽取本身单独一笔 commit。
