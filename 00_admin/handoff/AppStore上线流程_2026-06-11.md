## 2. 上线步骤（按顺序；【itsuki】=只有他能做，【CC】=代码/配置 CC 做）

### 第一阶段 — 上传前准备
1. 【itsuki】**Xcode 登开发者账号**：Xcode → Settings → Accounts → 加 Apple ID（那个开发者账号）。不登 headless / CC 拿不到描述文件，Archive 必失败。
2. 【CC】**确认签名配置生效**：`project.yml` Team ID 已填（§0）。如果 §3 决定 v1.0 不上推送 → CC 把 `TomoshibiApp.entitlements` 里 `aps-environment`（推送）项删掉 + project.yml `CODE_SIGN_ENTITLEMENTS` 视情况保留 NFC（避免审核期 entitlements 跟苹果后台对不上导致签名失败）。跑 `xcodegen` + 双 scheme build 验证。
3. 【CC】**构建号确认**：`CFBundleVersion` 每次上传必须递增（当前 1，首传可保持 1，重传 +1）。
4. 【itsuki】**苹果后台 App ID 能力**（仅当 v1.0 上推送时）：developer.apple.com 给 `com.itsuki.tomoshibi` 开 Push Notifications 能力 + 生成 APNs 证书配到后端。

### 第二阶段 — App Store Connect 后台（【itsuki】为主，CC 可代拟文案）
5. 【itsuki】appstoreconnect.apple.com **建 app 记录**（注：6-03 提过「5-08 卡 Validate 没提交」，可能已有半成品记录，先查）。bundle id 选 `com.itsuki.tomoshibi`。
6. 【itsuki+CC】**App 隐私问卷**：必须跟 `TomoshibiApp/PrivacyInfo.xcprivacy` 一致 —— 收集 姓名 / 邮箱 / 电话 / 照片 / 用户ID / 其他（生日性别房号学籍），全部「App 功能」用途、绑定身份、**不做追踪**。CC 可把这份对照表整理好给 itsuki 填。
7. 【itsuki】**元数据**：截图（CC 可用模拟器跑 app 截）/ 日语描述 / 关键词 / **隐私政策网址**（苹果强制 —— 可在 `pj.tomoshibi.cc` 挂一页，CC 能写）/ 年龄分级问卷 / 加密合规（project.yml 已填 `ITSAppUsesNonExemptEncryption = NO`）。
8. 【itsuki+CC】**审核用演示账号**：⚠️ 苹果审核员会真的登录测试。必须给一个能登进去、能看到核心流程的账号（学号+密码）。这条直接关系 §3 的后端决策。

### 第三阶段 — 打包上传
9. 【itsuki】Xcode → 选 `TomoshibiApp` scheme + 「Any iOS Device」→ Product → Archive → Organizer → Distribute App → App Store Connect → Upload。
10. 【itsuki】上传后在 App Store Connect 选构建、填完信息、提交审核。

## 3. ⚠️ 上线前必须先拍板的 3 个决策（CC 开工先问 itsuki）

1. **v1.0 上不上推送通知？**
   - 不上 → CC 删 entitlements 推送项（省去苹果后台开能力 + APNs 证书 + 避免审核对不上）。推送留 v1.1。

   - 〔建议：v1.0 占位姿态，倾向**不上**，推送归 v1.1〕

2. **后端怎么办（最关键）** —— app 一过审就要能登录，否则**审核员登不进去会被拒**。
   - 选项 A：itsuki 先把完整后端部署到 `api.tomoshibi.cc`（他说要本地对齐完才传）→ 然后再提审，审核员能正常登录。**最稳**。
   - 选项 B：先提审、赌审核员不深点 → 风险高（苹果明确要求可登录可用，骨架后端 = 大概率被拒）。
   - 〔CC 必须把「后端没部署 = 大概率过不了审」这个风险讲清楚，别让 itsuki 以为占位 app 可以空着后端上〕

3. **App Store 上的版本号写多少？** 当前 `0.23.0`。面向公众的「v1.0」要不要把 marketing 版本号（`CFBundleShortVersionString`）改成 `1.0.0`？还是保持 0.23.0？itsuki 定，CC 改 project.yml 三端同步（走 version-bump skill §4 联动）。
