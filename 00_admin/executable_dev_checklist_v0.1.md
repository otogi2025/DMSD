## 4. 点呼主闭环（里程碑 1，第 6-10 天）

### 硬件架构（2026-04-12 决策）
- 点呼机 = **Raspberry Pi + PN532 NFC 模块 + 扬声器**，贴在墙上
- 入口放 2 台点呼机（A/B 两条通道）
- 点呼机代码用 Python（和后端同一语言）
- 播报功能：点呼机本地 TTS，不依赖老师 iPad

### 分阶段策略（2026-04-12 决策）
- **Phase 1**：NFC 卡 + 后端 + 点呼机 → 最快上线，不需要学生 App
- **Phase 2**：加手机 App（iOS + Android）→ 学生可选卡或手机，可查看自己数据
- Phase 2 不替换 Phase 1，两种方式共存

### Phase 1 接口
- [ ] 点呼机 → 后端：
  - NFC 签到提交 `POST /api/v1/checkin`（uid + device_id）
  - 后端返回学生姓名 + 签到状态 → 点呼机播报
- [ ] 老师端接口：
  - 开始场次
  - 结束场次
  - 查询当前场次与座位快照
- [ ] 时间窗判定引擎：
  - `pending -> present/late/invalid`
  - 结算时 `pending -> absent`
- [ ] 老师端实时通道（WebSocket/SSE）
- [ ] 座位状态显示：
  - 灰/绿/黄/红
  - 健康图标、申请图标、免点呼标记
- [ ] 语音播报防作弊：
  - 点呼机读卡后播报学生姓名
  - 老师在入口对照人脸，防代签

### Phase 2 接口（后续迭代）
- [ ] 学生手机端 NFC 签到（iOS + Android）
- [ ] 学生端查看出勤历史、扣分记录

完成标准：
- Phase 1：点呼机刷卡 -> 播报名字 -> 后端记录 -> 老师端实时更新 -> 结束自动结算，全流程可演示。
