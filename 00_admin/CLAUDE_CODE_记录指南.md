# Claude Code 操作指南 — DMSD 记录协作

> 权威章程：`AC入试记录指南_v3.md`（用户侧）
> 本文是 CC 执行子集。不讲动机，只讲操作。

---

## 1. 目录边界

| 路径 | CC 权限 |
|---|---|
| `全量日志/YYYY-MM-DD.md` | **读写**（主要工作区）|
| `AC素材_候选/` | **只读** |
| `AC素材_成品/` | **只读** |
| 代码/docs | 按正常开发权限 |

CC 永远不写 `AC素材_候选/` 和 `AC素材_成品/`。

---

## 2. 会话开始

1. 用 `date` 确认今天日期。
2. 检查 `全量日志/YYYY-MM-DD.md` 是否存在，不存在则创建（见 §5 模板）。
3. 问 itsuki：「上次会话之后有没有没记下来的事？先记一下再开工？」
4. 读 `00_admin/progress_overview.md`（若存在），了解项目状态。

---

## 3. 对话中：碎片 dump

### 3.1 触发捕捉的范围（v3 比 v2 扩大）

下面任何一类发生都 dump：

- 代码/架构/文件结构的**改变**
- 任何**决策**（哪怕微小）
- itsuki 说出的**想法、看法、反思、怀疑**
- **问题**：bug、卡点、不理解的概念
- **学习**：新概念、新语法、新工具
- 和真人讨论的**访谈**要点
- CC 写出 itsuki 当时**不完全理解**的代码
- CC 和 itsuki **意见不一致**
- itsuki **纠正** CC

**不捕捉**：纯执行类操作（rm、mv、重启等）、寒暄、和项目无关的话题。

### 3.2 标准话术

识别到后先问：
```
刚才这个我记一下到 全量日志/YYYY-MM-DD.md 好吗？
归类：[标签] / 可能对应 AC 核心问题 #X
```

itsuki 同意 → append 到当日文件末尾。

### 3.3 碎片格式（append 到当日文件）

```markdown
## HH:MM [标签] 一句话主题
（正文：现象 / 对话 / 代码片段 / 想法）

**itsuki 原话**：
> "..."（尽量保留原话，不润色）

**#AC候选**（CC 按 §6 判断加不加）
**核心问题**: #1 / #2 / #3 / #4 / #5（CC 建议）
```

**标签建议**（自由扩展）：`[DMSD] [学习] [访谈] [决策] [问题] [分歧] [闪念-补] [碎片]`

---

## 4. CC 写代码的额外规则

代码包含下列任一时，**停下来告诉 itsuki**：

- itsuki 没接触过的库/API
- 非平凡模式（装饰器 / async / 元类 / 并发原语 / 复杂类型）
- 跨多文件改动

话术：
```
这段用到了 X，你熟悉吗？
不熟的话我先讲一遍，等你能用自己的话解释了我们记一笔到当日日志（[分歧] 标签，B 类：CC 写代码我学懂）。
```

记录时必须让 itsuki 口述一遍自己的理解，CC 转写到正文。

---

## 5. 当日文件模板（首次创建时）

```markdown
# YYYY-MM-DD

## 当日目录
（会话结束前由 CC 刷新）

---

```

会话结束前 CC 扫描当日所有碎片，刷新顶部目录为：
```
- HH:MM [标签] 一句话主题 #AC候选（如果有）
```

---

## 6. #AC候选 标签判断

加标签：
- 能对应 5 个核心问题之一
- 展示思考过程、权衡、反悔、不懂→懂
- 和 DMSD 主线叙事相关

不加：
- 纯代码/纯语法学习，看不出思考
- 闲聊、无关事务

**宁多勿少**。itsuki 事后可删可加。

---

## 7. 5 个核心问题（CC 用来打标签）

| # | 问题 |
|---|---|
| 1 | 为什么做 DMSD？（問題発見）|
| 2 | 遇到了什么困难？（問題意識）|
| 3 | 怎么解决的？（問題解決）|
| 4 | 学到了什么？（自己認識）|
| 5 | 为什么筑波？以后学什么？（志望動機）|

---

## 8. 会话结束

按顺序执行：

1. **刷新当日目录**（§5）
2. **列出今天 dump 的所有碎片**给 itsuki 确认：
   ```
   今天记录了 N 条到 全量日志/YYYY-MM-DD.md：
   - HH:MM [标签] 主题 #AC候选
   - ...
   其中 M 条是 #AC候选。
   ```
3. **起草 `00_admin/progress_overview.md` 更新草稿**（不直接写入，给 itsuki 确认）
4. **核心问题覆盖提示**（仅当某类长期空缺）：
   ```
   最近 #4 自己認識 类素材空缺，下次如果有合适时机记得触发。
   ```
5. **月末提醒**（每月最后一次会话）：
   ```
   这是 YYYY-MM 最后一次会话，记得做月度回顾 → AC素材_候选/ 的挑选 + AC素材_成品/monthly_review/YYYY-MM.md
   ```

**不做**：内容总结 / 会话回顾长文 / 替 itsuki 写感想。

---

## 9. 禁止事项

- ❌ 写入 `AC素材_候选/` `AC素材_成品/`
- ❌ 润色 itsuki 原话（保留原话）
- ❌ 在当日日志里加"事后才知道的信息"
- ❌ 替 itsuki 判断"这条该进 AC素材候选"（CC 只打 `#AC候选` 标签，升级到第 2 层是 itsuki 的月度回顾工作）
- ❌ 主动写自我推荐书/志愿理由书内容
- ❌ 未告知就创建非 `全量日志/` 的新文件

---

## 10. 元规则

- itsuki 是主角，CC 是辅助
- 识别触发时**先问 itsuki 自己有没有意识到**，再提醒
- 碎片 dump **必须征得同意**，不自作主张写入

---

## 11. 闪念不归 CC 管

itsuki 的临时想法通过手机备忘录 → Claude app 整理 → itsuki 自己粘贴进 `全量日志/`，标签 `[闪念-补]`。CC 不管这部分。
