## 1. 一句话项目 + 5 端是什么

**DMSD = 宿舍点呼数字化**。学生晚上回宿舍，用 NFC（近场通信 —— 手机或卡贴一下就传数据）刷一下完成签到，系统自动记考勤 + 算扣分，核心是防代刷。系统对外名 **Tomoshibi（灯火 / ともしび）**，DMSD 是项目/仓库代号。

5 个「端」（互相独立、各跑各的、靠后端连起来的 5 个程序）：

| 端 | 是什么 | 代码在哪 | 技术栈 |
|---|---|---|---|
| 后端 backend | 唯一判定者 + 数据库 + 给所有端提供接口 | `03_dev/backend/v1/` | FastAPI + PostgreSQL |
| 学生 iOS | 学生用的 iPhone App | `03_dev/student_ios/v1/` | Swift + SwiftUI |
| 学生 Android | 学生用的安卓 App | `03_dev/student_android/` | Kotlin + Compose |
| 老师网页 teacher_web | 老师看座位 / 改判 / 管学生 | `03_dev/teacher_web/v1/src/` | React + TypeScript + Vite（client.ts）|
| 点呼机 rollcall_device | 宿舍门口那台刷卡机 | `03_dev/rollcall_device/` | Pi 3A+（树莓派）+ PN532 读头 |

## 2. 系统怎么跑通（签到一条主线）

详细流程 + 攻防分析 → `02_design/flow_design.md`。骨架一条线：

```
学生刷卡（路径 A）/ 手机碰一下（路径 B）
  → 卡：点呼机 PN532 读 UID；手机：App 把身份数据写进点呼机的 ST25DV 邮箱（手机不联网）
  → 点呼机给数据盖 NTP 校准的时间戳 swipe_time（= 接触机器那一刻）
  → 点呼机 POST 到后端 checkin 接口（是点呼机连后端，不是手机）
  → 后端校验：是注册学生? 设备注册了? 在时间窗内?（按 swipe_time 判）
  → 写 attendance_event（只追加、不改旧记录）
  → WebSocket 实时推：老师网页座位变绿 + 点呼机播报全名 + 亮灯
```

**三条签到路径并存**：① NFC 卡贴点呼机 ② iPhone 写 ST25DV 邮箱 ③ Android 写同一张 ST25DV。后两条 2026-06-02 反转：手机从「读贴纸」改「写邮箱」、不再联网。每个时间窗内一个学生只能签到一次（幂等）。

## 3. 把 5 端绑在一起的契约（改任何端都要遵守）

全部细节 → `01_specs/API_CONVENTIONS.md`。最关键 4 条：

1. **响应格式**：⚠️ **2026-06-10 审查证实本条与代码不符**——后端 29 个路由实际全部直接返回数据模型（无 {ok,data} 包装），iOS 也直接解码，两侧代码互相一致、能跑通。原契约「成功 `{ok:true, data:{}}`；失败 `{ok:false, error:{...}}`」没有任何实现。改文档还是改代码待 itsuki 拍板（见 §6），**新代码先照现实写（直接返回模型）**。
2. **鉴权**：Header 带 `Authorization: Bearer <token>`；学生 token 只能访问 `/student/*`，老师 token 只能访问 `/teacher/*`。
3. **URL 命名**：⚠️ 还没最终拍板（API_CONVENTIONS §8.2 的 L8 未决）。**临时统一用方案 A**：`/api/v1/<角色>/<资源>`（例 `/api/v1/student/me/checkins`）。新代码按 A 写。
4. **时间 + 命名**：全链路 JST（日本时间）。判定时间基准 = **点呼机打的 `swipe_time`**（接触机器那一刻，NTP 校准）—— 受信任边缘设备，不算「客户端」；后端用它判时间窗，不用后端收到的时刻（避免网络延迟误判迟到）。普通客户端（手机 / 老师网页）本地时间仍不参与判定。字段名一律小写蛇形（`student_id`，不要 `studentId`）。

> ⚠️ 真正的字段级对齐（后端 ↔ iOS ↔ Android 哪个字段叫什么、是不是 Optional 可空）→ 用 `spec-sync` skill 真扫真比，本文件不复述。

### 4.1 demo / 生产双轨（每端隔离方式不同 — 改代码前必懂）

- **iOS**：一份源码编两个版本。demo 代码**允许直接写在生产源码里**，用 `#if DEMO ... #endif` 标注隔离（当前 10 个文件在用）；`TomoshibiApp` scheme 出生产版（编译产物完全不含 demo 代码），`TomoshibiAppDemo` 出演示版。这是设计意图 — itsuki 要快速切换两个模式，**带标注的 demo 代码不是要删的垃圾**。
- **老师网页 + 后端**：演示靠**演示账号**触发 — 学生和老师都带 `is_demo` 标志（`models.py`，后端数据库表定义）：演示老师只看演示学生，真老师自动滤掉演示数据，零交叉。演示数据量小，随正式版一起部署没关系。
- **Android**：没有任何 demo 开关，只有生产形态。
- **点呼机**：骨架阶段，无 demo 概念。
- **上线前要删的是什么**：只删「无开关、直接改生产行为」的临时 hack（如长按切点呼状态），清单在 TODO §A「demo scaffold 清理」段。生产显真实数据 / 演示显假数据是自明默认，不用问。

> ⚠️ **全项目最大的未完成结构块**：防作弊核心后端**一行都没写**——还缺设备注册校验 + 卡→学生映射 + 点呼机↔后端传输安全（加密 + 设备密钥）。`nonce`（一次性随机码）校验在 2026-06-02 架构反转后已撤；ECDSA（数字签名，防造假学号）降级 v1.1 可选。当前签到接口暂用老师令牌鉴权、手动传 `student_id`。**这是 v1.0 上线最大隐患。**

## 5. 不能违反的核心不变量（设计铁律）

改任何端，下面这些都不能破（来源 `flow_design.md §5/§7` + `05_logs/decision_log.md`）：

1. **后端是唯一判定者** —— 判定逻辑全在后端，手机 / 老师网页本地时间不算数。**时间戳例外**：由点呼机打 `swipe_time`（NTP 校准），点呼机是受信任边缘设备，后端用它判迟到（2026-06-02 反转）。
2. ~~**nonce 10 秒一次性**~~ —— **2026-06-02 架构反转后作废**（手机不联网、无远程代签场景）。新防代刷靠现场播报姓名 + 老师看脸 + 点呼机↔后端传输安全，详见 `flow_design.md §5`。
3. **ECDSA 签名** —— **降级 v1.1 可选**（手机写进邮箱的数据带签名防造假学号）。私钥存手机硬件（iOS Keychain / 安卓 Keystore），后端用注册时存的公钥验。v1.0 不强制。
4. **幂等** —— 同一次签到重复提交只记一次（卡用复合唯一索引，手机用 idempotency_key 幂等键）。
5. **老师入学日面签** —— 整个账号体系唯一的真人身份验证锚点；日常签到靠现场老师目视监督兜底。
6. **上线姿态**（4-19 G2 决策）：v1.0 = iOS + Android + 卡 一次性上线，不分阶段。
