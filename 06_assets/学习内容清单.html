2.5 HTTP / API 客户端-服务器架构

客户端怎么跟服务器说话
必学 难度 ★★★
HTTP = HyperText Transfer Protocol 超文本传输协议（网络上客户端和服务器通信的规则）
GET / POST / PUT / DELETE = 4 种 HTTP 请求方法（GET 取数据 / POST 创建 / PUT 更新 / DELETE 删除）
API = Application Programming Interface 应用程序接口（服务器对外开放的「能让客户端调用的功能列表」）
REST = Representational State Transfer 表现层状态转移（API 设计风格的一种，DMSD 用这个）
状态码 = 200 OK / 401 没授权 / 404 没找到 / 500 服务器爆炸
DMSD 里：iOS / Android / Web 3 个客户端都通过 HTTP 跟 backend 说话。backend 在 03_dev/backend/routers/ 下定义 API 端点（API endpoint = 一个具体的 URL 路径）
AC 故事：评委问「客户端怎么获取数据」→ 能从 HTTP 请求讲到 backend route 讲到数据库查询

2.6 数据库基础（PostgreSQL）

表 / 字段 / 主键 / 外键 / 索引 / 查询
必学 难度 ★★★
PostgreSQL = Postgres，一个免费开源的关系型数据库（DMSD 用这个存所有数据）
表 (table) = 像 Excel 的工作表，每行一条数据
字段 (column) = 表的列，比如 student_id / name / dorm_room
主键 (primary key) = 唯一标识一行的字段（通常是 id）
外键 (foreign key) = 指向另一个表主键的字段（学生表里的 dorm_id 指向宿舍表的 id）
索引 (index) = 给字段加速查找的数据结构
SQL = Structured Query Language 结构化查询语言（跟数据库说话用的语言）
DMSD 里：03_dev/backend/models.py 定义所有表 / alembic/versions/ 下是迁移脚本（migration = 数据库表结构变更记录）
AC 故事：评委问「点呼记录怎么存」→ 能从表设计讲到字段类型讲到查询性能

2.7 安全基础（hash / 加密 / 签名 / nonce）

为什么 DMSD 防作弊用这些
高优 难度 ★★★★
hash = 哈希，把任意长度数据压成固定长度指纹（密码不直接存，存哈希）
加密 (encryption) = 把数据变成只有持密钥的人能读懂的乱码
签名 (signature) = 证明「这条数据是某人发的、没被改过」
nonce = number used once 一次性随机数（防重放攻击 — 攻击者不能录下一次通信再发一遍）
ECDSA = Elliptic Curve Digital Signature Algorithm 椭圆曲线数字签名算法（DMSD 防代签到用这个）
DMSD 里：NFC 卡 ST25DV16K 用动态 nonce 每 10 秒刷新 / 学生注册码用 hash 验证 / 老师权限用 ECDSA 签名
AC 故事：评委问「怎么防代签到」→ 能从物理 NFC 距离限制讲到 nonce 防重放讲到 ECDSA 签名 = 完整的防御链 = 极强加分

4.1 Swift 语法基础

展开 6 个子条目
let / var / Optional / 类型推断
必学 难度 ★★
let = 常量（不能改）/ var = 变量
Optional = 可空类型 — Swift 区分「这个值可能为空」和「这个值一定有」，用 ? 表示可空。零基础容易翻车的语法。
struct / class / enum
必学 难度 ★★★
struct = 结构体（值类型，赋值是复制）/ class = 类（引用类型，赋值是同一份）/ enum = 枚举（有限取值集合）。SwiftUI 里 View 几乎都是 struct。
func / 闭包 / 高阶函数（map / filter / reduce）
高优 难度 ★★★
闭包 (closure) = 匿名函数，可以传给别的函数。Swift 里到处都是。
protocol / extension
高优 难度 ★★★★
protocol = 协议，定义「实现我的类型必须有这些方法」/ extension = 扩展，给已有类型加新方法。Swift 的「面向协议编程」核心。
async / await（异步编程）
高优 难度 ★★★★
网络请求要等几百毫秒，不能堵住 UI。async 函数表示「我会异步」，await 表示「在这里等结果」。Swift 5.5+ 的现代异步语法。
Codable（JSON 解码）
必学 难度 ★★★
让 Swift 结构体能自动把 JSON 转成 struct 实例（解码 / decode）或反过来（编码 / encode）。DMSD iOS 端跟 backend 通信全靠这个。

4.2 SwiftUI 声明式 UI

SwiftUI = Apple 的现代 UI 框架
必学 难度 ★★★★
声明式 (declarative) = 写「UI 长什么样子」而不是「怎么一步步画出来」
View 协议 = 所有 UI 元素都实现 View 协议
组合 = 复杂 UI 由简单 View 拼起来
跟传统的命令式 UIKit 是两套思路

7.1 NFC 物理原理

电磁感应是怎么传数据的
必学 难度 ★★★
NFC = Near Field Communication 近场通信 — 工作距离 4cm 以内
原理 = 13.56 MHz 电磁场感应（高中物理课的法拉第电磁感应定律的应用）
被动卡 (passive tag) = 自己没电，被读卡器的磁场激活 — NTAG215 就是被动卡
动态卡 (dynamic tag) = 有微控制器能改内容 — ST25DV16K 就是动态卡
02_design/hardware_design.md + 05_logs/learning_path.md 2026-04-12 条目已写
AC 故事：评委问「为什么 4cm 限制是优势」→ 「电磁场强度随距离立方衰减 → 远了根本耦合不上 → 物理上必须靠近 → 防作弊」

7.2 NFC 卡型号对比（NTAG215 / ST25DV16K）

为什么 DMSD 选 ST25DV16K
高优 难度 ★★
NTAG215 = NXP 公司的被动卡 — 内容写死，便宜（约 5 元 / 张）
ST25DV16K = STMicroelectronics 公司的动态卡 — 内容能被微控制器实时改（DMSD 每 10 秒刷新 nonce）— 贵（约 25 元 / 张）
选 ST25DV16K = 防 URL 复制攻击（NTAG215 内容固定，攻击者抄一份内容贴别处也能签到）
02_design/hardware_design.md §卡选型决策

7.3 PN532 模块

点呼机用的 NFC 读卡模块
高优 难度 ★★★
PN532 = NXP 公司的 NFC 收发芯片
跟 Pi 的连接接口 = I2C / SPI / UART 3 种（DMSD 选 V3 版本 — 接线方式见硬件设计）
跟 nfcpy 库配合在 Python 里读卡
02_design/hardware_design.md + 03_dev/rollcall_device/

7.4 树莓派 GPIO + 外设

Raspberry Pi 3A+ 跟外设接线
高优 难度 ★★★
Raspberry Pi (树莓派) = 信用卡大小的微型电脑，跑 Linux（DMSD 用 3A+ 型号）
GPIO = General Purpose Input / Output 通用输入输出针脚 — Pi 上 40 个针脚能接 LED / 喇叭 / 模块
DMSD 点呼机外设 = PN532 NFC 模块 + LED 灯（签到成功显示绿）+ 喇叭（日语播报「○○ さん おかえりなさい」）
02_design/hardware_design.md §接线 GPIO + 模块选型

7.5 防作弊机制（nonce + ECDSA）

3 层防御
必学 难度 ★★★★★
第 1 层 (物理) = NFC 4cm 距离限制，远程攻击不了
第 2 层 (动态) = ST25DV16K 每 10 秒刷新 nonce — 录下一次 URL 再发就过期了
第 3 层 (签名) = ECDSA 椭圆曲线签名 — 服务器验证「这个 nonce 是我发的」攻击者伪造不出来
02_design/system_features.md §防作弊设计 + 03_dev/backend/services/ 下签名验证代码
AC 故事：评委问「为什么 3 层不是 1 层」→ 「单层都有可能被绕（物理近距离也能用强磁场放大 / nonce 在硬件被破解 / 签名密钥泄露）→ 3 层叠加任何 1 层守住就安全」= 防御深度的思考 = 极强加分
