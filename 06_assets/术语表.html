📖 科学学习方法（建议第一次打开先看一遍）

这不是词典 · 是有方法学支撑的学习工具

背单词背不下来通常不是「记忆力差」，是方法不对。这个工具按认知科学研究的 4 个原则设计：

① 主动回忆 > 被动阅读 (Active Recall)

研究证明：测试自己 1 次 ≈ 重读 4 次。打开右上角「🎯 测试模式」 → 日语会被模糊 → 点一下才显示 → 强制大脑先「想一想」再「看答案」。

② 间隔重复 (Spaced Repetition)

每张卡片底部 3 个按钮：✓ 已掌握 / 🔄 学习中 / ❗ 需复习。状态保存在浏览器（关掉再打开还在）。

  1. 第一次看：标 🔄 学习中
  2. 第二天复习：能想起日语 → ✓ 已掌握 / 想不起 → ❗ 需复习
  3. 「❗ 需复习」用红框高亮，下次打开优先看这些
  4. 「✓ 已掌握」变浅绿淡出，不打扰但还能查

③ 检索练习 (Retrieval Practice)

点「🎲 随机考我」 → 系统从「需复习 > 学习中 > 未学」按优先级抽 5 张 → 每张你自己评判 ✓ 对 / ✗ 错。评判错的会自动标「❗ 需复习」。

④ 交错学习 (Interleaving) + 聚焦练习

不要一段死磕到底（研究表明效率反而低）。用顶部分类过滤随机切换：今天看「后端」+「项目特有词」 → 明天看「NFC 安全」+「宿舍场景日语」。

⑤ 输出 > 输入（日语目标专属）

每张卡片底部「🗣 面接想定」是真实面试讲稿。必须开口念出来，不是默读。N1 等级的输入≠流畅输出，AC 面试是输出考试。

建议节奏

· 每天 15 分钟（碎片时间，地铁 / 课间） · 周末 30 分钟对着 DMSD 项目用日语讲一遍 · 出愿前 1 个月每天「随机考我 5 张」

· 不要追求一次背完。这个表是工具，不是任务清单。

为什么文件夹要加 00、01、02 编号？

AC 面试大概率会被问到 —— 教授看 GitHub 仓库会问「ディレクトリ構成の意図は？」。

核心：强制排序 + 反映工作流时间线

文件系统默认按字母顺序排列。如果不加编号，目录会变成 admin → archive → assets → design → dev → logs → ops → release → specs —— 字母 a 到 s，没有任何业务意义。

加上编号之后变成 仕様 → 設計 → 開発 → 運用 → 発布 的项目时间线，打开 Finder 一眼看到做事的顺序。

99_archive 单独跳到 99 —— 归档永远在最末尾，留 90 段给以后可能加的杂物（98_drafts），不打乱 00-07 的主流程段。

ディレクトリに番号を付けたのは、ファイルシステムのデフォルトの並びがアルファベット順じゅんだからです。番号がないと admin → archive → assets... という順になって、プロジェクトの作業さぎょうの流ながれが見えません。

01_specs → 02_design → 03_dev という順番で並ならべることで、仕様しよう → 設計せっけい → 開発かいはつ という時系列じけいれつが一目で分かるようにしました。99_archive は最後さいごに置おきたいので、わざと 99 まで飛とばしています。
