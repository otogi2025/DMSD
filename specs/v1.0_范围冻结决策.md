# Tomoshibi 产品 v1.0 范围冻结决策（当前唯一真值）

冻结日期：2026-06-09（itsuki 拍板）

> **本文件作用**：冻结 v1.0 正式版的功能范围。一经冻结，新增需求一律推迟至 v1.1 及以后（功能冻结 feature freeze 原则）。范围有变更，先改本文件，再改代码。
> **关联**：版本沿革见 `CHANGELOG.md`；后续版本 `v1.1_范围冻结决策.md` / `v1.2_范围冻结决策.md`；契约 `API_CONVENTIONS.md`。

## 1. 版本定义与发布形态

- v1.0 为首个正式版，交付物 = 客户端（iOS + Android）+ 后端 + 老师网页。
- 发布策略 = 阶段发布（phased release）。v1.0 交付「宿舍生活服务」功能集；点呼签到及其硬件依赖功能延至 v1.1（见 §2.2）。
- 分发渠道：
  - iOS：App Store。
  - Android：签名 APK（安卓安装包）自托管于后端，学生自行下载安装（不经 Google Play，见 §2.1）。

## 2. 范围决策（关键决策记录）

### 2.1 Android 分发采用 APK 自托管
- 决策：不注册 Google Play 开发者账号；Android 以 release 签名 APK 自托管分发。
- 理由：目标用户含使用无谷歌移动服务（GMS）设备的留学生，Google Play 不可达。

### 2.2 点呼签到延至 v1.1
- 决策：点呼签到（实体卡 / 移动端写卡）依赖点呼终端与 NTAG215 卡，二者为硬件项、不在 v1.0 周期内就绪，整体延至 v1.1。
- 影响：v1.0 客户端「点呼签到」入口置为占位（标示「近日开放」），不得呈现可签到假象。

### 2.3 推送通道纳入 v1.0
- 决策：推送通知（push）纳入 v1.0 必做范围（审批结果、包裹到达等事件通知）。
- 约束：iOS 经 APNs（Apple 推送服务）真投递；Android 经 FCM（谷歌推送）对无 GMS 设备不可达，安卓推送的第一波实现方式待定（见 §5 未决项）。

### 2.4 演示账号全数据隔离
- 决策：演示账号仅可见演示数据，对真实数据零可达（含公告的只读访问）。

## 4. v1.0 排除项（冻结，推迟至后续版本）

下列功能不在 v1.0 范围，详见对应版本冻结文件：

- 点呼签到（NFC 写卡）/ 卡 UID 绑定 / 点呼终端软件 / 防作弊核心（设备令牌·设备私钥·卡映射）→ **v1.1**（`v1.1_范围冻结决策.md`）
- 紧急警报强制提示 / 暗色模式 / 在线学习申请 / 出租车预约 Android 端 / Android FCM 推送 → **v1.2 及以后**（`v1.2_范围冻结决策.md`）

## 5. 依赖与前置条件

- 后端完整版部署至生产 `api.tomoshibi.cc`，先决于本地前后端联调对齐完成（itsuki 把控）。
- iOS 提交审核，先决于开发者团队标识（Team ID）配置 + 代码签名启用（开发者账号已具备）。
- Android 出包，先决于 release 签名密钥库（keystore）生成。

**未决项（待 itsuki 拍板，不阻塞其余推进）**：
- 安卓推送第一波实现方式（FCM 对无 GMS 设备不可达的替代方案，或 v1.0 安卓推送降级）。
- 老师网页点呼默认页统计卡的演示数据：移除或接入真实接口。

## 6. 验收标准（v1.0 退出条件）

1. iOS 真机以真实学号完成：注册 → 登录 → 提交申请 → 老师网页审批 → 学生接收结果（推送或应用内）。
2. Android 同上全流程跑通（已接真实后端，非演示数据）。
3. iOS 通过 App Store 审核；Android APK 可经后端下载入口安装并运行。
4. 后端完整版在生产环境运行，三端调用无 404。
5. 演示账号登录仅见演示数据，对真实数据零可达。
6. 客户端点呼签到入口为占位态，不呈现可签到假象。

## 7. 实施要求（各端任务）

**后端**：演示账号公告只读隔离；数据库约束迁移 + 迁移脚本测试；APNs 推送服务接通；完整版部署生产（依赖本地对齐）。
**iOS**：团队标识配置 + 启用签名；包裹页与公告未读计数补加载/失败/空三态；点呼签到入口置占位；接 APNs；提交审核。
**Android**：各界面由演示数据切换至真实接口；登录接真 + 令牌持久化；release 签名出 APK；后端下载入口；点呼签到入口置占位；品牌图标替换。
**老师网页**：肉眼签收 → push；点呼默认页演示数据处置；配置 Resend 密钥。
**运维**：生产部署；App Store 提交；APK 上架后端；生产数据库迁移 + 定时备份。
