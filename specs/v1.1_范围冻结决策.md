- v1.1 = 点呼签到正式交付波次。

## 2. 范围决策（关键决策记录）

### 2.1 两条签到路径
- 路径 A（实体卡）：学生持 NTAG215 卡贴点呼终端，终端经 PN532 读取卡片 UID。
- 路径 B（移动端）：学生经客户端用 NFC 将身份数据写入点呼终端侧 ST25DV16K 的 Mailbox（邮箱缓存）；移动端全程不联网。
- 二者在「点呼终端 → 后端」段统一。判定时间基准 = 点呼终端打的 `swipe_time`（经 NTP 校准）。

### 2.2 卡绑定采用只读 UID
- 决策：卡仅作标识载体，不向卡写入学生数据；后端维护「卡 UID ↔ 学生 `id`(UUID)」对照表。
- 绑定对象为学生恒定主键 `id`（UUID），非学号（学号随升级变更）。
- 理由：NTAG215 不防克隆，写入学号易被伪造；对照表置于后端、卡片本身无敏感信息。

### 2.3 防作弊基础（与点呼终端同期）
- 设备身份：点呼终端持设备私钥，向后端证明为已注册终端（防冒充终端灌注假签到）。
- 设备令牌：终端经设备身份换取短期令牌用于日常接口调用（替代 v1.0 临时借用老师令牌的过渡方案）。
- 设备注册校验：未注册设备调用签到接口被拒。

### 2.4 移动端签名（ECDSA）降级为可选
- 移动端写卡数据附私钥签名（防伪造学号）列为 v1.1 可选项，非必做；不实现时由「现场老师核验 + 终端播报姓名 + 设备认证」承担防代刷。

### 2.5 晚自习功能从 v1.0 推迟至 v1.1（2026-06-14 上架审查决策）

晚自习出席管理（夜間学習）原列 v1.0，2026-06-14 iOS 上架就绪审查确认其后端链路未完成，决定整体推迟至 v1.1。该功能不依赖点呼终端硬件，但与点呼波次同期交付。

- 缺口：后端缺 `GET /study/today/state`（晚自习状态机驱动）与 `GET /study/attendance/mine`（学習履历）两接口；`GET /students/me` 未返回 `is_study_target`（学習対象标识）字段；推送投递（`app/services/push.py` 的 `_send_via_apns`）为占位实现。
- v1.0 降级状态：iOS `isStudyTarget` 默认 false，首页晚自习卡不显示，マイページ「学習履歴」显示「学習対象外」提示页。功能对用户不可见，不影响 App Store 上架完整性（无坏入口、无空白页）。
- v1.1 补完项：后端实装上述两接口 + `/students/me` 增 `is_study_target` + APNs/FCM 投递实装 + iOS 接入真实状态。规格主体见 `design/system_features.md §7.3.10`。

## 4. 依赖与前置条件

- v1.0 已上线（客户端已在用户设备，方可经更新激活）。
- 点呼终端硬件采购到货 + 现场装配 + 系统部署。
- 点呼终端软件待从零实现（当前仅占位骨架）。
- 后端防作弊模块待从零实现。

## 5. 验收标准（v1.1 退出条件）

1. 学生持卡贴终端，后端正确识别学生、记录考勤、老师网页座位实时变绿、终端播报姓名。
2. 学生经移动端写卡完成签到（飞行模式下亦可），客户端本地确认。
3. 未注册设备 / 伪造终端调用签到接口被拒。
4. 终端在网络闪断下走离线缓冲，恢复后补传，不丢签到。
5. 同一时间窗内同一学生重复签到仅记一次（幂等）。
