# Tomoshibi 产品 v1.2（及以后）范围决策

确立日期：2026-06-09（itsuki 拍板分波时归集）

> **本文件作用**：归集 v1.0 / v1.1 范围之外、已识别但暂不承诺周期的功能。性质为**候选池**（非冻结范围）—— 各项启动前需单独评估与拍板，确认后再升格为对应版本的冻结范围。
> **关联**：`v1.0_范围冻结决策.md` / `v1.1_范围冻结决策.md`。各候选项明细见下文 §1。

## 1. 候选功能清单

### 1.1 紧急警报强制提示（优先级最高，AC 价值高）
- 来源：2026-06-09 itsuki 经宿舍防灾训练识别 —— 单一声音警铃对戴耳机 / 静音用户失效。
- 功能：灾难（地震 / 火灾）时强制突破勿扰与静音发声警报；后续可由宿舍实体紧急按钮联动后端群发。
- 技术边界（已核实）：
  - 客户端可达上限 = iOS Critical Alerts（重要通知，突破勿扰 + 静音强制发声），需向 Apple 单独申请权限（限健康 / 安全 / 紧急类）。
  - **不可实现**「与政府地震速报（緊急速報 / WEA）完全一致」的系统级广播 —— 该能力不对普通应用开放。
  - Android 侧：无 GMS 设备 FCM 不可达，安全警报不得仅依赖 FCM，需常驻长连接等替代通道。

### 1.2 暗色模式（N18）
- 当前已移除设置页的占位开关；客户端入口强制浅色。完整暗色（逐屏对比度核验）列入本池。

### 1.3 在线学习申请（オンライン学習，类型 A）
- 含契約書（合同）拍照上传流程。后端字段与上传链路部分就绪，整体延后。

### 1.4 出租车预约 Android 端
- iOS / 老师网页 / 后端已实现；Android 端待补（随 Android 接后端工作一并评估）。

### 1.5 Android FCM 推送
- 面向具备 GMS 的 Android 设备的推送通道；与 v1.0 安卓推送方案决策联动。

## 2. 升格规则

- 本池各项不进入开发，直至单独评估并拍板纳入某一具体版本（届时迁入对应 `vX.X_范围冻结决策.md` 的纳入范围）。
- 优先级与排期由 itsuki 拍板，CC 不擅自启动。
