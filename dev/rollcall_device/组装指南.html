阶段 0 · 开工前–10 分钟
先把三条保命规则读进脑子，再把三样自己家里的东西找出来。时间预估：软件段 1–2 小时 / 焊接段 2–3 小时 / 接线段约 2 小时。
三条保命规则（每条读懂了再打勾）
规则一：接线、拔线之前，一律先拔掉树莓派的电源▶

带电插拔可能瞬间烧坏板子。养成肌肉记忆：手要碰针脚 = 先拔电源线。

规则二：一次只接一个模块，接完立刻验收，过了再接下一个▶

一次全接上，出了问题你分不清是哪根线的锅。同理：排查时一次只改一个地方，改一处、测一次。

规则三：红线（正极）绝对不能插反▶

尤其风扇那个 2 针小接头 —— 红线必须对准 5V 针，插反可能烧。

阶段 2 · 软件先跑通–1–2 小时 · 一根线都不接
先把软件跑通的好处：以后接线出问题，就能确定「一定是硬件的锅」，排查范围小一半。命令块右上角都有「复制」按钮。
2.1 烧系统卡 + 远程登录
Mac 上安装 Raspberry Pi Imager（官方烧卡工具）⚠️ 必须用这个，不能用 balenaEtcher 等别的烧卡工具▶

「烧卡」= 把树莓派的操作系统写进 microSD 卡。

为什么只能用 Pi Imager：它能在烧卡时预先写入 Wi-Fi 密码、SSH 开关、主机名这些设置。这台 Pi 3A+ 没有网线口、唯一的 USB 口要留给喇叭、不插键盘鼠标 —— 预置漏了，这台机器你就永远登不进去，只能重烧。别的烧卡工具没有预置功能。

下载：raspberrypi.com 官网 → Software → Raspberry Pi Imager（macOS 版）。

烧卡：选对系统 + 高级设置 5 项一个都不能漏▶

把 microSD 卡经读卡器插进 Mac，打开 Imager：

① 系统选 Raspberry Pi OS (64-bit)（代号 Bookworm）
② 烧录前点齿轮图标（高级设置），逐项填：

主机名rollcall-1以后就用这个名字登录
SSH打开（密码登录即可）SSH = 从 Mac 远程进入树莓派命令行的方式
用户名pi必须是 pi —— 开机自启配置里写死了这个名字
Wi-Fi 名 + 密码宿舍 / 家里的网一个字都不能错，错了登不进去只能重烧
时区Asia/Tokyo点呼判定全按日本时间

③ 点烧录，等它写完 + 校验完。卡里旧内容会被全部清空。

卡插进 Pi、上电、等 1–2 分钟联网▶

microSD 卡槽在 Pi 板子背面。插好卡 → 插电源线。第一次开机它要自己完成初始化 + 连 Wi-Fi，耐心等 1–2 分钟。

从 Mac SSH 登录进树莓派▶

在 Mac 上打开「终端」（Terminal，一个输命令的黑窗口，在 应用程序 → 实用工具 里，或用 Spotlight 搜「终端」），敲：

ssh pi@rollcall-1.local

第一次连会问 “Are you sure you want to continue connecting?” → 输 yes 回车，再输烧卡时设的密码（输密码时屏幕不显示任何字，是正常的，输完直接回车）。

验收：提示符变成 pi@rollcall-1:~ $ —— 说明你已经「在树莓派里」了，之后敲的命令都是在 Pi 上跑。
卡住了：连不上 → 先看路由器管理页面里有没有出现这台设备。有 = Wi-Fi 密码对、SSH 那边有问题；没有 = Wi-Fi 名或密码填错了，重烧卡。
2.2 打开两个通信开关
raspi-config 里开 SPI、开 I²C、音频切 3.5mm▶

SPI 和 I²C 是两种「芯片之间说话」的通信方式（读卡器走 SPI、贴纸走 I²C），树莓派默认全关着。在 SSH 里敲：

sudo raspi-config

出来一个蓝色菜单（方向键移动、回车确认、Esc 返回）：

① Interface Options → SPI → Yes
② Interface Options → I2C → Yes
③ System Options → Audio → Headphones（把声音从 HDMI 切到 3.5mm 圆孔，不切喇叭不出声）

改完退出，重启：

sudo reboot

重启会把 SSH 断开，等 1 分钟再重新 ssh pi@rollcall-1.local。

核对两个开关真的开了▶ 
ls /dev/spidev*
ls /dev/i2c-*
验收：第一行打出 /dev/spidev0.0，第二行打出 /dev/i2c-1。

现在还没接任何模块，所以先别跑 i2cdetect —— 那条留到阶段 4.3 接上贴纸后用。

2.3 装代码和依赖
把点呼机代码从 Mac 拷进树莓派▶

这条命令在 Mac 的终端上跑（新开一个终端窗口，别在 SSH 里面敲）：

scp -r ~/dev/DMSD/dev/rollcall_device pi@rollcall-1.local:/home/pi/rollcall_device

scp = 隔着网络拷文件的命令。会再问一次密码。拷完回到 SSH 窗口继续。

装系统包 + 建 Python 虚拟环境 + 装依赖▶

回到 SSH（树莓派）里，一段一段贴：

cd /home/pi/rollcall_device
sudo apt update
sudo apt install -y python3-venv python3-dev libgpiod2 i2c-tools
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt

cd = 进入某个文件夹；venv = Python 虚拟环境，把本项目的依赖库跟系统隔开互不污染。最后一步要下载不少东西，几分钟正常。

卡住了：lgpio 或 adafruit-blinka 装报错 → 多半缺系统包，补一句 sudo apt install -y python3-libgpiod 再重试。
生成内置提示音▶ 
.venv/bin/python tools/gen_tones.py
验收：不报错，提示音文件写进了 assets/。
复制一份配置文件（先不用改内容）▶ 
cp config/config.example.json config/config.json

配置里的字段（设备编号、激活码、后端地址）留到阶段 5 再真正填。现在只是让程序有文件可读。

2.4 空跑模拟模式（软件段终点）
用键盘假装刷卡，确认程序能转起来▶ 
.venv/bin/python -m src.main --config config/config.json --simulate
注意：是 python -m src.main，不是 python src/main.py —— 后者会报 ImportError。这是 Python 包的运行方式，不是代码有 bug。

跑起来后直接打字模拟：

card 04a1b2c3d4e5f6   # 假装刷了一张卡（路径 A）
phone 某个uuid         # 假装手机碰了贴纸（路径 B）
quit                  # 干净退出
验收：打 card ... 有反应、打 quit 能干净退出。报网络错误是正常的（后端还没配）—— 你要看的是程序本身跑起来了、状态机在转。

到这里的意义：软件这层已经证明没问题。后面出任何故障，都可以先怀疑硬件。

阶段 3 · 焊接–第一次约 2–3 小时
人生第一次拿烙铁。焊接的本质一句话：用熔化的锡把金属针和板子上的金属圈粘在一起，让电能通过。要焊两块板：PN532 焊一条排针、ST25DV 焊 6 根排针。分练习和实战，别跳练习。
摆好场地：耐热垫、湿海绵、通风、烙铁调 350℃▶

① 耐热垫铺桌上，烙铁架放稳（烙铁头 350℃，碰到什么烫坏什么）
② 套装里的海绵沾水拧半干 —— 烙铁头脏了在上面蹭一下就干净
③ 开窗或开风扇 —— 焊锡的烟别对着脸吸
④ 烙铁插电，温度旋钮调到 约 350℃，等 2–3 分钟到温

安全：烙铁不用时必须放回架子上；拿烙铁只握手柄；焊完的焊点几十秒内还是烫的，别用手摸。
先在废排针上练 10 个焊点，练到稳定出「光亮小锥形」▶

排针买了 60 根，掰几根「牺牲品」插在面包板上练。四个基本动作，每个焊点都是这套：

① 加热 —— 烙铁头同时碰住针和板上的金属圈，停约 2 秒
② 送锡 —— 焊锡丝送到针和金属圈的接缝处（不是送到烙铁头上！），锡会自己熔化流进去
③ 先撤锡丝，再撤烙铁
④ 别吹气 —— 让它自然冷 2 秒（吹凉会产生裂纹）

焊完对照下面四张图判断好坏：

✅ 好焊点
锥形小山、表面光亮、锡把针和金属圈都包住
❌ 冷焊
灰暗、粗糙、像磨砂 —— 温度不够或焊时动了。重焊
❌ 虚焊
锡成圆球挂在针上、跟板子之间有明显缝 —— 没粘上板子。重焊
❌ 短路
两根针之间被锡连成一片 —— 用吸锡器吸掉重来

10 个里能连着做出 5 个「光亮锥形」就算出师，去焊真板子。

先焊 ST25DV（板底 6 孔焊 6 根排针）有 4 个备份，先拿它实战▶

为什么先焊它：ST25DV 买了 4 个，焊坏一个还有 3 个；PN532 只有 1 个。先在有备份的板子上实战。

做法：6 根排针从板底孔插入（塑料条在板底一侧），先焊两端各 1 针固定、确认排针垂直不歪，再焊中间 4 针。每针就是练习时那四个动作。

万用表验收 ST25DV 的 6 个焊点▶

焊完别靠肉眼，用万用表拨到通断档（表盘上有 🔊 蜂鸣器图标那一档，两点相通会「哔」）：

① 每个焊点对自己要通：一支表笔碰针尖、另一支碰板上这根针对应的焊盘/走线 → 应该响。不响 = 虚焊，重焊
② 相邻两针之间要不通：表笔碰相邻两根针 → 应该不响。响了 = 短路，吸锡重来

验收：6 根针全部「对自己通、对邻居不通」。这步不过关就往下走，后面会出各种莫名其妙的读不到卡，且极难排查。
再焊 PN532 的排针 只有 1 个，慢慢来▶

套件自带排针，焊到板边那排孔上。手感已经有了，不着急，一针一针来。歪了就先熔开两端定位针调正。

万用表验收 PN532 的每个焊点▶

方法跟 ST25DV 一样：每针「对自己通、对邻居不通」，全过才算焊接阶段完工。

阶段 4 · 逐个模块接线–约 2 小时
顺序：LED → PN532 → ST25DV → 风扇/喇叭（LED 不用焊、接错也烧不了，先拿它练数针脚）。每接一个模块前先拔电源，接完再上电。
先搞懂两套针脚编号，这是全场最容易搞死人的地方：
① 物理 pin 号（1–40）= 针在板子上的位置，数针脚时用它；
② GPIO 编号（又叫 BCM 编号）= 这根针在代码里的名字。
两套数字互不相等：比如「GPIO11」在物理 pin 23 的位置，而「物理 pin 11」其实是 GPIO17。下面所有表格两个号都标了 —— 动手数针脚永远看「物理 pin」列。

怎么找 pin 1：靠近 microSD 卡槽那一端就是 pin 1 / pin 2 那头；拿不准看板子背面 —— pin 1 的焊盘是方形的，其他都是圆的。
GND（接地）针有很多根，互相完全等价，哪根方便接哪根 —— 但所有模块都必须接到某根 GND（叫「共地」，少接一个电路就不通）。
⚠️ 文档里 PN532 的 GND 写的是 pin 6，但风扇接头会把 pin 4+6 整个占掉 —— 所以图上建议 PN532 的 GND 改接 pin 14（任一 GND 都行）。
4.1 LED ×4（不用焊、烧不坏，先练基本功）
拔掉电源，把 4 个 LED 经面包板接好▶

先认 LED 的两条腿（LED 有方向，接反不亮）：

颜色含义短腿接到（物理 pin）GPIO 编号
蓝待机pin 15GPIO22
绿签到成功pin 13GPIO27
红失败pin 11GPIO17
白启动中pin 16GPIO23

5V 针不够 4 颗 LED 分怎么办：用面包板 —— 一根杜邦线把 pin 2（5V）引到面包板的电源轨（红色长条），4 颗 LED 的长腿各自串好 220Ω 后都插到这条轨上。

为什么是「低电平 = 亮」：电流从 5V 流进 LED，GPIO 信号针在「放电流出去」的一端 —— 代码把信号针拉到 0V（低电平），电路才通、灯才亮；拉到 3.3V（高电平）灯灭。跟直觉相反，但这是接法决定的，代码里已经处理好了，你只管照表接。
上电跑主程序，看白灯 → 蓝灯▶ 
.venv/bin/python -m src.main --config config/config.json --log-level INFO
验收：启动瞬间亮白灯（启动中），进待机后变蓝灯。（后端没配报网络错仍是正常的，看灯就行。）
卡住了：某颗完全不亮 → 十有八九长短腿接反了，拔下来调头。4 颗全不亮 → 拔电源，用万用表电压档量 pin 2（5V）和任一 GND 之间是不是约 5V。开机瞬间 LED 微亮一下是正常的（程序启动第一件事就是把灯全灭）。
4.2 PN532 读卡器（路径 A：刷学生卡）
先把板上的模式开关切到 SPI 不切，接线全对也读不到卡▶

PN532 V3 板上有拨码开关或跳线帽，出厂默认可能是 I²C 模式。对照它自带说明书或板上丝印，切到 SPI 模式。切完拍张照留档。

上电，刷卡看日志打出卡号▶

4.3 ST25DV 贴纸（路径 B：手机碰）—— 全项目最难关
拔电源，接 4 根线 + 门铃线串 10kΩ 上拉▶
ST25DV 板上印的字接 Pi 的哪根针物理 pinGPIO 编号
SDASDA（I²C 数据）pin 3GPIO2
SCLSCL（I²C 时钟）pin 5GPIO3
VCC3.3Vpin 1—
GND接地pin 9—
GPO门铃线（见下）pin 18 ⏳GPIO24 ⏳

GPO 门铃线是什么：手机把数据写进贴纸后，贴纸靠这根线「按门铃」通知树莓派「有新东西了，快来读」。

门铃线必须串一个 10kΩ 电阻「上拉」到 3.3V：在面包板上，GPO 那格 → 插一根 10kΩ 电阻 → 电阻另一头接到 3.3V（pin 1 引过来的轨）。同一格再引一根线去 pin 18。别错拿 220Ω（阻值不对不管用）—— 用万用表量一下再插。

⏳ GPO 用哪个 GPIO 是配置里定的（默认 GPIO24 = pin 18），标了「待硬件联调核实」—— 如果实测要换针，配置文件 gpio.st25dv_gpo 要同步改。

验收第一步：i2cdetect 能看到芯片▶ 
i2cdetect -y 1
验收：打出的表里有 53 和 57 两个地址。
卡住了：看不到 = 接线或焊点问题 —— 回阶段 3 用万用表把 6 个焊点重新过一遍通断。
验收第二步：iPhone 碰贴纸，日志解析出学生身份▶

跑起主程序，用 iPhone 打开 Tomoshibi App 点签到，手机贴到 ST25DV 天线上。

验收：日志打出解析到的学生 UUID（一串带横杠的编号）。
这一步出问题不一定是你接错了。这里是全项目代码里标「待硬件联调核实」最多的地方 —— ST25DV 的寄存器位号、GPO 引脚行为都是照芯片说明书写的、从没被实物验证过。折腾 20 分钟没进展就停手，把日志（journalctl -u tomoshibi-rollcall -n 50 或前台跑的输出）整段发给 CC，对着芯片手册一起查。
4.4 风扇 + 喇叭
拔电源，风扇接头直插 pin 4 + pin 6 红线对 5V · 绝不接 GPIO▶

风扇的 2 针接头刚好套到 pin 4（5V）+ pin 6（GND）上，红线那头对准 pin 4。

风扇绝对不能接 GPIO 信号针 —— 信号针最大 16mA，风扇要 100mA，会烧板子。它只吃 5V 和 GND 两根电源针。
验收：上电风扇转。
喇叭：3.5mm 音频线插 Pi 圆孔，USB 线取电▶

Lazos 喇叭两根线：3.5mm 那根插 Pi 的圆形音频口；USB 那根只是取电。

⏳ USB 取电插哪：两份文档说法不一 —— 采购清单（较新）说插单独的 5V 充电头、不占 Pi 唯一的 USB 口；接线说明写的是插 Pi 的 USB 口。到时候实物确认：有闲置充电头就用充电头，Pi 的 USB 口能省则省。两种接法都不危险。

声音验收：刷卡有播报声▶
验收：刷一张卡，喇叭出声（现在还没绑学生，播提示音 / 报错音都算「出声」）。
卡住了：没声先想起阶段 2.2 —— 音频切到 Headphones（3.5mm）了吗？没切就 sudo raspi-config 补切。这不是喇叭坏了。
阶段 5 · 端到端第一次真签到–连上真后端
前面全通了，现在把机器接到真后端，走一次完整的「刷卡 → 后端 → 老师网页」。
先把设备在后端「注册上户口」
让后端建这台设备的记录，拿到一次性激活码▶

管理员在后端给这台设备建记录后，会得到一个一次性激活码（enroll_code）。这步在电脑上做 —— 到时候叫 CC 一起弄。激活码只能用一次，用过就作废。

在 Pi 上建数据目录▶

程序要有个能写的地方存密钥和本地名单：

sudo mkdir -p /var/lib/tomoshibi && sudo chown pi:pi /var/lib/tomoshibi
把 config.json 的字段填成真的▶ 
nano config/config.json

nano = 命令行里的文本编辑器：方向键移动，改完 Ctrl+O 回车保存、Ctrl+X 退出。

字段填什么
device_id这台机器的编号，如 dorm-1-01
enroll_code上一步拿到的一次性激活码（激活成功后程序自动清空它）
server_url / ws_urlhttps://api.tomoshibi.cc / wss://api.tomoshibi.cc
key_path / data_dir保持默认 /var/lib/tomoshibi/*（上一步已建好）
gpio.st25dv_gpo保持 24；除非 4.3 实测换了针才改
audio_output先跑 aplay -l 看喇叭的 card 和 device 号，填成 plughw:卡号,设备号
 
aplay -l
前台跑一次：激活 + 拉名单 + 进待机▶ 
.venv/bin/python -m src.main --config config/config.json --log-level INFO

首次启动会自动走完：生成设备密钥 → 用激活码激活 → 换 12 小时令牌 → 拉学生名单 + 同步语音 → 进待机。

验收：蓝灯待机、日志无报错。Ctrl+C 可以随时优雅退出。
卡住了：白灯闪烁 = 激活/令牌问题 → 查故障对照表「白灯闪烁」；黄灯（红+绿同亮）= 点呼时段没开始，是正常等待不是故障。
完整验收清单（六条全过 = 第一次刷卡成功 🎉）
断网再刷卡 → 仍绿灯，恢复网络后自动补传▶

把 Wi-Fi 断掉（路由器上踢掉这台设备或关热点）再刷已绑定的卡：本地名单命中照样绿灯。恢复网络后，这条记录自动补传到后端 —— 老师网页上应该能看到它出现。

装开机自启，重启后不用手动启动▶

systemd = Linux 的开机自启机制，装好后断电重启机器都会自己爬起来干活：

sudo cp config/tomoshibi-rollcall.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tomoshibi-rollcall
systemctl status tomoshibi-rollcall
验收：status 显示 active (running)。然后 sudo reboot 重启 → 不碰键盘，机器自己白灯 → 蓝灯。

以后看实时日志用：journalctl -u tomoshibi-rollcall -f（Ctrl+C 退出看日志，不影响程序）。

故障对照表现象点开看排查法
ST25DV 读不到（i2cdetect 里没有 0x53 / 0x57）▶

检查 I²C 四根线（SDA/SCL/VCC/GND）+ raspi-config 里 I²C 真开了；GPO 线接对针脚且串了 10kΩ 上拉。还不行 → 回阶段 3 复测焊点通断。

PN532 读卡无反应▶

① 板上跳线切到 SPI 模式了吗 ② /dev/spidev0.0 存在吗 ③ SS 线接的是 CE0（pin 24 / GPIO8）吗。

刷卡有反应但没声音▶

raspi-config 把音频切到 3.5mm（Headphones）；再 aplay -l 核对 config 里 audio_output 的设备串填对了。

白灯闪烁（认证错误）▶

令牌或激活问题：确认 enroll_code 正确且没被用过、这台设备在后端是启用状态（device_active = true）。看日志定位。

黄灯（红 + 绿同时亮）▶

= 点呼时段还没开始（SESSION_NOT_RUNNING），正常等待态，不是故障。

断网时刷卡什么表现才算对▶

本地名单里有这张卡 → 绿灯；没有 → 红灯。恢复网络后自动补传，不用人管。

开机瞬间 LED 微微亮一下▶

正常。程序启动的第一件事就是把 4 颗 LED 全部置灭。

要换机器 / 换密钥▶

管理员先在后端重发激活码（reset-enroll），Pi 上删掉本地密钥文件（key_path 指的那个）后重启，走一遍重新激活。
