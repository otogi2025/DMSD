🛟 卡住了 · 先自查这 5 条任何阶段通用
下面 5 条能解决大部分「明明照着做了却不动」的情况，而且不用等任何人回复。5 条走完还是不行，再去文末的故障对照表按现象找。
① 上一步你动了什么？只把那一处改回去刚才还好、现在不好 = 问题一定在最后一个动作里。一次只改一处、改完就测，别攒着改三样再上电 —— 那样出问题你分不清是哪一样造成的
② 有没有跳过没打勾的步骤？回去补最常见的是阶段 2 的两个通信开关（SPI / I²C）没开，或者改完开关没重启。开关没开的话，后面接线接得再对，机器也「看不见」模块
③ 把相关的线全部拔下来重插一遍接触不良的表现是「时好时坏 / 碰一下就变」，不是彻底不动。别小看这一条 —— 新手组装最常见的故障就是它，而且重插 30 秒就能排除
④ 重启：先重启程序，再重启整台 Pi名单和配置都是启动时读的，你在后端改了东西（比如刚绑了卡）机器不会自己知道。前台跑的按 Ctrl+C 重开；自启的用 sudo systemctl restart tomoshibi-rollcall；整机重启用 sudo reboot（别直接拔电）
⑤ 看日志 —— 它通常直接把原因写出来了前台跑的就看屏幕；开机自启的用 journalctl -u tomoshibi-rollcall -n 50。哪怕看不懂英文报错，最后几行里的关键词（Permission / Connection / not found）也够定位方向，实在不懂就整段发给 CC
🛑 这三种情况立刻停手，不要硬试① 闻到焦味 / 板子烫手 / Pi 反复重启 → 先拔电源再说，八成是电源和地短路了 ② 焊盘（针脚周围那圈铜）翘起来或掉了 → 别再加热，换一块板 ③ 同一个问题卡了 20 分钟以上 → 停下来找 CC，继续试只会把简单故障叠成复杂故障

2.1 烧系统卡 + 远程登录
Mac 上安装 Raspberry Pi Imager（官方烧卡工具）⚠️ 必须用这个，不能用 balenaEtcher 等别的烧卡工具▶

「烧卡」= 把树莓派的操作系统写进 microSD 卡。

为什么只能用 Pi Imager：它能在烧卡时预先写入 Wi-Fi 密码、SSH 开关、主机名这些设置。这台 Pi 3A+ 没有网线口、唯一的 USB 口要留给喇叭、不插键盘鼠标 —— 预置漏了，这台机器你就永远登不进去，只能重烧。别的烧卡工具没有预置功能。

下载：raspberrypi.com 官网 → Software → Raspberry Pi Imager（macOS 版）。

烧卡：选对系统 + 高级设置 5 项一个都不能漏▶

把 microSD 卡经读卡器插进 Mac，打开 Imager：

① 系统选 Raspberry Pi OS (Legacy, 64-bit) Lite（约 420MB）—— 它不在第一屏，要点进最下面的 Raspberry Pi OS (other) 才能找到
② 烧录前进 Customisation（自定义设置），逐项填：

为什么是这个而不是第一屏推荐的那个（2026-07-27 实操确认）：① 要 Lite —— 带 Desktop 字样的版本自带图形桌面，而这台机器不插显示器键鼠，桌面白吃掉 Pi 3A+ 仅有的 512MB 内存；② 要 Legacy —— Legacy 这条才是 Debian Bookworm 系统，requirements.txt 顶部注释写明的目标环境就是「Bookworm / Python 3.11+」；第一屏那几个已经是新一代的 Trixie，自带更新的 Python。说清楚这里的证据强度：Bookworm 上装依赖这件事 2026-07-27 已实测跑通（Python 3.11.2，8 个包全装上）；而「Trixie 上会不会装不上」没有测过，只是「照文档写明的目标环境走更保险」，不是已证实的不兼容。名字只差一个词的陷阱：(Legacy, 64-bit) 和 (Legacy, 64-bit) Lite 是两个不同选项，前者带桌面（1.1GB），别点错。

2.2 打开两个通信开关
raspi-config 里开 SPI、开 I²C、音频切 3.5mm▶

SPI 和 I²C 是两种「芯片之间说话」的通信方式（读卡器走 SPI、贴纸走 I²C），树莓派默认全关着。在 SSH 里敲： 

sudo raspi-config

出来一个蓝色菜单（方向键移动、回车确认、Esc 返回）：

① Interface Options → SPI → Yes
② Interface Options → I2C → Yes
③ System Options → Audio → Headphones（把声音从 HDMI 切到 3.5mm 圆孔，不切喇叭不出声）

改完退出，重启：

sudo reboot

重启会把 SSH 断开，等 1 分钟再重新 ssh rollcall-1@rollcall-1.local。

核对两个开关真的开了▶ 
ls /dev/spidev*
ls /dev/i2c-*
验收：第一行打出 /dev/spidev0.0，第二行打出 /dev/i2c-1。

现在还没接任何模块，所以先别跑 i2cdetect —— 那条留到阶段 4.3 接上贴纸后用。

2.3 装代码和依赖
把点呼机代码从 Mac 拷进树莓派▶

这条命令在 Mac 的终端上跑（新开一个终端窗口，别在 SSH 里面敲）： 

scp -r ~/dev/DMSD/dev/rollcall_device rollcall-1@rollcall-1.local:/home/rollcall-1/rollcall_device

scp = 隔着网络拷文件的命令。会再问一次密码。拷完回到 SSH 窗口继续。

装系统包 + 建 Python 虚拟环境 + 装依赖▶

回到 SSH（树莓派）里，一段一段贴：

cd /home/rollcall-1/rollcall_device
sudo apt update
sudo apt install -y python3-venv python3-dev libgpiod2 i2c-tools
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt

cd = 进入某个文件夹；venv = Python 虚拟环境，把本项目的依赖库跟系统隔开互不污染。最后一步要下载不少东西，几分钟正常。

卡住了：lgpio 或 adafruit-blinka 装报错 → 多半缺系统包，补一句 sudo apt install -y python3-libgpiod 再重试。

2.4 空跑模拟模式（软件段终点）
用键盘假装刷卡，确认程序能转起来▶

「模拟模式」= 程序照常跑，只是把读卡器换成你的键盘、把灯和喇叭换成屏幕上的文字。现在一根线都没接，靠它就能验证软件那一层是好的： 

.venv/bin/python -m src.main --config config/config.json --simulate
注意是 python -m src.main，不是 python src/main.py —— 后者会报 ImportError。这是 Python 包的运行方式，不是代码有 bug。（-m 的意思是「把它当一个模块包来跑」。）

04a1b2c3d4e5f6                               # 同上，card 两个字可以省

① 温度调多少

手柄上那个白色旋钮就是调温度的，刻度是 200 / 250 / 300 / 350 / 400 / 480（单位 ℃），转到哪个数字对准旁边的三角标记就是设成多少。

先转到 350，别动。350℃ 对通孔焊接（就是我们要做的这种）是通用安全值 —— 低了焊锡半天不化、你会越按越久反而把板子烫坏；高了烙铁头氧化飞快、焊盘也容易翘。

万一 350℃ 试了几次焊锡就是不化：先排除「烙铁头没镀锡」（3.7 那一步）—— 十次有九次是这个原因，不是温度不够。确认镀过锡还是不化，再往上调，一次只加 20–30℃，最多到 400。480 那一档任何情况下都别用，那是拆大件用的，焊这种小板子等于拿喷灯烤。

手柄下方还有一个黄色的 ON / OFF 拨钮。先调好温度再开开关；中途离开桌子超过 5 分钟就拨到 OFF —— 通着电闲置会让烙铁头持续氧化发黑，黑了就不吃锡了。

这只是临时方案，稳定性远不如真正的架子。开工前请再翻一遍套装包装：烙铁架通常是拆开就散着的一个金属弹簧圈加一块底板，容易被当成包装填充物忽略掉。
④ 焊错了怎么把锡弄走（吸锡带用法）

那卷粉色标签的铜色编织扁带就是吸锡带，靠毛细作用把化开的锡「吸」进铜网里。用法三步：

① 把带子的头按在要清理的焊点上 → ② 烙铁压在带子上面（隔着带子加热下面的焊点）→ ③ 看到锡被吸进铜网变成银色，把烙铁和带子一起移开。

别先移烙铁再移带子 —— 锡会重新凝固，把带子焊死在板子上，硬拽就会连焊盘一起撕下来。吸满锡的那一截用剪刀剪掉，露出干净的铜网再继续用。
⑤ 一条健康提醒
这类套装配的焊锡丝多半是含铅的（包装上没写「無鉛」/「Lead Free」就按含铅对待）。含铅锡本身不会经皮肤吸收，但手上会沾到 —— 焊接期间别吃东西、别揉眼睛，每次收工洗手。另外焊接冒的白烟是助焊剂（松香），闻多了呛嗓子，开窗或开个小风扇往侧面吹，别对着脸吹也别整个人趴在烟上面。

给新烙铁头「镀锡」—— 不做这步，你会以为自己手笨全新烙铁头不粘锡，是它表面有层膜，不是你的问题▶

为什么必须做：全新的烙铁头表面有一层保护层／氧化层。这层东西不导热也不粘锡 —— 你会看到焊锡碰到烙铁头就滚成球掉下去，怎么都焊不上，然后怀疑是自己手不稳。不是。是烙铁头还没开锅。

四步（叫「上锡」或「镀锡」）：

① 烙铁插电，调 350℃，等 3 分钟真到温
② 烙铁头在湿海绵上快速蹭一下（会「呲」一声冒白汽，正常）
③ 立刻把焊锡丝按到烙铁头的斜面上，让锡熔开、裹住整个斜面
④ 再在海绵上蹭掉多余的锡

验收：烙铁头的斜面是亮银色、像镜子。如果是暗灰色或发黑 —— 氧化了，重做 ②③④ 一遍。
接下来全程都要「养头」：每焊完两三个点，就在海绵上蹭一下再补一点锡。烙铁通着电闲置会持续氧化变黑，中途休息超过 5 分钟就拔电，回来重新镀一次。头一旦烧黑烧死，再怎么按也焊不上。

先在废排针上练 10 个焊点，练到稳定出「光亮小锥形」▶

先解决「东西会跑」这件事 —— 新手最大的障碍不是手抖，是只有两只手（一只拿烙铁、一只拿锡丝，没手按住板子）。练习时这样固定：

随便掰一条排针，长针那一头朝下插进面包板插稳。剩下的部分就自己立在那儿了，两只手全空出来。

排针有长短两头：一头长（约 11mm）、一头短（约 6mm），中间那条黑塑料把它们串着。长的插面包板、短的朝上 —— 这个方向后面焊真板子时还要用，现在先记住手感。

四个基本动作，每个焊点都是这套：

① 加热 —— 烙铁头同时碰住针和板上的金属圈，停约 2 秒
② 送锡 —— 焊锡丝送到针和金属圈的接缝处（不是送到烙铁头上！），锡会自己熔化流进去
③ 先撤锡丝，再撤烙铁
④ 别吹气 —— 让它自然冷 2 秒（吹凉会产生裂纹）

单个焊点从碰上到撤走，不许超过 5 秒。超过 5 秒还没成型，说明温度不对或者烙铁头没镀好锡 —— 撤走，重新养头，别赖在那儿烤。板子上的金属圈（焊盘）是一层很薄的铜皮粘在板上的，长时间烤会整片翘起来脱落，那个位置就永久废了，没法修。

❌ 冷焊

❌ 虚焊

为什么先焊它：ST25DV 买了 4 块，焊坏一块还有 3 块；PN532 只有 1 块。先在有备份的板子上实战。

先认清这块板（照片核对过实物，2026-07-26 到货那批）：正面印着 ST25DV16 / I2C/NFC EEPROM 和一朵小花（Adafruit 的标志）。底边一排 6 个金色小孔，孔旁边的字是上下交错印的 —— 别按「一行字对一个孔」去读，会串位。从左到右的真实顺序是：

固定法 —— 这是全场最实用的一招：

① 6 针排针的长针那头朝下，插进面包板，插到底、插稳
② ST25DV 板子从上面套下去，6 个孔对准 6 根短针，压到贴住塑料条
③ 现在板子被面包板托着、排针天然垂直，你两只手全空出来了

这样焊完，排针是朝下的 —— 板子以后就一直插在面包板上用，天线那面朝上正对手机，接线也全走面包板。阶段 4 的接法就是照这个来的。

焊接顺序：先焊最左边第 1 针和最右边第 6 针（这两针管定位）→ 停下来，从侧面看板子是不是跟面包板平行、排针有没有歪 → 歪了现在还能救（烙铁按住那个焊点熔开，手扶正，撤烙铁）→ 正了再焊中间 4 针。

焊接面在板子朝上那一面（有小花和字的那面）—— 就是你现在低头看到的这面。锡要流进孔里、把针和金色圆圈都包住。
万用表验收 ST25DV 的 6 个焊点（三测，第一条防烧板）▶

焊完别靠肉眼。万用表拨到通断档（表盘底部那个「(•」形状的声波图标，两点相通会「哔——」）。黑表笔插 COM、红表笔插右边 VΩmA 孔 —— 拿不准回上面那张万用表说明看。

测 1 · 防烧板（最重要，没过绝对不许上电）
一支表笔碰 VIN 针，另一支碰 GND 针 → 必须不响。
响了 = 电源和地被焊锡连在一起了，一上电就烧。用吸锡器把那两个焊点吸干净重焊。

测 2 · 查短路
挨个碰相邻的两根针，5 组全测：VIN–GND、GND–SCL、SCL–SDA、SDA–GPO、GPO–VEH → 全都不响才算过。

测 3 · 查虚焊（不用表，用手）
镊子轻轻夹住每根针，左右晃一下 → 纹丝不动才叫焊牢。能晃动 / 能转 = 虚焊，补一次锡。

验收：VIN 和 GND 不通 ✅ · 相邻 5 组全不通 ✅ · 6 根针晃不动 ✅
说明白这三测能测出什么、测不出什么：它们能挡住「上电烧板」和「明显虚焊」这两类致命问题，但不能证明每根针真的通到芯片（那要拆开测芯片引脚，做不到也没必要）。真正的功能验收是阶段 4 的 i2cdetect —— 那一步能看到芯片地址，才算这块板真的活了。所以这里三测过了就往下走，别在这儿死磕。
再焊 PN532：只焊上边缘那排 8 个孔 只有 1 块，慢慢来板子有两排孔，左边那排 4 孔本项目用不到、不焊▶

🍞 面包板怎么通电 —— 不懂这个，下面每一步都会插错

面包板 = 一块布满小孔的塑料板，里面某些孔是用金属片暗中连在一起的。把两个零件的腿插进「同一组」孔，它们就通电了 —— 这就是不用焊也能接线的原理。规律只有两条：

开工前花 30 秒验一下你手上这块板：万用表通断档，两支表笔插进同一竖排的两个孔 → 应该响；插进左右相邻两排 → 应该不响；沿着红线轨从最左插到最右 → 应该响。最后这条要特别测 —— 有些 400 孔板的电源轨在正中间是断开的（红线看着连续，里面断了），不知道这点的话，你会以为「明明接了 5V 怎么半边没电」。
🔌 母-母杜邦线插不进面包板 —— 用「转接柱」解决

这是个买东西时没预料到、但一动手就会撞上的问题：

东西 两头长什么样 能插进哪
树莓派 40 针 都是金属针（公头） 只能被「套」，套它的必须是孔

结论：树莓派和面包板之间少一个「公头」。解法就是阶段 3 掰好的单根排针 ——

套上去松松垮垮、一碰就掉？排针插浅了 —— 要插到塑料条贴住面包板表面。还是松就换一根（排针粗细有公差）。接触不良造成的故障最难查，宁可现在多花 10 秒插紧。
4.1 LED ×4（不用焊、烧不坏，先练基本功）
拔掉电源，把 4 个 LED 经面包板接好▶

先认 LED 的两条腿 —— LED 有方向，接反了不会坏，但也不会亮：

两种认法，第二种更可靠：
① 腿的长短 —— 长腿 = 正极（＋），短腿 = 负极（−）
② 外壳的平边 —— LED 那颗圆脑袋侧面有一小段是削平的（不是完整的圆），平边那一侧的腿就是负极

为什么要记第二种：腿一旦被剪短过、或者你把两条腿掰成一样长插进面包板，长短就没法比了。平边这个特征是刻在壳上的，永远在。现在拿一颗在灯下转一圈找到那个平边，找过一次以后就认得了。

为什么必须经面包板、不能直接插树莓派：4 颗 LED 都要吃 5V，而树莓派上 5V 针只有 2 根；而且每颗都要串一个 220Ω 电阻，电阻的两条腿也得有地方落脚。面包板就是这个「落脚点」 —— 一根线把 5V 引过去，4 颗 LED 在那儿分。

① 一根母-母杜邦线：一头套树莓派 pin 2（5V），另一头套一根单排针，排针插进面包板上边的红线 ＋ 轨。→ 从此整条红轨都是 5V。

唯一会插错到看不出来的地方：LED 两条腿千万别插进同一列。同一列 = 内部本来就通着 = 等于把 LED 两头直接短接，灯永远不亮，而且外观上完全看不出问题。插完低头确认一次：两条腿跨在两个不同的列号上。
为什么是「低电平 = 亮」：电流从 5V 流进 LED，GPIO 信号针在「放电流出去」的一端 —— 代码把信号针拉到 0V（低电平），电路才通、灯才亮；拉到 3.3V（高电平）灯灭。跟直觉相反，但这是接法决定的，代码里已经处理好了，你只管照表接。

4.2 PN532 读卡器（路径 A：刷学生卡）
先把板上的模式开关切到 SPI 不切，接线全对也读不到卡▶

PN532 这块板能用三种方式跟树莓派说话（SPI / I²C / 串口），出厂默认通常不是我们要的 SPI。切换靠板上那个黑色小方块拨码开关（照片上在板子正面靠边的位置，上面有两个小拨片，旁边印着 1 2 或 SEL0 SEL1）。

先找模式对照表：一般印在开关旁边、板子背面，或者套件自带的小纸片上。找到了就照着拨到 SPI，拨完拍张照留档，跳过下面那段。

找不到对照表怎么办 —— 别停下来问我，自己试完就行。🤔 两个拨片只有 4 种组合（上上 / 上下 / 下上 / 下下），试错完全没有风险：拨码开关只是切换板子内部走哪条线，拨错既不烧板也不烧树莓派。做法：
① 拔掉树莓派电源 → 拨成一种组合 → 上电 → 跑一次下面的读卡测试
② 读不到卡就断电、换下一种组合，最多 4 次必中
③ 中了以后拍张照片，记下拨片朝哪边 —— 组装第二台时直接照抄
一条能省时间的判据：接好线以后跑 i2cdetect -y 1，如果看到 24 这个地址，说明板子现在在 I²C 模式（PN532 的 I²C 地址是 0x24）—— 那就肯定不是 SPI，直接换下一种组合，不用再费劲跑读卡测试。

每根线具体怎么走（板子焊完针是朝下的，所以它现在插在面包板上）：

VCC 接的是 3.3V（pin 17），不是 5V。走 SPI 时这块板按 3.3V 逻辑工作，插到 5V 针上有烧坏的风险。插之前对着 上面那张 40 针图 再数一遍针 —— pin 17 在左列，从靠近 microSD 卡槽那头数下来第 9 个。

4.3 ST25DV 贴纸（路径 B：手机碰）—— 全项目最难关
拔电源，先只接 4 根线（门铃线和 10kΩ 电阻先别管）故意分两步做 —— 理由在里面，这一条能帮你省掉最难的一关▶
ST25DV 板上印的字 接 Pi 的哪根针 物理 pin GPIO 编号
VIN 3.3V ← 板上写的是 VIN，不是 VCC pin 1 —
GND 接地 pin 9 —
SCL SCL（I²C 时钟） pin 5 GPIO3
SDA SDA（I²C 数据） pin 3 GPIO2
GPO 这一步先不接 —— 见下一条「门铃线」
VEH 整个项目都不接（那是给外接设备供电用的）

板上 6 个孔从左到右是 VIN · GND · SCL · SDA · GPO · VEH（照片核对过实物），字是交错印的，别按「一行字对一个孔」读。走线还是老套路：板子的针 → 面包板那一列 → 转接柱 → 杜邦线 → 树莓派。

VIN 接 3.3V（pin 1），不能接 5V。虽然板子背面印着能吃 2–5V，但它的 SDA/SCL 要跟树莓派的 3.3V 信号对齐 —— 接 5V 会让信号电平打架。
为什么故意分两步：门铃线（GPO）是这块板上唯一需要额外接一个电阻的地方，也是全项目最容易卡住的一步。而不接它，功能一样是完整的（原因下一条讲）。所以先用 4 根线把「能不能读到芯片、手机能不能写进去」这两件事验证掉 —— 万一出问题，你要排查的线只有 4 根，不是 5 根加一个电阻。

一个数字都没有（整张表全是 --）—— 按这个顺序查，别跳：
① 先量电：断电，万用表拧到 V⎓ 20 档，上电，黑笔碰任一 GND、红笔碰 ST25DV 的 VIN 针 → 应该约 3.3。读数是 0 = 电根本没送到，查 VIN 和 GND 那两根线（多半是转接柱松了）
② 再确认开关：ls /dev/i2c-* 有没有 /dev/i2c-1。没有 = 阶段 2.2 的 I²C 开关没开成
③ 再查 SDA/SCL 有没有插反：这两根接反是最常见的，互换一下再跑一次，30 秒的事
④ 都没问题 → 回阶段 3 用万用表把 6 个焊点的三测重新过一遍
验收第二步：iPhone 碰贴纸，日志解析出学生身份▶

跑起主程序，用 iPhone 打开 Tomoshibi App 点签到，手机贴到 ST25DV 上。

碰的位置很关键，碰不对会以为是接线坏了：
· 板子这边：天线是板子正面中间那个印着小花的大方框区域，不是那排针
· 手机这边：iPhone 的 NFC 天线在机身最上端、靠背面那一条 —— 所以是拿手机顶部去贴，不是拿手机中间去贴
· 贴住不动停 1–2 秒，别一碰就走

验收：日志打出解析到的学生 UUID（一串带横杠的长编号）。
没反应时先确认「手机认不认得这块板」：iPhone 息屏状态下贴上去，如果系统弹出 NFC 提示条 —— 说明板子是活的、手机也找得到它，问题在软件那一层；如果连系统提示都没有，那是贴的位置不对或板子没供电，回去查线。这一招能把排查范围立刻砍一半。
这一步出问题不一定是你接错了。这里是全项目代码里标「待硬件联调核实」最多的地方 —— ST25DV 的寄存器位号、GPO 引脚行为都是照芯片说明书写的、从没被实物验证过。折腾 20 分钟没进展就停手，把日志（前台跑的整段输出，或 journalctl -u tomoshibi-rollcall -n 50）发给 CC，对着芯片手册一起查。这一关卡住不影响你继续做 4.4 和刷卡那条路径 —— 先跳过去做别的，别在这儿耗掉一整天。
（选做）加门铃线 GPO + 10kΩ 电阻，让响应快 1 秒不做也能用 —— 先读里面第一段再决定做不做▶
先说结论：这根线可以不接，功能不会缺。它的作用只是「让机器反应快一点」。确认过代码（src/nfc/st25dv.py）：不接这根线时，程序每隔 1 秒主动去问一次贴纸「有没有新东西」，照样能读到手机写进去的数据 —— 只是最坏情况下慢 1 秒。接上以后，贴纸会主动「按门铃」，反应基本是瞬间的。
所以：赶时间、或者上面那步已经折腾很久了 → 跳过这条，等第一次端到端跑通以后再回来加。

GPO 门铃线是什么：手机把数据写进贴纸后，贴纸把这根线拉低（从有电变成没电），树莓派看到这个变化就知道「有新东西了，快来读」。

为什么要串一个 10kΩ 电阻：这根线的设计是「平时松着、要通知时才拉低」。松着的时候它既不是高也不是低，树莓派读出来就是乱跳的。所以要用一个电阻把它轻轻吊在 3.3V 上（术语叫「上拉」）—— 平时被吊着是高电平，贴纸要通知时能轻松把它拽到低。电阻是为了「吊得住但又不至于拽不动」，阻值必须是 10kΩ，220Ω 太小了拽不动。

面包板上的接法（3 步）：

① 10kΩ 电阻：一条腿插进 ST25DV 的 GPO 针所在那一列，另一条腿插进树莓派 3.3V 引过来的那一列
② 同样那个 GPO 列，再插一根转接柱 → 杜邦线 → 树莓派 pin 18（GPIO24）
③ 上电前用万用表 20k 档量一下那根电阻，确认显示约 9.9～10.1 —— 别拿成 220Ω，两种电阻长得一模一样

顺带一提，代码里还开了树莓派自己的内部上拉（Button(gpo_pin, pull_up=True)）。所以严格说这个外接电阻是「加固」而不是「唯一依靠」—— 这也是为什么不接它也能工作。接上更稳，因为树莓派内部那个上拉比较弱。
验收：再碰一次手机 → 日志出 UUID 的速度明显变快（基本是碰上就出，不用等）。

⏳ 用 GPIO24（pin 18）是配置文件 config.json 里的 gpio.st25dv_gpo 定的，这个值标着「待硬件联调核实」。如果实测发现要换针，配置里那一行要同步改。

4.4 风扇 + 喇叭
拔电源，风扇接头直插 pin 4 + pin 6 红线对 5V · 绝不接 GPIO▶

风扇的 2 针接头刚好套到 pin 4（5V）+ pin 6（GND）上，红线那头对准 pin 4。

风扇绝对不能接 GPIO 信号针 —— 信号针最大 16mA，风扇要 100mA，会烧板子。它只吃 5V 和 GND 两根电源针。
验收：上电风扇转。
喇叭：3.5mm 音频线插 Pi 圆孔，USB 线取电▶

Lazos 喇叭两根线：3.5mm 那根插 Pi 的圆形音频口；USB 那根只是取电。

⏳ USB 取电插哪：两份文档说法不一 —— 采购清单（较新）说插单独的 5V 充电头、不占 Pi 唯一的 USB 口；接线说明写的是插 Pi 的 USB 口。到时候实物确认：有闲置充电头就用充电头，Pi 的 USB 口能省则省。两种接法都不危险。

声音验收：刷卡有播报声▶
验收：刷一张卡，喇叭出声（现在还没绑学生，播提示音 / 报错音都算「出声」）。
卡住了：没声先想起阶段 2.2 —— 音频切到 Headphones（3.5mm）了吗？没切就 sudo raspi-config 补切。这不是喇叭坏了。

三条命令，按顺序敲

第 1 条 · 用老师账号登录，换一张令牌（令牌 = 后端发的临时通行证，证明「这是有权限的老师在操作」）：

  -H 'Content-Type: application/json' \
  -d '{"login_id":"op","password":"你的密码","selected_dorm":1}'

把 192.168.x.x 换成刚查到的地址（走 B 的话整段换成 https://api.tomoshibi.cc）。本地开发账号的用户名和密码写在 dev/backend/v1/seed.py 顶部的常量里（DEV_OP_PASSWORD / DEV_PASSWORD）—— 打开那个文件抄。能建设备的账号必须满足两条：权限组是 op 或 寮管理者、并且不是演示账号（后端专门挡了演示老师建真实硬件）。

返回是一长串 JSON，开头长这样 —— 引号里那一大串就是令牌，整串复制下来： 

{"access_token":"eyJhbGciOi......(很长)......","token_type":"bearer","expires_in":...}

第 2 条 · 建这台设备的记录（把上一步的令牌贴到 Bearer 后面）： 

curl -s -X POST http://192.168.x.x:8000/api/v1/devices \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer 粘贴刚才那串令牌' \
  -d '{"device_id":"dorm-1-01","device_type":"hybrid","device_location":"一寮 玄関","device_notes":"1号機"}'
字段 填什么
device_id 这台机器的编号。必须跟稍后 config.json 里填的一模一样，建议就用 dorm-1-01
device_type 只能是 card_reader（只刷卡）/ iphone_tag（只手机）/ hybrid（两种都行）三个之一。你这台两条路都做了 → 填 hybrid
device_location 装在哪，随便写中文或日文，如 一寮 玄関
device_notes 备注，可省略

返回里有一段 "enroll_code":"..." —— 那就是激活码，立刻抄到纸上或备忘录： 

{"device_id":"dorm-1-01",...,"enroll_code":"这一串就是要抄的","device_active":true}
这串码只会显示这一次。关掉终端就再也找不回来了 —— 后端只存了它的哈希值，没法反查明文。真丢了也不是绝症：重新走一遍「重发激活码」（POST /api/v1/devices/dorm-1-01/reset-enroll，同样带令牌）会给你一串新的。

第 3 条 · 确认它真的建上了：

curl -s http://192.168.x.x:8000/api/v1/devices \
  -H 'Authorization: Bearer 粘贴刚才那串令牌'
验收：返回的列表里能看到 dorm-1-01，并且 "device_active":true。（这个列表不会再显示激活码，那是故意的。）
报错对照
· {"detail":"Not authenticated"} → 令牌没贴上，或者 Bearer 和令牌之间少了空格
· 401 / 令牌过期 → 重跑第 1 条拿新令牌
· 403 / 权限不足 → 这个账号权限组不对，换 op 或 寮管理者 的账号
· 提到 demo / 演示 → 你用的是演示老师账号，后端不允许它建真实设备，换真账号
· DEVICE_ALREADY_EXISTS（409）→ 这个 device_id 已经建过了。要么换个编号，要么走上面的 reset-enroll 重发码
· 命令卡住没反应 / Connection refused → Mac 后端没跑起来、或 IP 填错、或 Pi 和 Mac 不在同一个 Wi-Fi

刷之前先确认两件事，不然你会对着不动的机器查半天：
① 机器现在是黄灯（红+绿同亮）吗？黄灯 = 今晚的点呼时段还没开始，这时刷卡不会有绿灯响应，是设计如此不是故障。去老师网页把今晚的点呼开起来，机器会转成蓝灯待机。

看日志：如果程序是前台跑的，直接看屏幕；如果已经装了开机自启，用 journalctl -u tomoshibi-rollcall -n 30。找那串 14 位、只含 0–9 和 a–f 的字符（比如 04a1b2c3d4e5f6），抄下来。

第 2 步 · 查这个学生的内部编号（在 Mac 上敲，令牌还用 5.1 那张；过期了就重拿一张）：

  -H 'Authorization: Bearer 粘贴令牌'

返回里每个学生都有一个 "id":"xxxxxxxx-xxxx-..." 的长串 —— 那就是要用的内部编号，认准名字对上的那一条。

走 A 本地后端的话，学生是假数据（seed 投进去的），随便挑一个能查到的名字就行。q= 后面留空则返回全部。

第 3 步 · 把卡和人绑在一起：

curl -s -X POST http://192.168.x.x:8000/api/v1/cards \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer 粘贴令牌' \
  -d '{"card_uid":"04a1b2c3d4e5f6","student_id":"上一步查到的那串 id"}'
card_uid 必须是 14 位小写字母数字。日志里如果打的是大写（04A1B2...），手动改成小写再填，否则后端直接拒收。

第 4 步 · 再刷一次那张卡。名单是启动时拉的，刚绑的卡机器还不知道 —— 如果还红灯，把程序重启一下（前台跑的 Ctrl+C 后重开；自启的 sudo systemctl restart tomoshibi-rollcall）再刷。

验收：绿灯 + 喇叭用日语念出这个学生的名字。这是整个项目最值得录下来的一帧 —— 从这一刻起「刷卡点呼」不再是文档里的设想。

还是红灯 → ① 日志里这次打出的编号和你绑的那串真的一模一样吗（大小写、有没有抄少一位）② 绑卡的 curl 当时返回的是成功还是报错 ③ 程序重启过了吗。

然后浏览器开 http://localhost:5173，用跟 5.1 同一个老师账号登录 → 进点呼页面。确认过配置：开发模式下网页会自动把请求转给本机 8000 端口的后端，不用额外配地址。

验收：Pi 上刷卡的那一瞬间，网页上这个学生的状态自己变了 —— 不用手动刷新页面（网页和后端之间有一条实时通道）。这一下变化就是「卡 → 读卡器 → 树莓派 → 后端 → 老师看到」整条链路打通的证据，录视频一定要拍到这一帧。
网页上没变化？按顺序排除：① Pi 那边日志里这条签到成功了吗（有没有报错）② 网页现在开的是点呼页面吗、今晚的点呼时段开始了吗（没开始的话机器是黄灯，本来就不会有签到）③ 手动刷新一下页面，如果刷新后出现了 = 数据进后端了、只是实时通道断了，属于小问题不影响本次验收。
断网再刷卡 → 仍绿灯，恢复网络后自动补传▶

把 Wi-Fi 断掉（路由器上踢掉这台设备或关热点）再刷已绑定的卡：本地名单命中照样绿灯。恢复网络后，这条记录自动补传到后端 —— 老师网页上应该能看到它出现。

装开机自启，重启后不用手动启动▶

systemd = Linux 的开机自启机制，装好后断电重启机器都会自己爬起来干活： 

sudo cp config/tomoshibi-rollcall.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tomoshibi-rollcall
systemctl status tomoshibi-rollcall
验收：status 显示 active (running)。然后 sudo reboot 重启 → 不碰键盘，机器自己白灯 → 蓝灯。

以后看实时日志用：journalctl -u tomoshibi-rollcall -f（Ctrl+C 退出看日志，不影响程序）。

故障对照表现象点开看排查法
ST25DV 读不到（i2cdetect 里没有 0x53 / 0x57）▶

检查 I²C 四根线（SDA/SCL/VCC/GND）+ raspi-config 里 I²C 真开了；GPO 线接对针脚且串了 10kΩ 上拉。还不行 → 回阶段 3 复测焊点通断。

PN532 读卡无反应▶

① 板上跳线切到 SPI 模式了吗 ② /dev/spidev0.0 存在吗 ③ SS 线接的是 CE0（pin 24 / GPIO8）吗。

刷卡有反应但没声音▶

raspi-config 把音频切到 3.5mm（Headphones）；再 aplay -l 核对 config 里 audio_output 的设备串填对了。

白灯闪烁（认证错误）▶

令牌或激活问题：确认 enroll_code 正确且没被用过、这台设备在后端是启用状态（device_active = true）。看日志定位。

黄灯（红 + 绿同时亮）▶

= 点呼时段还没开始（SESSION_NOT_RUNNING），正常等待态，不是故障。

断网时刷卡什么表现才算对▶

本地名单里有这张卡 → 绿灯；没有 → 红灯。恢复网络后自动补传，不用人管。

开机瞬间 LED 微微亮一下▶

正常。程序启动的第一件事就是把 4 颗 LED 全部置灭。

要换机器 / 换密钥▶

管理员先在后端重发激活码（reset-enroll），Pi 上删掉本地密钥文件（key_path 指的那个）后重启，走一遍重新激活。

焊接现场（阶段 3）
焊锡碰到烙铁头不化 / 化了也不粘在焊盘上▶

九成是烙铁头没镀锡（3.7 那一步）。新烙铁头表面有一层保护膜，不先化一层锡上去，热量传不出去、焊锡自然不粘 —— 这个坑会让人以为是自己手笨。回 3.7 重做一遍镀锡。

剩下一成：① 通电还不到 2 分钟，温度没上来 ② 烙铁头氧化发黑了 → 在湿海绵上擦一下再补一点锡 ③ 你碰的是烙铁头的侧面尖端，应该用斜面最宽的那一面去贴焊盘，接触面积大热量才传得过去。

焊点鼓成一个球，一碰针脚就晃 / 直接掉▶

典型的「冷焊」：焊锡只是堆在上面，没有真正跟焊盘熔在一起。正常的焊点应该是光滑的小火山形，不是圆球。

补救：把烙铁重新按在那个点上 2–3 秒让锡整个化开，再补一点点新焊锡，然后先移开焊锡丝、再移开烙铁，让它自己冷却（这几秒别碰板子）。锡堆太多就先用吸锡器吸掉重来。

同一个焊点连续加热别超过 5 秒，也别反复来回补。焊盘是一层很薄的铜皮，烫过头会整片翘起来脱落 —— 那就是永久性报废、没法修。宁可停手歇 30 秒等它凉了再补一次。
接线现场（阶段 4）
杜邦线两头都是「洞」，插不进面包板▶

正常，不是买错了。买的是母-母线（两头都是孔），面包板要的是「针」。解法是用单根排针当转接柱 —— 排针插进面包板、杜邦线的孔套在排针露出来的那截上。详细图解见阶段 4 开头的面包板说明卡。

接好线，但灯乱闪 / 时好时坏 / 碰一下桌子就变▶

接触不良，这是新手组装最常见也最难查的故障，因为它不是「坏」而是「有时候好」。按可能性排查：

① 杜邦线的孔套在排针上松不松，轻轻拽一下会掉吗 → 松就换一根线 ② 排针插进面包板够不够深，塑料条应该贴住板面 ③ 焊点是不是上面说的「球形冷焊」 ④ 面包板电源轨中间是不是断开的（400 孔的板子常见）—— 用万用表通断档从左端量到右端确认。

诊断小技巧：故障出现时用手指轻轻按住某一根线，如果症状变了，问题就在那一根附近。

上电瞬间有焦味 / 板子发烫 / Pi 直接重启▶
立刻拔掉 Pi 的电源，别急着找原因。

几乎一定是电源和地短路了（3.3V 或 5V 直接连到 GND）。拔电后用万用表通断档量：Pi 的 3.3V 针和 GND 针之间、每块模块的 VIN/VCC 和 GND 之间 —— 响 = 短路，找到那处拆开重接/重焊。确认不响了再上电。

这就是阶段 3「三测」里第一测（VIN↔GND 必须不通）存在的理由。

软件 / 命令行
SSH 突然断了 / 连不上 Pi 了▶

先分清是网断了还是机器挂了：拿手机连同一个 Wi-Fi，或者看 Pi 板上的绿灯有没有在闪（闪 = 在读写卡，活着）。

① 最常见：Pi 的 IP 变了 → 用主机名连 ssh rollcall-1@rollcall-1.local，或去路由器管理页面重新查 IP ② 刚拔插过线导致重启 → 等 1 分钟再连 ③ 终端里显示 REMOTE HOST IDENTIFICATION HAS CHANGED → 你重烧过卡，按提示删掉旧记录那一行即可。

程序一启动就退出，报权限 / 找不到目录▶

多半是数据目录没建或没权限（程序开机要往那里写设备密钥）。跑一次：sudo mkdir -p /var/lib/tomoshibi && sudo chown "$USER:$USER" /var/lib/tomoshibi。另外确认命令是 python -m src.main 而不是 python src/main.py。

万用表屏幕只显示一个孤零零的「1」▶

不是坏了，是超量程 —— 当前档位量不了这么大的值。测电阻时换更大的档（2k → 20k）；如果两根表笔本来就没碰在一起，显示 1 才是正常的。表笔插孔别插错：黑笔 COM、红笔 VΩmA。
