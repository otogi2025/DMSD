# 纸质点呼降级方案

> 系统在点呼时刻不可用时，退回纸质名单点呼的标准动作。目标：**点呼队伍永远不因系统故障停下**。
> 生效时点：第二波（真宿舍点呼上线）起。第一波无点呼功能，本方案不适用，但 §2 事前准备中的名单打印能力应在第一波就验证。
> 现场卡片（§3）为日语，供寮监直接使用；其余为运营者视角的流程说明。

## 1. 触发标准

满足任一条即切纸质，**由当晚在场负责教员（寮監）宣布**，不需要等运营者远程诊断：

1. 点呼开始时刻，老师网页打不开或点呼画面无法开始，重试一次页面刷新仍失败。
2. 点呼进行中系统故障（座位全部不更新 / 点呼机全部无反应），2 分钟内无恢复迹象。
3. 点呼机不可用且该栋无替代签到手段（单台故障即该栋切纸质，其他栋不受影响）。

原则：**切换宁早勿晚**。点呼窗口只有几分钟，全体学生在排队等待；恢复系统的尝试与纸质点呼并行进行，而不是让队伍等系统。

## 2. 事前准备（常备物资）

| 物品 | 要求 | 责任 |
|---|---|---|
| 纸质名单 | 每栋一份，按房间号排序，含姓名+房号；每周从老师网页学生名簿页打印更新（新入寮/退寮后立即重印） | 运营者印制，放各栋点呼台抽屉 |
| 笔 + 夹板 | 与名单同放 | 同上 |
| 本方案 §3 现场卡片 | 塑封，贴点呼台或与名单同放 | 同上 |

名单来源：老师网页学生名簿页（第一波已有）直接打印，无需专门开发导出功能。

## 3. 现场卡片（日语，塑封贴点呼台）

```
■ システム障害時の点呼（紙運用）

1. 「今日は紙で点呼します」と宣言し、通常どおり整列させる
2. 名簿の部屋番号順に点呼を実施し、記号で記録する
     ○ = 出席   △ = 遅刻（時刻をメモ）   × = 不在
   ※ 外泊・帰省等の届出者は名簿余白に「届出」と記入
3. 点呼終了後：
   ・名簿の記入面をスマートフォンで撮影（バックアップ）
   ・不在者への対応は通常の手順どおり（電話確認等）
4. 障害発生時刻と状況を名簿の余白にメモしておく
   （例：「21:55 画面が開かない」）

紙の名簿が最終記録です。システム復旧後の入力は
教員が行いますので、名簿は捨てずに保管してください。
```

## 4. 事后补录（系统恢复后）

1. **补录人**：当晚负责教员或次日担当教员，用老师网页手动改判功能（点呼画面的手动调整弹窗）按纸质名单逐个录入。改判走已实装的手动判定接口，append-only 且有审计留痕，放心操作。
2. **迟到判定**：纸质记录的时刻为准，△ 且超过截止时刻的按迟到录入。
3. **与点呼机补传的冲突**：点呼机离线期间本地缓存的签到会在恢复后自动补传 —— 补传与手动录入撞同一学生时**老师手动优先**（已拍板规则，flow_design.md §6）。补录前先等点呼机重连补传完成（老师网页告警解除），再补纸质名单上剩余的人，可减少冲突。
4. **核对**：补录完成后，点呼画面的出席统计应与纸质名单的 ○△× 计数一致；不一致逐个排查。
5. **纸质名单归档**：照片留存，纸件按宿舍惯例保管（它是该晚点呼的原始凭证）。

## 5. 复盘记录

每次降级后 24 小时内，运营者按下表记入开发日志：

| 项目 | 内容 |
|---|---|
| 发生时刻 / 恢复时刻 | |
| 症状 | 现场看到什么（对照故障手册 S 编号） |
| 影响范围 | 哪几栋、多少人次、是否产生误判 |
| 根因 | 事后诊断结果 |
| 补录耗时 / 冲突数 | 衡量本方案执行成本 |
| 改进项 | 名单是否最新、卡片是否好用、监控是否提前发现 |

## 6. 演练

真宿舍上线前，与寮监协调做一次**计划内纸质演练**（选一次正常点呼按纸质流程走一遍 + 事后补录），验证：名单可用、卡片看得懂、补录一人平均耗时。演练结果记入 §5 表格。上线后每学期一次。
